# 全链路比赛调试网页

独立端口 **8087**，真实执行完整比赛，不启动正式 `mission_node`。Python 标准库 HTTP/SSE 与原生 HTML/CSS/JavaScript，沿用已有网页工具，无前端框架或外网依赖。原有 8080 路线工具、8086 区域工具及正式比赛入口保持可用，运行时只能选择一个控制入口。

## 构建和启动

首次使用或更新 ROS 接口后：

```bash
source /opt/ros/humble/setup.bash
cd /root/工创/ros2_ws
colcon build --symlink-install --packages-select agv_interfaces agv_cboard agv_planning agv_mission agv_screen agv_perception
cd /root/工创
./tools/competition_debug/start.sh
```

访问 [http://127.0.0.1:8087](http://127.0.0.1:8087)，其他电脑用 `http://小车IP:8087`。启动只提供待命网页，不自动运行比赛。启动前退出正式比赛、路线/区域控制工具、已有桥接、屏幕程序，以及占用主相机或二维码相机的拍照/识别工具。

覆盖端口、串口或现有配置来源：

```bash
./tools/competition_debug/start.sh port:=8097
./tools/competition_debug/start.sh host:=127.0.0.1 serial_port:=/dev/ttyACM0
./tools/competition_debug/start.sh screen_port:=/dev/ttyUSB0
./tools/competition_debug/start.sh mission_config:=/绝对路径/mission.yaml
./tools/competition_debug/start.sh raw_config:=/绝对路径/raw.yaml coarse_config:=/绝对路径/coarse.yaml storage_config:=/绝对路径/storage.yaml
```

另支持 `planner_config`、`cboard_config`、`screen_config`、`qr_config`。不提供网页调参，修改配置后重启工具。`debug_config` 沿用路线工具的网页心跳、接口及时序配置，不影响区域 PID。

本入口启动并监督：

| 组件 | 归属与复用方式 |
| --- | --- |
| `competition_debug_controller` | 新增独立整场编排；独占最终 `/C/controll`；提供 HTTP/SSE；复用路线工具的导航、屏幕配置、里程地图与停止确认 |
| `route_planner_node` | 本入口启动一份真实规划器，复用 `/tools/route_debug/*` 私有接口；每站按固定工作方向对齐并等待释放 |
| `cboard_bridge_node` | 本入口启动一份桥接，串口及参数读源码 `cboard.yaml`；底盘与机构共用同一连接 |
| 原料、粗加工、暂存控制器 | 在本控制进程内复用正式核心及 8086 的真实/停留替代包装；不再启动第二份 `coarse_node` |
| `QRNode` | 到扫码站才创建，复用正式相机及预处理解码，首张有效新帧即采用；成功或停止后销毁并释放相机；待命扫码预览仅复用相机采集，不创建扫码节点或提交任务码 |
| 区域主相机 | 待命时可手动预览，否则第一次区域任务才打开；复用 8086 的单相机圆环/物料识别与标注；导航期间保留，停止/完成释放；下一轮重新打开 |
| 显示屏串口 | 仅显示屏配置模式点击开始时打开，复用路线工具的协议、旧消息清理和 OK 门控；不启动 `screen_node` |
| 雷达 | 仅 `mission.yaml` 的 `use_lidar: true` 加载现有 `agv_obstacles` 启动入口，并使用真实 ScanRoads、复位、运行查询与停止协议 |

启动前沿用路线工具的只读 ROS 图冲突检查：已有底盘控制、桥接、已知设备节点或私有执行服务时拒绝，不关闭用户进程；仅观察客户端不阻止启动。运行时持续检查独占控制、真实反馈、会话及许可。任一受监督进程退出，整套退出，不自动重启或续跑。没有 ROS 节点的独立拍照工具仍需人工关闭。

**当前仓库雷达包为占位实现**。默认源码 `mission.yaml` 为 `use_lidar: false`，明确跳过扫描、沿用人工禁行地图。设为 `true` 时启动入口会在打开设备前报“真实雷达执行端尚未实现”，与正式整套启动行为一致；不会伪造扫描或静默按关闭运行。未来真实雷达入口实现后，本工具在出区后扫描、合并人工禁行并等待规划器确认，再前往扫码站。

## 本轮操作

1. 人工恢复车辆、物料及机构。将车摆在选定启停区内：启停区1/节点1车头朝地图下方；启停区3/节点3朝上。
2. 选择“网页配置”或“显示屏配置”，确认三区域“真实取放”开关（全部默认开启，每个区域两轮共用）。开始后所有选项锁定，直到停止/完成并复位。
3. 网页配置：选择起始启停区、最终停车区，点击地图路段1～12设置双向禁行，点击“开始 · 一键跑完整场”。显示屏配置：点击网页开始后才接收屏幕本轮操作；屏幕路径页 OK，然后起终点页 OK，再按大 START 按钮，从 START 起静止至少2秒，且执行端全部就绪才开始。等待配置时也可停止；旧屏幕配置不会启动新一轮。
4. 待命时切到“当前相机”，点击“打开主相机预览”检查主相机与识别标注，或点击“打开扫码相机预览”检查扫码摄像头原始画面。两种预览共用显示区，切换时自动释放上一台相机，不启动比赛或机构动作；扫码预览不识别或提交本轮任务码。点击对应关闭按钮或停止可释放。开始比赛前自动释放待命预览，再由比赛流程管理相机；复位及退出也会释放。比赛期间不能手动开关相机，到扫码阶段自动显示二维码画面及识别标注。预览报错会显示相机/识别原因及画面请求错误，扫码相机10秒无图或断流时显示具体提示。地图/相机切换只改显示，不开第二个相机。主视图区随页面滚动，不吸顶遮挡日志。
   等待完整比赛执行，中途无单步、跳阶段、单阶段启动或自动故障重试。相机状态显示未启用、等待新图像、当前识别或已释放。
5. 完成或故障后点击“保存完整日志”，下载本轮 JSON（配置及来源、任务码、完整中文日志、逐件真实/替代结果、故障上下文）。页面只显示最近80条，下载保留整轮；开始下一轮会清理旧轮日志，请提前保存。

固定流程：

```text
斜移出区 → 按配置扫描/跳过雷达 → 二维码区导航与工作朝向对齐 → 真实扫码
→ 第一轮原料取料 → 粗加工三放三取 → 暂存第一层放置
→ 第二轮原料取料 → 粗加工三放三取 → 暂存同色码垛
→ 返回最终停车区角点 → 斜移入区 → 释放确认完成
```

扫码没有等待总时限：未识别、任务码无效、相机启动无图或断流时持续停车等待，相机自动重连；首张通过校验的有效新帧即采用，不要求连续5帧，不使用3秒停留或手工任务码代替。过期画面不会被采用；底盘、机构或反馈的独立故障仍停止并显示原因。任务码沿用正式四组校验与 `batch_spec` 顺序；第二轮码垛目标位置来自第一层同色位置映射，不按第二批位置组硬套第一层布局。该策略仅用于本工具，8080路线调试和正式扫码的默认连续5帧策略不变。

二维码解码在单独工作线程执行，同时最多处理一帧，避免复杂图像阻塞ROS控制、机构反馈和网页心跳；任务码校验及结果发布仍在ROS回调中处理。机构反馈超时规则不变，停止时丢弃未完成解码，不会继续发布扫码结果。

扫码节点的创建和销毁也在后台执行，相机释放不阻塞控制回调；新节点仅在初始化完成后加入控制执行器，停止时先从执行器移除再后台释放。初始化期间停止也会等待后台创建完成后释放设备，不再提交结果。扫码阶段不设等待超时，首帧有效任务码直接用于显示屏及后续流程。解码输入须为新鲜采集帧，但不会仅因解码耗时超过0.5秒丢弃已识别的有效任务码。

## 真实动作与停留替代

开关仅控制原料抓取4、粗加工放置6/取回5、暂存第一层放置6/第二层码垛7（动作号实际读取对应区域配置）。关闭时不发送这些取放程序，每次改为全轴停止至少1秒，并沿用 8086 的真实 WORK 恢复分支。

原料区现流程：沿工作方向前进12 mm（`base_motion.distance_mm`可调）→ 原地等待所需颜色并追踪抓取 → 抓取程序回高位，在当前位置等待下一件 → 三件完成收纳后退回P0；正式比赛可由离区导航吸收偏移。取消初始任意颜色跟随和m0机构返回。详见[原料流程](../../ros2_ws/src/agv_perception/RAW.md)。

替代完成只记录 `DWELL_COMPLETED`，真实动作确认记录 `REAL_COMPLETED`。流程内部保留顺序记录以便推进，不将替代结果描述为真实物料成功。第一轮暂存被替代后，第二轮仍需现场存在真实同色物料；缺少目标会明确等待，图像断流则故障，不编造识别结果。若要演练码垛视觉，请按本轮任务码提前安排真实第一层物料。

“停止”立即关闭推进并归零，扫码阶段释放扫码相机，区域阶段关连续机构流并发送 ABORT(0)，请求规划器停止；雷达启用时同时取消扫描并确认执行端释放。网页先显示“正在停止”，确认后显示“停止完成”或保留故障原因。任何同源观察页面也可停止，开始/复位遵循单控制页规则。

结果未知或停止释放未确认时禁止再次开始/复位；按提示检查执行端、退出工具并人工恢复。停止后结束本轮，无续跑；人工恢复车辆、物料和机构后点击复位，再选模式与开关开始。复位只清软件状态，不移动或收纳实车。Ctrl+C 沿用监督入口统一结束所启动的进程。

## 比赛与区域调试共用视觉执行方式

正式比赛、8087 全场调试和 8086 区域调试共用 `agv_perception.work_vision.RingVision`（含独立进程的物料识别/圆环几何及异步预览），三区域控制器仍为 `RawTask`、`CoarseTask`、`StorageTask`；调试模式只包装逐件停留替代。原料每色保留最大实例，暂存保留各实例，按当前目标精修。正式入口只适配任务启停，不再维护另一套识别流水线。

三区域整批作业共用 `VisionGate`：工作姿态或识别目标切换后，仅采用当前目标的新鲜图像；冷启动的过期结果先丢弃并保持零速，在 `camera_start_timeout_s` 内等待首张合格图像。建立有效图像流后，超过 `max_frame_age_s` 的结果立即停止所有视觉运动并清除跟随状态，等待及时新帧后继续；连续 `camera_start_timeout_s` 没有有效结果才结束任务。有效画面缺少物料继续停车等待。8087 故障日志增加图像序号、图像年龄、采集/识别帧率及阶段耗时。

更新后执行 `cd /root/工创/ros2_ws && colcon build --packages-select agv_perception --symlink-install`，随后重启比赛或调试入口。无需更改串口协议和现场 PID 参数。

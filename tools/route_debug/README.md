# 路径规划与 C 板通信浏览器调试

通过浏览器控制真实小车，复用 `agv_planning` 和 `agv_cboard`。左侧保留原始赛场截图，显示规划路线、真实里程驱动的连续估算位置／朝向和已走轨迹；右侧设置任务并查看反馈。

## 构建与启动

依赖现有 ROS2 Humble、`python3-yaml`、`python3-serial`。网页服务使用 Python 标准库，不需要 pip、Node.js、外网CDN或 rosbridge。

第一次使用或接口代码更新后，在项目根目录构建：

```bash
source /opt/ros/humble/setup.bash
cd /root/工创/ros2_ws
colcon build --symlink-install
```

结束正式 mission、其他底盘控制程序及已有 C 板桥接，然后运行：

```bash
cd /root/工创
./tools/route_debug/start.sh
```

本机打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。其他电脑在同一局域网用浏览器访问 `http://小车IP:8080`。这是直接控制实车的本地调试页面，运行于受信任的调试网络。

可覆盖串口、监听地址、端口和配置路径：

```bash
./tools/route_debug/start.sh serial_port:=/dev/ttyACM0 port:=8081
./tools/route_debug/start.sh host:=127.0.0.1
./tools/route_debug/start.sh planner_config:=/绝对路径/planner.yaml cboard_config:=/绝对路径/cboard.yaml
./tools/route_debug/start.sh mission_config:=/绝对路径/mission.yaml
./tools/route_debug/start.sh screen_port:=/dev/ttyUSB0
./tools/route_debug/start.sh screen_config:=/绝对路径/screen.yaml
```

默认串口来自源码 `ros2_ws/src/agv_cboard/config/cboard.yaml`，当前为 `/dev/rm_cboard`。默认运动参数来自源码 `ros2_ws/src/agv_planning/config/planner.yaml`，包括x/y位置PID、vx/vy独立速度上限、角度PID、角速度上限、到达容差、控制频率和逐边距离；页面“实际加载的运动配置”显示参数和读取来源。直线和斜移均进行双轴位置纠偏，当前车体vx绝对值不超过0.7 m/s、vy绝对值不超过0.4 m/s，同时由角度PID锁头；过冲可反向修正，平移完成需两条位置轴与角度同时到达。工具不修改这两个文件，也不提供网页调速。

比赛出入区斜移距离读取源码 `ros2_ws/src/agv_mission/config/mission.yaml` 的 `parking_offset_mm`，默认200 mm，表示两条车体轴各自的位移。可用 `mission_config:=...` 指定其他比赛配置文件；只读取斜移参数，起终点以网页或显示屏本轮选择为准。页面显示实际距离和配置来源，修改配置后重启工具。

Ctrl+C 结束入口会统一退出本工具启动的进程。发现已有控制进程时入口拒绝启动，不关闭用户进程。未连接硬件时仍能打开页面，但真实反馈不就绪时不能启动运动。

启动检查只把实际提供服务的节点视为服务冲突；Foxglove 等观察工具保留的服务客户端不会阻止启动。服务冲突信息会显示服务端节点名，便于定位。

## 自由行走

1. 选择节点1～9的起点、终点及当前车头方向，方向按原截图上下左右。
2. 将小车人工摆在所选起点并朝向所选方向。
3. 如终点为2／4／6／8，可勾选“到终点后按固定工作方向对齐”。不勾选时保持车头方向，按路径前进、后退或横移。
4. 起点为1或3时，可勾选“起步斜移出启停区”，默认关闭。开启时请将车摆在启停区内，按所选车头方向先两轴同时斜移到该区角点，再执行到目标节点的完整路线；斜移保持朝向，终点工作对齐仅在到达最终目标后执行。距离共用 `parking_offset_mm`，只添加起步出区，不添加终点入区。其他起点禁用并清除此选项。
5. 按需点击地图路段编号设置障碍，再点击“启动”，工具自动同步位置、发送本轮封路地图、规划并执行；结束后输出归零。

作业时车头朝向固定：二维码2朝下、原料4朝左、粗加工6朝右、暂存8朝下。二维码区用车左侧（+vy）面向二维码板，其余三区用车右侧（-vy）面向工作区。沿途经过工作区不转向、不等待。起终点相同也允许：按选项完成零路程任务或原地对齐。

## 模拟比赛

起点和最终停车区分别选择“启停区1（节点1）”或“启停区2（节点3）”。请将车摆在所选启停区内；从1出发时车头朝地图下方，从3出发时朝地图上方，都指向二维码区2。先保持车头方向两轴同时斜移：1前进并右移，3前进并左移，到达1左下角或3左上角，再按完整配置边长前往二维码区。

点击“启动”后依次执行：

```text
起始启停区内 → 斜移出区到角点 → 2 → 4 → 6 → 8 → 4 → 6 → 8 → 终点角点 → 斜移入区
```

各工作区到达并转到固定作业方向、确认执行器释放后，保持零速等待3秒；2也用等待代替扫码。共10段动作（8段正常导航及2段斜移）、7次等待，等待总计21秒。出区后直接前往二维码区，回到终点角点后直接斜移入区，不增加等待。最后保持到达角点时的朝向，由规划器按当前朝向换算入区方向，两轴各到达配置距离并确认执行器释放后才结束。不会启动相机、雷达、抓放任务，也不下发机构命令。

地图沿用节点位置作为角点锚定，模拟比赛及开启起步斜移的自由行走，其里程轨迹从启停区内相对角点的偏移开始；出入区段绘制斜线路线。自由行走关闭起步斜移时，直接按选定节点起步。

## 显示屏驱动

此模式复用上述模拟比赛的10段路线和7次3秒等待，不启动正式 mission、雷达、相机或抓放。保留网页地图、轨迹、执行状态和运动参数；网页起终点与朝向、禁行路段改为只读，由屏幕配置决定。操作核心为“开始 / 停止 / 复位”。

1. 在网页选择“显示屏驱动”，人工把车放在将要选择的启停区内，摆正车头。启停区1对应节点1、车头朝下；启停区2对应节点3、车头朝上。
2. 点击网页“开始”，工具才打开屏幕串口并接收本轮屏幕操作。此时清除旧任务码、请求屏幕进入 `select_routine`，丢弃开始之前的串口消息；请核对旧的按钮高亮，必要时手动取消。
3. 屏幕选择禁行路径，按路径页 OK；再选择起终点，按起终点页 OK。空禁行列表有效，禁行同时作用于两个方向。
4. 起终点页 OK 提交 `CFG`，同时表示开始运动。**从收到这个 OK 起保持零速至少2秒**，且必须等 C 板、里程、规划器和本轮地图就绪后，才斜移出区并进入比赛路线；初始化超过2秒时，在就绪后开始。网页显示启动倒计时。
5. 网页“停止”立即归零、取消倒计时、关闭本轮屏幕操作接收，并请求规划器停止。等待配置时也可停止；不能用屏幕再次按 OK 恢复。
6. 停止或正常完成后，先人工恢复车辆位置，再点网页“复位”。复位清除本轮配置并关闭屏幕操作接收；必须再次点击网页“开始”，重新在屏幕上提交禁行路径和起终点。

只有显示屏、未接 C 板时，也可点击网页开始并读取屏幕配置，但不会下发运动。提交起终点后最多等待 `initialization_timeout_s`（默认20秒），仍未就绪则停止并报错；可复位重做。保持网页连接，原有浏览器失联停止机制仍生效。

屏幕串口和波特率默认读取 `ros2_ws/src/agv_screen/config/screen.yaml`；可用 `screen_config:=...` 或 `screen_port:=...` 覆盖。仅点击显示屏模式的“开始”时连接屏幕，自由行走和模拟比赛不要求屏幕在线。不要同时运行正式 `screen_node` 或屏幕交互测试脚本，以免占用串口。网页显示实际屏幕串口和通信错误。本模式跳过真实扫码，因此仅清零屏幕旧任务码，不生成任务码或抓放统计。

## 障碍路径选择

自由行走和模拟比赛都可点击地图路段编号1～12，多选障碍路段；再次点击取消，“清空选择”恢复全部畅通。显示屏驱动模式由屏幕配置这些路段，网页只显示。选中路段及编号标红，表示双向禁行。路段编号与比赛图及串口屏一致，区别于底图红底的节点编号1～9：

```text
  7 ──①── 4 ──②── 1
  ③       ④       ⑤
  8 ──⑥── 5 ──⑦── 2
  ⑧       ⑨       ⑩
  9 ──⑪── 6 ──⑫── 3
```

启动或复位提交后锁定选择，初始化、导航、作业等待及停止确认期间均不能修改；需先停止，确认停止后修改并重新启动。切换模式保留当前选择，重新打开页面会显示已有任务的封路设置。其他页面在任务运行时同步显示该任务的障碍，并遵循现有控制权限制。

障碍通过现有 `blocked_edges` 接口传入，工具确认规划器收到相同封路集合后开始执行。规划器按封路地图绕行；无路可达时显示规划失败并停止。比赛各工作区之间共用本轮封路设置，启停区斜移仍在区内执行。

## 停止与复位

“停止”会立即关闭运动反馈转发、发送零速、取消倒计时并请求规划器停止，然后查询确认软件释放。停止后不提供续跑；确认当前节点和朝向后开始新任务。

重新运行：人工确认车辆所在节点与朝向，重新选择页面当前位置等信息，停止结果确认后可直接点击“启动”；工具建立新的任务和地图锚定。“复位”仍可用于单独准备上下文，但不是通信恢复的必经步骤。

每次切入PC、通信节点重启、串口重连或板端重启都会重建通信里程原点，旧任务终止，旧地图锚定失效。通信健康自动恢复，无需手动清锁。页面初始化只绑定当前位置与地图，不额外重置里程，不自动返回起点。

正常完成后可直接设置下一次任务并启动，同样须先按新设置摆好车辆。停止未确认或运动／复位服务结果未知时禁止再次启动；需检查执行端、退出工具、人工恢复现场后重新运行，不自动重发可能已执行的运动。

页面采用单一控制会话；其他页面可查看和停止。控制页停止接收状态或关闭后，最多按 `config/debug.yaml` 的 `browser_timeout_s`（默认8秒）触发停止。浏览器重连不自动恢复。新页面应等待旧会话超时后再接管。底盘自身反馈／指令超时机制独立运行。

## 显示与接口

地图位置由实际固定系 x/y 与人工确认的节点/朝向锚定后绘制，包含横向偏移，不再按规划段进度贴路，也不在完成时吸附终点。截图像素标定仅用于显示，平行边长度不一致时使用平均标定并提示近似；不会据此改变控制进度。它仍是轮式里程估计，不能消除打滑或IMU漂移。反馈失效时图标变淡并冻结，坐标会话改变时断开旧轨迹。

数值区分输入指令与下位机实际车体系速度，轴顺序统一为前 x / 左 y / 逆时针转。显示 x/y、yaw、坐标会话、许可代次及当前段投影/横向偏差。

例如起点 1、终点 2、车头朝下且未勾选终点对齐，直行应显示正 vx、vy=0、转速=0；对应里程位置沿本次起步前方推进。方向修正说明见 [车体坐标统一实施记录](../../docs/车体坐标统一实施记录.md)。

浏览器使用同源HTTP命令、SSE持续状态推送和应用心跳；全部控制逻辑在小车端串行执行。无WebSocket依赖。调试内部服务与话题位于 `/tools/route_debug/`：

| 接口 | 作用 |
| --- | --- |
| `plan` | 规划并执行服务 |
| `get_runtime`、`stop`、`reset_context` | 状态查询、停止、初始位姿同步 |
| `control`、`status`、`path` | 规划器内部速度、执行状态、路线 |
| `progress` | 可选10 Hz真实执行段快照 |
| `map`、`heartbeat` | 本轮封路地图与租约 |

硬件最终话题继续使用 `/C/controll`，本工具控制节点独占发布；反馈为 `/C/odometry`、`/C/status`。工具启动的规划器开启 `debug_allow_any_pose` 和 `debug_publish_progress`，正式规划器默认关闭这两项，保留原启停区复位限制。

## 验证

纯状态机和显示转换验证：

```bash
cd /root/工创
PYTHONPATH=tools/route_debug python3 -m unittest discover -s tools/route_debug/tests -p test_session.py -v
node tools/route_debug/tests/test_web.js
```

屏幕串口帧与开始/停止门控验证（仅使用新建PTY）：

```bash
source /opt/ros/humble/setup.bash
source /root/工创/ros2_ws/install/setup.bash
PYTHONPATH=tools/route_debug:$PYTHONPATH python3 -B -m unittest discover -s tools/route_debug/tests -p test_screen.py -v
```

完整ROS2／网页／伪串口验证（仅新建PTY，固定独立domain 94，需允许本机网络）：

```bash
./tools/route_debug/tests/run_ros_pty.sh
```

该测试启动真正的规划器与通信桥，通过HTTP提交任务、模拟板端里程响应控制帧，覆盖任意起点、比赛完整10段与真实3秒等待、可配置斜移距离与串口双轴速度、重复命令、停止、复位、同点转向和控制页失联；另用屏幕PTY验证网页开始门控、屏幕禁行与起终点、至少2秒零速等待、完整比赛路线以及倒计时急停。测试不连接真实C板或显示屏，临时配置使用较短边长以缩短验证时间，不修改正式YAML。

当前验证结果及仍需现场验收的项目记录于 `docs/路径规划与板件通信可视化调试工具实施记录.md`。

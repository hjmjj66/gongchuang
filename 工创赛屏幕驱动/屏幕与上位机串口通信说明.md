# 屏幕与上位机通信、交互联调说明

## 1. 运行交互程序

保持屏幕 USB 连接和正常供电，关闭其他软件对 COM5 的占用，不要拔线。在本目录打开 PowerShell：

```powershell
python -X utf8 interactive_screen_test.py --port COM5
```

缺少依赖时先运行 `python -m pip install pyserial`。串口采用 9600、8N1、无流控。程序不控制机器人运动。

## 2. 完整操作流程

1. 终端按回车开始一轮。程序把 show_number 的 t0、t1 清为 `000+000`，然后切到 select_routine。
2. 在 select_routine 多选不能走的路径，按 OK。终端显示禁行路径；不选表示无禁行路径。屏幕 OK 事件负责跳到 setup。
3. 在 setup 各选一个启动区和停止区，按 OK。终端打印两个区域；屏幕自行跳到 show_number。
4. 在终端手动输入四组三位任务码，例如 `452+321+254+312`，不提供默认值。屏幕分别显示 `452+321`、`254+312`，第二段没有开头加号。
5. 确认任务码后按终端提示，输入两个次数，例如 `3 2`，分别表示抓取正确次数、放置正确次数。程序先切 result，等初始化完成再更新 t4、t5。
6. 第三页保留任务码、显示次数。终端回车可继续输入次数；r 从禁行路径开始新一轮；q 退出。

注意：区域按钮和路径按钮只改变屏幕颜色，按对应页 OK 后上位机才收到整组选择。重新开始会清零任务码，但路径按钮是否恢复未选取决于 HMI 页面的初始化代码；若保留上轮高亮，请手动取消或在 HMI 初始化中清除。

## 3. 页面、控件约定

| 页面 objname | 功能及控件 |
| --- | --- |
| select_routine | 禁行路径多选；b4 是 OK |
| setup | 启动区/停止区选择；b0 启动1，b1 启动2，b2 停止1，b3 停止2，b4 OK |
| show_number | 任务码文本控件 t0、t1 |
| result | 任务码 t0、t1；抓取正确次数 t4；放置正确次数 t5，均为文本控件 |

select_routine 路径按钮映射：b0→1、b1→2、b2→3、b3→4、b5→5、b6→6、b7→7、b8→8、b9→9、b10→10、b11→11、b12→12。选中背景色是 2016。

show_number 的 t0、t1 文本控件本身必须设置 vscope=全局，以供跨页清零和复制；不能只设置页面本身。字库包含数字和加号，txt_maxl 建议至少 16。

result 前初始化事件：

```text
t0.txt=show_number.t0.txt
t1.txt=show_number.t1.txt
```

当前程序在进入 result 后用当前页 t4、t5 赋值，不依赖这两个控件跨页全局访问。不要在其他事件中不断重置次数。任务码在比赛中持续显示，实际字高至少 12 mm，实物测量确认。

## 4. 屏幕发给上位机的消息

所有消息以真实回车换行字节 0D 0A 结束。

| 消息示例（Python 字节表示） | 含义 |
| --- | --- |
| `b'ROUTE,1,5,12\r\n'` | 路径 1、5、12 禁行 |
| `b'ROUTE\r\n'` | 无禁行路径 |
| `b'CFG,1,2\r\n'` | 启动区 1、停止区 2 |

ROUTE 允许任意数量的不同编号，范围 1～12，不允许重复；数字表示禁止走的路径。CFG 两个数字只能分别为 1 或 2。ROUTE 后由屏幕执行 `page setup`，CFG 后由屏幕执行 `page show_number`。取消 OK 按钮的“发送组件ID”。

上位机必须支持串口拆包/粘包，不能假设一次 read 就是一条消息。直接使用 screen_protocol.py 中的新版解析器：

```python
from screen_protocol import ScreenMessageParser

receiver = ScreenMessageParser()  # 接收循环外创建一次
# 下列代码放进现有接收循环
for kind, values in receiver.feed(ser.read(min(ser.in_waiting or 1, 4096))):
    if kind == 'ROUTE':
        forbidden_routes = list(values)  # 空列表表示没有禁行路径
        print('禁行路径：', forbidden_routes)
    elif kind == 'CFG':
        start_zone, stop_zone = values
        print('启动区、停止区：', start_zone, stop_zone)
```

交互程序要求先收到 ROUTE（允许为空），再处理 CFG。原来的 ConfigParser 仅识别 CFG，仍保留供旧程序使用；新流程请使用 ScreenMessageParser。CFG 是否触发运动由主控逻辑决定，本协议没有另外发送启动指令。

## 5. 上位机发送给屏幕

每条指令分别发送，末尾追加三个真实字节 FF FF FF。当前联调每条间隔 100 ms。不要将多行正文不加分帧地作为一个字符串发送。

识别二维码后依次发送：

```text
show_number.t0.txt="452+321"
```

```text
show_number.t1.txt="254+312"
```

第三页次数显示依次发送：

```text
page result
```

等待约 300 ms 完成页面初始化，再逐条发送：

```text
t4.txt="3"
```

```text
t5.txt="2"
```

后续更新次数无需切页，在 result 页直接给 t4、t5 赋新值。次数是上位机统计的累计正确次数，屏幕不负责判定或递增。

交互程序中的函数可复用：

```python
from interactive_screen_test import send_task, send_counts

send_task(ser, '452+321+254+312')
send_counts(ser, 3, 2, enter=True)  # 切页后赋值
send_counts(ser, 4, 3)             # 已在 result，直接更新
```

任务码必须是四组三位数字，次数必须是非负整数。任务码保留字符串；颜色及位置是否合法由任务程序校验。如果进入第三页后修改第二页任务码，还需同步第三页，复制只发生在 result 初始化时。

## 7. 联调检查

- 返回 1A FF FF FF（变量名称无效）：核对页面和控件 objname、文本/数字控件类型及跨页全局属性。文本用 .txt，数字控件用 .val。
- 跨页复制编译失败：检查 show_number 的 t0、t1 控件本身是否为全局。
- 选择路径没输出：确认 select_routine 的 OK 事件发送 ROUTE，且结束为 printh 0D 0A，按钮高亮色与判断中的 2016 一致。
- 只收到 CFG 不继续：本轮尚未收到 ROUTE，先从禁行路径页按 OK。
- 改完 HMI 属性后保存、编译、重新打开模拟器；实物必须下载最新工程。
- 同一串口仅由一个程序打开，保持 USB 连接和屏幕供电。
- 通信无应答确认和重发机制；写入成功不代表显示一定成功。100 ms 和切页后 300 ms 是联调保守等待，不是显示成功确认。

本次更新经过软件消息解析和指令序列检查，新增禁行路径流程仍需实物联调。

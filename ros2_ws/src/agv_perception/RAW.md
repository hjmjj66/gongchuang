# 原料区取料流程

2026-11-18：取消任意颜色初始跟随、m0记录和机构返回m0。

到达原料区且已面朝工作方向后，执行高位工作位3，用新鲜停稳里程记录底盘进区位置P0，再沿车头方向前进 `base_motion.distance_mm`（默认 **12 mm**）。进区到位并确认停车后，在当前高位等待本件所需颜色；只追踪当前所需颜色，目标丢失立即停机构，在当前位置等待重现。

原料机构视觉伺服只控制旋转和伸缩，两轴误差及输出连续满足 `grasp_gate.qualified_frames` 后停轴执行抓取4。真实抓取程序自身返回高位，上位机不再发重复工作位，也不做机构位置返回。前两件完成后在当前位置等待下一颜色；第三件完成后直接执行收纳2。程序执行期间底盘保持零速。

收纳后退出方式与粗加工一致：

- 正式比赛开启 `merge_exit_navigation` 且使用真实导航时，请求 `defer_reference_return=true`；执行端原地停稳后报告延期返回，由下一段导航保留的固定系目标吸收这12 mm偏移。不额外重设导航原点或叠加第二份补偿。
- 关闭离区合并或使用8086单独调试时，按里程实际退回P0并确认停车后完成。容差默认1 mm。底盘进退/停车超时或反馈过期报错停止，不假报到位。

`base_motion` 在 [raw.yaml](config/raw.yaml) 和8086“原料区 · 底盘进退”中配置；距离为mm，速度为m/s，位置容差为m。其参数独立于粗加工/暂存。原料视觉PID、准心、门槛和预测参数保留原值。修改后网页下次开始生效，正式执行节点需重启。

8086的1秒模拟仅替代抓取，随后真实执行工作位3（包括第三件）；底盘进退、机构跟随与收纳都实际执行。单目标追踪模式仍直接从当前位置持续追踪，不运行整批进退流程。

固定程序使用 `/C/arm_command`，机构伺服使用 `/C/arm_servo`，旋转rad/s、伸缩RPM、升降0。取消不会自动收纳或退回P0。

## 卡尔曼与短时延迟补偿试验

`motion_prediction` 仅作用于原料机构视觉跟随；不改变底盘进退、动作号和固定抓取流程。正式 `raw.yaml` 和8086当前raw参数均为 `enabled: true`，8086保存参数时同步正式配置，整批作业和单目标追踪复用 `RawGantryServo`。关闭开关后恢复原来的逐新帧PID和帧间保持输出。网页停止后保存，下次开始生效。

状态为 `[e_u, e_v, de_u/dt, de_v/dt]`，单位为px和px/s。新帧按真实读帧时间间隔执行匀速卡尔曼预测/修正；控制循环按 `预测误差=滤波误差+相对像素速度×T` 计算两轴PID。`T=min(图像年龄+extra_delay_s,max_horizon_s)`，帧间投影不推进滤波后验、不重复使用同一观测修正。PID输出继续按既有旋转rad/s和伸缩RPM限幅，没有额外叠加速度前馈或D项。

| 参数 | 试验初值 | 含义 |
|---|---|---|
| `measurement_std_px` | 2.0 | 中心测量噪声标准差；实测静止目标抖动后调整 |
| `acceleration_std_px_s2` | 500.0 | 相对像素加速度噪声标准差；越大越快响应启停，也越易跟随噪声 |
| `initial_velocity_std_px_s` | 100.0 | 首帧速度设零时的不确定度 |
| `extra_delay_s` | 0.0 | 尚未包含在图像年龄里的相机/执行延迟，实测后填写 |
| `max_horizon_s` | 0.15 | 总外推上限；图像年龄超过此值时停轴、清计数，等待新帧 |

这些数值是未做现场标定的试验初值。相机时间戳是软件读帧完成时间，不是曝光时间；`extra_delay_s` 不应再次包含已由图像年龄计算的处理耗时。预测时限须不超过图像有效期；超过后者仍按视觉故障处理。目标丢失、切换颜色、固定动作、取消和预测超时均清空估计；新帧间隔超过预测时限也重新初始化并按设定帧数重新累计。

连续达标门槛继续使用**真实新帧的原始中心误差**和正常计算、限幅后的两轴输出。预测帧不会增加计数；帧间输出不再满足门槛时清计数。达到设定帧数后仍立即停轴并交接固定抓取程序，没有把相对像素速度当成转盘真实速度，也没有增加运动中拦截抓取。

网页诊断显示 `error_uv`、`filtered_error_uv`、`pixel_velocity_px_s`、`predicted_error_uv`、`frame_age_s`、`prediction_horizon_s` 和开关/有效状态。现场先使用单目标追踪，在同一准心、PID和限速下比较开关前后的误差、抖动、过冲与达标耗时，再验证整批取料。相机随夹爪运动，像素速度包含相机运动，不能据其接近零断定转盘停稳。


## 原始帧链路与延迟实测（2026-11-17）

原料作业和单目标追踪读取 `RingVision.latest()`，数据来自 `CameraStream` 最新1280×720原图的物料检测结果。识别结果先发布，再由独立线程绘图、缩放和编码JPEG；预览上限15 FPS、网页状态推送10 Hz均不限制50 Hz控制循环。预览忙时跳过显示帧，不排队等待显示。正式 `CoarseVision` 同样读取最新原图，且没有绘图、JPEG或HTTP步骤。抓取计数只累计控制循环实际收到的不同合格新帧。

本次8086未运行，使用同一 `RingVision`、现场相机和当前正式物料YOLO配置独立采样，不连接串口或发送运动指令；每组预热2秒、采样10秒，观测按约50 Hz读取。画面内检出颜色1/2/3，配置为30 FPS采集、30 Hz识别上限、4个相机缓冲。

| 场景 | 采集 / 识别 / 预览 FPS | 读帧至结果发布 ms（中位 / P95） | 50 Hz读取的观测年龄 ms（中位 / P95） |
|---|---|---|---|
| 全颜色几何，目标0 | 30.0 / 28.8 / 14.4 | 47.2 / 64.7 | 58.9 / 80.6 |
| 所需颜色2几何 | 30.0 / 29.5 / 13.3 | 46.8 / 62.7 | 56.9 / 80.4 |

原始结果见[原料延迟采样](../../../docs/相机检查记录/原料区延迟实测_20261117.json)。模型推理中位约28.5～28.8 ms，几何约2.2～3.1 ms；本次没有更改识别限频、模型、分辨率、缓冲数或预测补偿参数。页面新增“识别发布年龄”（`stages_ms.capture_to_result`），用于区分识别本身与JPEG/显示耗时；帧旁年龄还包含识别发布后到状态读取的等待。

时间戳在软件读帧完成时记录，不含此前曝光、USB和相机内部缓冲时间，也不含后续ROS、串口及机构执行时间。现场采样没有执行跟随或抓取，不能代表运动精度或传感器到机构动作的完整延迟。新增回归使用真实HSV检测并阻塞预览编码，确认原料仍能连续发布原始坐标和新帧，标定JPEG仍与自身帧匹配。

## 完整服务的带目标性能优化（2026-11-17）

前一次约29 FPS的数据来自独立识别程序。本次在8086完整ROS/HTTP服务及C板反馈负载下复现有目标时约12～13 FPS，说明独立采样不能代表完整调试服务的表现。

物料模型、圆心定位和判色现由 `MaterialWorker` 独立进程执行，原图使用共享内存传递，减少与ROS/HTTP的Python执行竞争。主进程异步等待识别，及时收集JPEG结果；预览按累计周期调度，避免识别在20 FPS附近时每次重新等待完整周期而落到10 FPS。JHB没有配对顶帽时跳过整幅白平衡和判色。正式 `CoarseVision` 同样使用该物料进程。

识别、控制和标定仍使用同一帧的原图坐标，没有降低分辨率、替换模型、关闭圆心定位或改动判定阈值。每次只处理一张图，下一次取最新采集帧；切换模型/颜色后丢弃在途旧结果，模型加载失败保留原模式。网页预览继续以15 FPS为目标。

同一X5、相同ROS/HTTP/桥接配置，30 Hz输入固定实拍图；原有模型使用 `check_black_blues.jpg`，JHB使用模型包 `selftest.jpg` 缩放至1280×720，两图均含三只物料。每种模式预热2秒，以200 ms间隔读取30次网页状态；下表FPS为采样中位数，图像年龄在网页状态生成时计算。未开始作业，也没有执行抓取。

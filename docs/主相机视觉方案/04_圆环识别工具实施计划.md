# 圆环识别工具实施计划

日期：2026-10-30。状态：下文保留原实施计划；现已完成几何核心、编号框处理与独立图片调试入口，真实 YOLO 模型与推理适配仍待接入。实际用法见[视觉工具说明](../../ros2_ws/src/agv_perception/README.md)，实施记录见本文末尾。

## 1. 本轮目标和已确认选择

实现供粗加工区、暂存区等任务复用的圆环识别工具：YOLO 识别编号工位并提供 ROI，传统视觉在各自 ROI 内寻找圆心，精定位失败时允许退回当前检测框中心，并明确标记中心来源。

用户已确认：

1. 编号印在圆环中心，工位编号为 1、2、3。
2. YOLO 按编号分类；每种编号只取达到最低置信度的最高置信度框。
3. 每个编号工位使用独立 ROI，可以适当扩展后再找圆。
4. 使用灰度、模糊和按需启用的形态学处理，再进行霍夫圆检测。
5. 一个可信圆即可提供中心；多个中心相近的同心圆可融合中心，不强求检测出全部同心环。
6. 最终输出统一还原为主摄像头原图坐标。
7. 找圆失败时可退回 YOLO 框中心，结果需区分圆检测中心与框中心。
8. 工具输出观测，区域程序负责目标选择、持续对准、稳定判定和动作。
9. 用户尚未训练模型，模型路径和部署格式留空；不使用第四份开源的模型，不自动下载示例模型。

“一个 ROI”代表一个编号工位，工位内部可以包含多条同心环。不能把三个编号工位放在一个框中，再用左右排序代替编号识别。

本轮按已确认的组合方案编写，不再实现两套并列的正式识别模式或增加 1/2 后端开关。纯几何检测作为可独立调用、独立调试的组成部分保留，不负责自动识别编号。

## 2. 与现有项目的关系及范围

工具放在现有 `agv_perception` 包内，不另建 ROS 包。核心接收调用方传入的图像，不自行打开摄像头、不发布底盘速度、不发送机构命令。

后续主相机节点统一采集，圆环工具和物料工具共享图像；各区域程序复用同一套圆环检测核心。独立调试时允许调试节点单独打开主摄像头，不能与另一个主相机采集进程同时占用它。

已有 `agv_perception/camera.py` 提供持续采集、最新帧缓存、帧序号和接收时间，独立相机调试优先复用它。当前线程名带 `qr_camera` 不影响功能，不为本工具提前重构扫码代码。

本轮实现范围：

- 单帧编号候选处理、ROI 几何精定位、坐标还原、框中心退化及结果结构。
- YOLO 接入边界与未配置状态，模型参数占位。
- 静态图片的手动 ROI 几何调试，以及正式模型接入后的图片、相机调试入口。
- 配置、可视化、针对实际算法的测试和使用说明。

本轮不实现模型训练、数据集制作工具、底盘或机械臂伺服、区域状态机、工位跨帧跟踪、卡尔曼滤波、被遮挡圆心预测和纯传统数字识别。

现有区域文档仍包含“按左右顺序赋编号”的旧设计。本计划对圆环身份与检测路径的约定优先；区域流程、动作约定等不因本次工具计划而改变。

## 4. 核心输入与输出

### 4.1 输入约定

组合入口概念上为 `RingDetector.detect(frame, frame_seq, stamp)`，返回本帧观测。模型在工具初始化时加载一次，不逐帧加载。

- `frame`：OpenCV 原始 BGR 图像，不含框、十字线或文字等绘图。
- `frame_seq`：本次图像序号，由采集层提供。
- `stamp`：图像对应的时间，由采集层提供。
- 阈值、类别映射及几何参数在初始化时读入配置。

现有 `CameraStream` 的时间戳记录软件读帧完成时间，不是传感器曝光时间；沿用时在结果说明中保留这个含义，不能据此宣称已测得相机端到端延迟。调试采集层使用现有单调接收时间检查缓存年龄。

核心不负责多帧稳定判断。图像类型、配置和模型输出只在对应入口做检查，内部函数使用已规范的数据。

### 4.2 一帧输出

一帧结果携带帧号、图像时间、处理耗时、总体状态及三个编号各自的结果；编号固定按 1、2、3 排列。没有检测到的编号也有明确无效状态，不由订阅方猜测空缺原因。

| 字段 | 含义 |
|---|---|
| `ring_id` | 场地编号 1、2、3，由类别名称/配置映射得到，不直接使用模型内部类别索引 |
| `identity_source` | `yolo` 或 `manual`；后者仅用于显式手动 ROI 调试 |
| `valid` | 本帧是否存在可使用的中心观测；不表示已经对准或可以放料 |
| `status` | 检测与退化状态，例如 `OK`、`NOT_DETECTED`、`BBOX_ONLY`、`TRUNCATED` |
| `center_px` | 原图像素中心，浮点值；无效时为空值，不能使用 `(0, 0)` 代替无目标 |
| `center_source` | `circle`、`bbox` 或无来源 |
| `yolo_confidence` | 模型检测置信度，不能当成圆心精度 |
| `bbox_xyxy` | 原图中原始检测框，供检查框中心与标注一致性 |
| `roi_xyxy` | 扩展且限制在图像内的实际处理区域 |
| `radii_px` | 最终同心组内保留的半径，仅圆检测成功时提供 |
| `circle_support` | 最终圆组的圆周边缘支持指标及有效圆数，用于解释精定位依据 |
| `geometry_reason` | 找圆失败、圆组歧义等原因，框中心退化时仍保留 |

核心使用简单 Python 数据结构；首版不为调试提前增加 ROS 自定义消息。调试入口可以输出 JSON 文件/JSONL 记录，区域集成时先直接调用核心接口。

## 5. 正式组合处理流程

### 5.1 模型初始化与类别规范

未来模型必须能够区分 1、2、3 三个工位，框住完整外圈，中心数字自然位于框内。训练标注应围绕圆环外边界，避免把旁边背景和文字大面积纳入框，保证框中心退化具有几何意义。

模型适配层将不同部署格式的结果规范为：类别编号、置信度、原图浮点框坐标。若推理前有缩放或 letterbox 补边，在这一层完成反变换。

模型若已自带 NMS，不再重复执行同一轮 NMS。若未来输出是原始张量，则由该适配实现所需后处理，不让几何模块了解模型张量格式。

当前没有模型，适配层先保留接入边界及清楚的未配置提示。待用户提供模型和格式后，再实现对应运行时；不先绑定 Maix、PyTorch、ONNX 或 X5 BPU 的某一种实现，也不承诺现阶段已能推理。

### 5.2 每编号只保留最高置信度框

1. 将模型类别映射为 1、2、3；忽略不属于三种编号的类别。
2. 过滤低于 `confidence_threshold` 的候选；等于阈值可以保留。
3. 每种编号选择置信度最高的一个框；分数相同时按模型输出顺序固定选择第一个。
4. 之后只处理所选框，不把三个编号互相竞争后只留下一个全局最高分框。

用户确认的选择规则优先：选出的最高分框如果几何失败，按框中心退化规则处理，不悄悄改选同编号的较低分框。

同一物理区域若被不同编号分别选中、存在明显重叠冲突，先记录和显示，不增加额外编号投票/跨帧重关联算法；正式控制如何利用这些结果留在区域集成阶段评估。不能把最高置信度规则描述为已经保证编号绝对正确。

### 5.3 裁剪 ROI

- 按检测框宽、高的一定比例分别向四周扩展，比例来自 YAML。
- 裁剪到原图边界；保留真实 ROI 原点，供坐标还原。
- ROI 从原图裁出，不从模型输入缩略图或已绘制调试图中裁出。
- 首版直接在原尺寸 ROI 上运行几何检测，避免增加一次缩放与尺度换算；未来确有性能需求再增加。
- 扩展 ROI 触及图像边界本身不等于圆环截断；若原始检测框已经触及图像边界，则标记目标可能截断。可信圆检测仍可提供结果，框中心退化默认不接受这种情况。

### 5.4 灰度、形态学和霍夫圆

基础处理采用 `BGR → 灰度 → 高斯模糊 → HOUGH_GRADIENT`。首版选择标准霍夫，便于参数解释与验证；借鉴西安理工的候选定位思路，不完整复制其增强链，也不同时实现 ALT 分支。

按需启用的形态学分支采用：暗色反二值化（暗环变前景）→ 小核开/闭运算 → 霍夫圆。这样形态学操作作用于明确的前景掩膜，而不是把灰度或 HSV 的腐蚀效果与二值掩膜混用。

预处理选择固定在 YAML 中，不逐帧试遍多个分支后盲选。默认先用灰度基础路径，调试图证明有收益后，再启用二值形态学路径。高斯核、二值阈值、形态学核与次数、霍夫参数分别配置；开闭运算允许关闭。

不默认启用 CLAHE、强膨胀、椭圆拟合或额外轮廓拟合路径。

### 5.5 可信圆筛选

霍夫输出先作为候选，以以下信息筛选：

1. **半径范围**：采用相对原始检测框短边的比例，转换为当前 ROI 的像素半径；比例需要实拍标定，以覆盖需要使用的同心环。
2. **位置范围**：圆心位于框内的合理中央区域，与框中心的允许偏离按框尺寸归一化配置。
3. **圆周支持**：在模糊灰度图的 Canny 边缘上，沿候选圆周采样；允许小幅径向容差，计算有边缘支持的比例以及分布在多少个角段。

圆周支持同时看比例与角段覆盖，避免数字中的局部弧线仅在一个小区域提供边缘。对应门槛可配置，现阶段不冒充已标定值。

原图候选圆是否可信由这些几何依据决定，不使用 YOLO 置信度替代边缘检查。霍夫找不到圆或全部候选不合格时，进入退化分支。

### 5.6 同心归并与中心融合

- 候选按圆周支持程度从高到低处理。
- 圆心距离在门槛内、且加入后组内最大圆心距离仍不超过门槛，才进入同一组，避免链式归并把多个中心连起来。
- 半径和中心均几乎相同的重复候选只保留支持更好的一个，避免重复边缘增加虚假的独立证据。
- 一组只有一个可信圆也有效，不要求三条环全部出现。
- 一组有多个一致圆时，以圆周支持程度作为权重融合圆心；半径保留为列表，不合成一个没有明确物理意义的半径。

存在多个不同中心的组时，按圆周支持、与框中心的接近程度选择；圆数只作为附加依据，不以“圆越多越正确”为原则。若两组在配置门槛下仍无法明确区分，记录几何歧义并使用框中心退化，不任意选一个圆组。

### 5.7 坐标还原

局部中心为 `(u_roi, v_roi)`、实际裁剪原点为 `(x0, y0)` 时：

```text
u_image = x0 + u_roi
v_image = y0 + v_roi
```

保留浮点精度，只在绘图时取整。模型框反变换在适配层完成，ROI 中心还原在组合层完成，两者分别测试，避免重复缩放或遗漏偏移。

图像左上角为原点，x 向右、y 向下，单位为像素。结果不是底盘、机械臂或世界坐标，不在本工具内换算运动指令。

### 5.8 退化、无效与新帧

| 情况 | 返回行为 |
|---|---|
| 编号达到阈值，得到可信圆组 | `valid=true`，来源 `circle` |
| 编号达到阈值，找圆失败，原框完整可用 | 原始 YOLO 框中心，`valid=true`，来源 `bbox`，状态 `BBOX_ONLY`，保留几何失败原因 |
| 找圆失败且原始框触及图像边界 | 默认不使用框中心，`valid=false`，状态 `TRUNCATED` |
| 某编号没有达到最低置信度的框 | 该编号 `valid=false`，状态 `NOT_DETECTED` |
| 模型未配置或无法加载 | 明确报告 `MODEL_NOT_CONFIGURED` / `MODEL_LOAD_FAILED`；正式入口不进入正常检测循环 |
| 相机无新帧或图像已过期 | 调试采集层报告状态，不重复包装旧中心为新观测 |

框中心使用原始检测框计算，不使用扩展 ROI 的中心。即使扩展在图像边缘发生不对称裁剪，也不会改变退化中心定义。

退化策略由配置开关控制，默认允许完整框退化。区域接入时根据 `center_source` 决定是否用于最终动作；本工具不把 `valid=true` 解释为最终精对准通过。

## 6. YAML 组织和参数

`ring_debug_node` 沿用现有 ROS2 的 `节点名 → ros__parameters` 结构，参数启动时读取，修改后重启生效。核心接收解析后的配置，不在每帧读磁盘。

| 参数组 | 内容与默认意图 |
|---|---|
| 模型 | `model_path: ""`、`model_format: ""`；`class_labels: ["1", "2", "3"]` 表示要求的语义类别，接入真实模型时核对内部类别顺序 |
| 候选选择 | 最低置信度、模型后处理需要时使用的 IoU 阈值；例如 0.5 / 0.45 只能作为调试起点，不代表实测结论 |
| 相机 | 设备路径、1280×720、请求 30 fps、4 缓冲、动态帧率设置、处理频率、最大图像年龄 |
| ROI | 扩展比例、最小可处理尺寸、原框触边容差 |
| 预处理 | 灰度基础/二值形态学选择、高斯核、阈值、小核大小和开闭次数 |
| 霍夫 | `dp`、`minDist`、`param1`、`param2`、相对半径上下限；`minDist` 不可大到跨工位误用，也不以检测出全部同心环为目标 |
| 可信圆 | 中心偏移上限、圆周采样数、径向容差、支持比例、角段覆盖门槛 |
| 归并 | 圆心距离门槛、重复候选半径容差、组选择歧义门槛 |
| 退化 | 是否允许框中心，原框触边时默认不允许框中心 |
| 调试 | 图片路径、预览开关、结果输出路径、手动 ROI、手动编号提示 |

主相机设备参考现有 C100 检查记录中的稳定路径；实现时在配置注明其为历史检查值，现场通过枚举核对，不修改扫码相机配置。相机实际帧率和模型处理帧率分别统计，不承诺 YOLO 也达到 30 fps。

几何检测只有一个当前 profile。未来粗加工、暂存若需不同参数，由调用方分别实例化/传入对应配置；本轮不引入复杂的区域继承与配置合并系统。

## 7. 没有模型时如何开发与验证

模型留空不妨碍验证几何算法，但不能完成自动编号检测。

提供显式的 `geometry_only` 图片调试方式：用户在配置或命令参数中给出一张图、一个手动框和可选编号提示，运行同一个 `ring_geometry` 实现，保存候选圆、可信圆组和最终中心图。

手动输入的编号只用于调试标注，输出必须标记 `identity_source=manual`；自动组合结果标记为 `identity_source=yolo`。手动输入不得被描述为模型检测结果，也不作为正式自动识别路径。

没有提供手动 ROI 时不自动做全图找圆并按左右顺序编造 1、2、3。模型配置为空时，正式组合/相机识别入口在打开相机前说明缺少模型并退出；只有显式几何调试入口可以绕过模型。

现阶段可以完成：

- 参数读取、模型缺失提示、结果结构与调试入口。
- 实际 OpenCV 圆检测、筛选、归并、融合和局部坐标还原。
- 针对规范化框列表的编号选择及退化组合逻辑；测试框是明确的测试输入，不是运行时伪模型。

待用户训练并提供模型后完成：

- 对应部署格式和运行时的真实加载、预处理、推理、后处理。
- 类别映射、坐标反变换以及 X5 上的耗时验证。
- 真正的 1/2/3 自动编号识别与相机完整链路验收。

## 10. 验证方式与验收边界

沿用仓库现有 `unittest` 风格，直接调用真实实现，不引入新的测试框架。

| 检查 | 验证内容 |
|---|---|
| 编号与阈值 | 同编号最高分、三个编号独立保留、阈值等号、未知类别、缺失编号；不绕过最高分框选择规则 |
| 坐标 | 非零 ROI 原点、向边界裁剪、框中心与扩展中心区别、原图坐标还原 |
| 几何 | 使用绘制圆环图运行实际 OpenCV：单圆、同心环、中心数字、局部噪点、多个不同圆组、无圆 |
| 归并 | 接近圆心融合、重复候选处理、组内最大距离限制，保证不会把相离中心串联融合 |
| 退化 | 找圆失败且完整框时返回 `bbox`；触边不能用框中心；无模型不能用退化机制绕过模型 |
| 输出 | 无效中心为空、来源准确、手动身份不冒充自动识别、帧号与时间跟随当前输入 |
| 模型接入后 | 类别名称映射、真实缩放/补边坐标反变换、真实模型完整链路 |

合成图的圆心容差按真实 OpenCV 输出设置，不要求霍夫结果与绘图整数坐标完全相等；几何误差应以原图像素为单位记录。合成测试验证算法实现，不替代现场参数标定。

实拍验收分别记录圆检测中心与框中心相对人工参考中心的误差、识别/漏检情况、几何精定位成功率和整帧处理耗时。不在没有模型和实测图像时编造准确率、毫米精度、固定圆周门槛或可最终放料结论。

构建使用现有 colcon 流程，只针对相关包执行适当检查。本次编写计划不运行旧硬件程序、不安装推理依赖、不修改构建产物，也不触碰工作区已有的路径规划和网页工具改动。

# 原料区龙门架视觉伺服改造指导计划

日期：2026-11-15。状态：原料正式执行及8086原料调试已按本计划实施，软件验证见[实施记录](13_原料区龙门架实施记录.md)；动作号已按v0.5落实，实车标定及联调待完成。

本计划替代[旧原料区指导](08_原料区任务流程与实施指导.md)中逐件通过底盘跟随、临时颜色跟随、三帧丢失恢复、找料总超时以及先返程后收纳的规定。旧版本的软件实现与验证仍见[原料实施记录](11_原料区实施记录.md)，不能据其测试结果认定本次改造已实现。

## 1. 范围与已确认条件

- 只修改原料区正式流程及现有8086网页的原料选项，粗加工、暂存的业务流程保持现状。
- 正式比赛仍在阶段4、10调用 `RAW_PICK`，每批严格按输入的三种颜色顺序抓取；两批各自重新记录入站位置、定位转盘中心。
- 014电机驱动整个伸缩导轨绕固定轴旋转；相机固定在夹爪正上方，近似垂直俯视，与夹爪相对静止，随伸缩和旋转一起运动。
- 机构采用图像误差速度闭环：横向像素误差控制旋转角速度，纵向像素误差控制伸缩RPM，不计算绝对长度或绝对角度目标。
- 图像上方对应导轨伸出方向；目标在标定点左侧时，机构从上往下看逆时针转动。
- 转盘中心粗对准与逐件抓取使用同一个像素标定点，空配置时默认为实际原图中心。
- `fb_mm`、`yaw_rad` 只作为调试观测，不参与图像误差闭环，也不作为实际停稳的证明。长度、角度的机械限位由下位机负责，上位机保留正常速度限幅。
- 用户已确认：伸缩/旋转点动后可以直接执行抓取、工作位及收纳程序，不要求额外HOME。该确认更新了旧协议文档中点动后基准失效的适用前提，实施时需同步说明，不能修改既有协议字段含义。
- 正式抓取程序负责抓取、入仓、托盘转120°，并回到统一的工作位置，不回到上一次视觉跟随结束的伸缩/旋转位置。

## 2. 完整执行流程

```text
到站并停车
  → 用新鲜里程记录本批入站 P0=(x0,y0)
  → 执行工作位程序，等待完成
  → 底盘慢速寻找物料、估计转盘圆心
  → 底盘用圆心像素误差粗对准同一抓取标定点
  → 底盘停车，锁定本批转盘定位阶段完成
  → 等待当前所需颜色
  → 底盘保持零速，用旋转+伸缩持续跟随
  → 连续4张新帧：中心对准、旋转输出很小、伸缩输出很小
  → 两机构轴归零，提交本件抓取
  → 抓取/入仓/托盘转位/回工作位完成
  → 下一颜色；不重新移动底盘定位转盘中心
  → 三件完成后先收纳，等待收纳完成
  → 底盘二维返回本批 P0，停车
  → 本次完成，交回比赛调度
```

原料阶段不新增升降点动，不做底盘角度纠偏，底盘 `wz=0`。底盘只在初始找料、转盘圆心粗对准和最终返程期间运动；逐件跟随、丢失等待、回工作位、抓取、收纳期间保持零速。

## 3. 初始底盘找料与等待

### 3.1 可见物料的处理

识别调用强制返回全部颜色，使用现有工具输出的有效最终中心，不限制HSV、YOLO顶面或整体模式。初始转盘定位只使用本批三种颜色对应的物料，避免把其他目标混入圆拟合。

同一张新图像同时有三个有效中心时，优先用这三个点求圆心。只有一两个可见时，允许底盘慢速跟随一个可见物料，以获得三个中心的共同视野；这个阶段不执行抓取，也不推进颜色索引。选择规则可复用“本批顺序中最先可见者”，锁定后避免在两个可见物料之间反复切换；它只是初始定位手段，不是后续按色跟随的临时目标机制。

初始跟随和圆心粗对准分别使用独立的低速参数，速度应比旧版逐件底盘跟随更缓和，不能直接照搬旧增益。

### 3.2 完全无目标时的一次扫描

在初始找料没有任何本批物料可见时，执行一次：

1. 按用户的工作区方向，`vx>0` 向左走100mm，到位停车1秒。
2. 若仍未看到物料，从该处以 `vx<0` 向右走200mm，到位停车1秒。
3. 若仍无物料，在当前所在位置保持停止，持续等待，不返回P0、不自动收纳、不报找料失败、不反复重扫。

“左/右”是用户对当前原料工作视角的称呼；ROS底盘仍沿用车体系 `vx` 正前负后，不修改公共坐标约定。距离沿扫描起步时的车体x轴方向，通过二维里程反馈投影闭环测量，不以速度乘时间代替；第二段200mm从第一段终点量起，因此无目标完整走完后相对扫描起点为负100mm。

扫描移动或停车期间，只要出现任意一个本批有效物料，立即结束剩余扫描，底盘先取消原扫描速度，再转入慢速找视野/定位；不要求继续走完100mm或200mm，也不要求补完尚未结束的1秒等待。

初始扫描只用于尚未完成转盘定位的阶段。锁定底盘以后，目标不可见不能触发这套扫描。

### 3.3 无法得到可靠圆心

若能看到物料但不能得到可靠圆心，例如有效点不足、轨迹没有展开或三点近共线，不能用假中心继续流程。底盘停止，机构保持工作位，继续观察和等待；不存在“圆心估计超时后返程/失败”的业务分支。

后续得到可用新观测后继续定位。用户的“持续等待”适用于图像正常但没有目标或几何条件不足；不等于允许通信失联、图像断流、执行错误时继续运动。

## 4. 转盘圆心估计与粗对准

### 4.1 同帧三点估计

相机近似正俯视，三个物料顶面中心在近似同一平面，首版按像素平面上的圆处理，不引入椭圆透视校正。设三个中心为 `(u_i,v_i)`，解：

```text
(u_i-a)^2 + (v_i-b)^2 = R^2
```

得到本帧圆心 `C=(a,b)`。完全重合、过近或近共线的点不能产生可用圆心。三个点确定一个圆本身不证明估计精确；本任务只用于粗定位，几何有效性判断需结合实际图像设定，不将其当成高精度转盘测量。

### 4.2 轨迹拟合作为补充

一直不能同帧看到三个中心时，允许先让底盘和机构全部停止，等待转盘转动，累计可见物料的多帧中心，再用最小二乘等现有简单方法拟合共同圆心。

只在同一个静止相机姿态下累计轨迹；同一采集帧不重复加入。点需要有实际空间分布，不能用几乎不动的单点或短小退化轨迹强求圆心。等待转盘运动后自然补齐，不虚构剩余物料的位置。

底盘或机构只要开始移动，就清空该静止姿态下的轨迹样本。跨相机位移不能直接混合像素坐标。轨迹求出的旧像素圆心也不能在底盘移动后继续充当当前观测：移动后应由同帧三点重新估计，或重新停车采轨迹；因此这种补充模式可以分段“停车估计 → 小幅慢速纠正 → 停车重估”。

### 4.3 持续更新直到对准

转盘圆心与抓取共用标定点 `Q=(u_ref,v_ref)`，底盘使用当前有效圆心误差进行慢速视觉伺服。沿用已确认的初始底盘映射：

```text
e_u = a - u_ref
e_v = b - v_ref
vx = -PID_center_u(e_u)
vy = +PID_center_v(e_v)
wz = 0
```

粗对准过程中持续更新新圆心，不是先估计一次后拿旧坐标一直移动。当前帧不能提供有效中心时不沿用旧速度，底盘归零；等待新同帧估计或静止轨迹估计。

圆心到标定点的像素误差进入较宽的粗定位容差，且底盘停车反馈正常后，结束本批转盘定位。具体容差及必要的新帧确认数作为标定参数，初值不能冒充现场已标定值。

每批只完成一次这个定位阶段。后续机构跟随会使相机画面改变，不能继续利用锁定前的圆心像素作为伺服目标；也不因物料抓走而重新拟合剩余两点或一点。

## 5. 伸缩、旋转图像误差伺服

### 5.1 目标选择

底盘停车后，只寻找当前顺序所需颜色。当前颜色不可见就等待，不跟随第二、第三顺序的颜色。看到当前颜色的一张有效新帧即可开始机构跟随，不采用旧的三帧恢复门槛。

已抓取或网页中已模拟完成的颜色从剩余目标中排除。不同物料中心由工具提供，任务层不重新计算颜色或顶面中心。

### 5.2 两轴控制方向

设当前所需物料中心为 `(u,v)`：

```text
e_u = u - u_ref
e_v = v - v_ref
yaw_wz = -PID_yaw(e_u)   # rad/s；目标偏左 e_u<0 → 逆时针正转
fb_rpm = -PID_fb(e_v)    # RPM；目标偏上 e_v<0 → 正向伸出
ud_rpm = 0
底盘 vx = vy = wz = 0
```

两轴允许同时运动。使用限幅后的有符号输出；先用较小P增益调试，I/D默认从0开始。伸缩长度改变会改变旋转对像素的响应，首版通过低速增益及现场调参适配，不要求反解绝对 `r、t`、标定014轴投影或像素毫米比例。

图像误差零线是通过抓取标定点的竖直线；准心为空时才等于画面竖直中分线。不使用“物料与画面底边中点连线的斜率”作为真实极角，也不把拟合转盘中心当成机构旋转轴。

### 5.3 丢失与回工作位

当前颜色丢失时立即将伸缩、旋转输出归零并清空抓取计数，底盘继续零速。短暂丢失期间若目标出现，一张新帧即可恢复跟随。

连续丢失超过可配置的短期时长后，执行一次工作位程序，等待完成，再在工作位持续等待同一个所需颜色：

- 无等待总时限，不报找料超时、不跳颜色、不自动离站。
- 不重做底盘扫描或转盘中心定位。
- 一次丢失事件只回工作位一次，等待期间不反复发送工作位指令。
- 目标再次出现，直接恢复伸缩/旋转跟随；之后若重新发生长时间丢失，再执行上述恢复。

工作位动作过程中不使用画面驱动跟随；动作完成后丢弃动作前/动作中的控制观测，等待新姿态图像。

## 6. 抓取门槛与完成语义

相机随机构运动时，转盘仍在转动也可能出现物料像素稳定。因此不能只凭物料连续几帧位移小，或只凭底盘零速，宣布物料停稳。

正式和网页统一要求当前所需颜色连续4张不同的新采集帧同时满足：

```text
hypot(e_u,e_v) <= grasp_tolerance_px
abs(yaw_wz) <= small_yaw_output_rad_s
abs(fb_rpm) <= small_fb_output_rpm
```

检查的是本帧正常计算、限幅后的PID输出，不能先强制输出0再拿0通过门槛，也不能拿固定动作阶段的0累计计数。任一条件失败、目标丢失、旧帧/重复帧或切换物料均不能累计达标帧；无新帧时不增加计数，图像超过有效期应按视觉故障处理。

第4张合格帧当次产生两轴零速和一次抓取请求，不额外引入视觉停车复核等待。桥接负责先停止连续点动，再按下位机固定动作的空闲要求交接；不能让旧的非零JOG在抓取后重新生效。固定动作受理等待和执行期间，底盘及视觉点动始终为0，不因画面移动重新跟随。

上述是用户确认的近似停转判据，表示图像误差及控制需求都较小，不声称测得转盘真实速度。现场需核对阈值、相机处理延迟和夹爪接触延迟，不能把 `fb_mm/yaw_rad` 的显示值包装成实测速度。

固定抓取完成后，才记本件 `PICK` 完成并推进索引。ACK只表示受理；本次程序完成反馈应已包含入仓、托盘转120°、恢复工作位。没有抓实传感器或抓实视觉复核，不在结果里声称已验证实际夹取。

## 7. 收纳与返程

第三件抓取程序完成 → 收纳 → 收纳完成 → 二维返回P0 → 停车完成。此顺序覆盖旧版“保持工作位返程、回P0后收纳”。

二维返回复用本批固定里程系的x/y闭环，当前yaw仅用于固定系到车体系的速度转换，不做目标朝向对齐。每批重新获取P0，不能沿用第一批参考。

完成结果仍需三项有序 `PICK`、已收纳、已回P0、机构空闲和运动控制已释放；`final_alignment_outcome=NOT_RUN`。仅抓完或仅收纳完不能提前完成比赛阶段。

## 8. 正式与网页的对应关系

继续复用现有[三区域网页入口](../../tools/coarse_debug/README.md)，不另建第四个网页。原料选项的新版提示必须明确“真实底盘与龙门架运动”，不能保留旧的“全程不发送机构动作”。粗加工、暂存原有调试选项继续遵循各自规则。

| 环节 | 正式原料任务 | 新版网页原料调试 |
|---|---|---|
| 输入 | 比赛任务颜色顺序，阶段4或10 | 人工输入三个不同颜色，如213；两批无需不同选项 |
| 开始 | 记录P0，实际执行工作位 | 同样记录P0并实际执行工作位，不再要求人工固定到工作位 |
| 初始扫描与圆心定位 | 真底盘运动，持续更新圆心 | 完整复用 |
| 按色跟随 | 真旋转、真伸缩 | 完整复用，实际发送JOG |
| 长时间丢失 | 回工作位，持续等当前颜色 | 同样实际回工作位并持续等待 |
| 抓取触发 | 4帧中心/两轴输出达标，实际抓取程序 | 相同门槛；仅抓取程序替换为两轴和底盘零速等待1秒 |
| 每件后 | 抓取程序自动恢复工作位 | 1秒模拟完成后单独实际执行工作位；完成后再处理下一件 |
| 结束 | 实际收纳，完成后底盘回P0 | 同样实际收纳并回P0，不自动开往下一区域 |

网页物料不实际移走，已模拟完成颜色即使仍可见也忽略。模拟抓取的计数在1秒完成时记录一次；工作位恢复仍须完成，才能开始下一件。第三件也完成对应工作位恢复后再收纳，与正式抓取结束姿态一致。

网页应展示：本次P0、当前状态、扫描段与已走距离、同帧三点/静止轨迹圆心来源、当前估计中心及半径、粗对准误差、所需颜色、物料中心来源、两轴像素误差、旋转/伸缩输出、4帧计数、当前等待原因、已完成件数、工作位/收纳执行状态。`fb_mm/yaw_rad` 若展示，标为下位机位置反馈/指令位置，准确语义以电控为准。

独立调试YAML及网页编辑保存继续使用现有方式，保存只影响原料调试参数，不改正式比赛配置、不改粗加工和暂存参数。运行中禁止切换区域或保存控制参数；停止、页面失联不自动恢复任务。

## 9. 接口改造与现有实现的差距

### 9.1 保留的公共入口

保留 `/vision/raw/run_batch`、`RAW_PICK`、公共宿主 `coarse_node`、现有运行/停止/复位及区域互斥。正式底盘最终输出仍经mission仲裁，不从视觉节点绕开 `/C/controll`。网页保持独立调试入口及唯一桥接持有者。

物料工具仍一次输出全部颜色和最终有效中心；一个共享相机线程，不另开原料相机进程。机构视觉跟随期间必须持续采集和识别；只有固定动作期间暂停用于控制的观测。旧版“机构动作期间暂停识别”不能错误套用到视觉JOG阶段。

### 9.2 连续旋转/伸缩通道

串口已有 `0x03 ARM_JOG`：`yaw_wz` 为rad/s、逆时针正；`fb_rpm` 为RPM、伸出正；`ud_rpm` 保持0；固定动作仍用 `0x02 ARM_CMD`。不改帧格式、单位和ID，不另开串口。

当前ROS `JogArm.srv` 只提供定时升降，`ArmController` 把它当作一个待完成的点动动作，尚不能逐帧更新旋转和伸缩。需要增加用于持续视觉控制的速度输入，交由同一桥接以50Hz发送；具体消息/话题命名在实施中确定，并明确是新增接口，不将其写成现有可调用功能。

连续通道至少携带新鲜度时间、旋转角速度、伸缩RPM和已有坐标/控制许可绑定，沿用现有单任务控制来源。输入过期、许可丢失、任务停止或固定动作交接时归零，不无限锁存最后的非零速度；下位机既有200ms JOG超时保持仍生效。

固定动作与连续JOG由桥接统一仲裁：停止JOG → 交接固定动作 → 等待对应完成 → 用新视觉指令恢复。按需利用新鲜空闲反馈完成协议交接，不新增视觉停稳复核。必须清除抓取前的JOG缓存，防止固定动作结束后旧速度续跑。

粗加工、暂存使用的定时升降JOG和固定动作完成语义需要回归保持；不将连续跟随当作一次长达整件等待时间的定时动作，不因持续等目标触发通用机构动作执行超时。

### 9.3 等待与故障的区别

| 情况 | 行为 |
|---|---|
| 初始一次扫描后无目标 | 当前地点全零持续等待，不重扫、不返回 |
| 正常图像但没有可靠圆心 | 底盘与机构停止，继续采集观测，等待可靠几何条件 |
| 底盘锁定后所需颜色尚未出现 | 工作位全零持续等待 |
| 跟随目标短暂丢失 | 两轴立即零速，允许新帧直接恢复 |
| 跟随目标持续丢失 | 回工作位一次，然后全零持续等当前颜色 |
| 固定动作拒绝、完成未知/超时 | 停止并如实报错，不重发抓取 |
| 通信异常、图像断流/过期、下位机故障 | 停止相关输出，按既有故障机制处理 |
| 人工停止、取消、网页失联 | 停止底盘和机构控制，不自动收纳/返程/续跑 |

“持续等待”必须保持任务状态、控制许可、状态反馈及可停止能力，不能用阻塞循环占住执行器。正式宿主、mission或网页外层若有原料找料总超时，需要一并核对并取消该业务上限；保留反馈有效期、图像断流检测、运动执行和固定动作的正常故障超时。

## 10. 配置迁移指导

以下为计划分组，不是当前YAML已支持字段；参数通过现有YAML体系承载，不引入新配置工具。

| 分组 | 内容 |
|---|---|
| `arm` | 工作位、抓取、收纳固定动作号；沿用现有电控配置核对，不臆造新动作号 |
| `vision` | 共用物料配置、原图标定点、图像有效期、相机启动/断流时限 |
| `initial_search` | 正vx100mm、负vx200mm、每段停车1秒、扫描速度与里程到位容差 |
| `initial_follow` | 初始可见物料慢速底盘跟随PID及平移上限 |
| `circle_estimation` | 三点退化判断、静止轨迹采样与分布要求；不设置失败离站的总时限 |
| `circle_servo` | 圆心粗定位像素容差、慢速底盘PID及速度上限、到位确认 |
| `gantry_servo` | 横向旋转PID、纵向伸缩PID、rad/s与RPM输出上限 |
| `target_loss` | 多久丢失后回工作位；回位后无等待总时限 |
| `grasp_gate` | 中心容差、旋转小输出阈值、伸缩小输出阈值、固定4帧 |
| `xy_return` | 本批P0二维返回PID、限速、到位容差和停车确认 |
| `execution` | 控制频率、数据新鲜度、固定动作请求与完成时限、已有许可时限 |

删除或迁移旧原料 `reacquire_frames=3`、逐件 `item_timeout_s`、临时颜色锁定及以底盘实际速度为抓取门槛的配置，避免保留旧字段却悄悄改变含义。正常图像中的缺目标不能被旧 `target_missing_timeout` 转成错误退出。

正式未标定值按仓库已有要求显式保持未就绪；网页沿用可编辑保存的低速调试初值，清楚标注待现场标定。伸缩RPM、旋转rad/s的数值不能复制底盘m/s上限。100/200mm、1秒、4帧按本次确认值实施。

## 11. 实施顺序

1. 扩展原料纯控制核心，分开底盘速度、连续机构速度和固定动作请求；实现新状态流和无限等待语义。
2. 实现同帧三点/静止轨迹圆心估计，测试相机运动后样本清空、粗对准期间新中心更新和本批只定位一次。
3. 在原串口桥接中接入连续伸缩/旋转、停止及固定动作交接，保持定时升降接口兼容；用伪串口验证字节和时序。
4. 在公共视觉宿主接入原料新核心、新帧边界、机构跟随时持续识别，以及收纳后返程结果契约；核对mission没有旧找料业务超时。
5. 同步迁移原料正式配置和8086原料选项；真实发送工作位/收纳/回工作位，只有抓取用1秒替代，更新页面运动提示和独立参数表。
6. 使用真实ROS节点、HTTP、伪串口及明确的软件视觉场景覆盖两批、等待恢复和停止；回归粗加工、暂存的正式与网页流程。
7. 现场低速验证图像方向、底盘扫描距离、相机随机构运动的反馈、圆心粗定位和两轴增益，再验证4帧触发、抓取程序、工作位恢复、收纳后返程。

## 12. 验收清单

| 场景 | 必须行为 |
|---|---|
| 开始和第二批重入 | 工作位前记录新P0；清空前批中心、轨迹、搜索进度、PID和完成记录 |
| 初始三色同帧可见 | 用有效中心求圆，慢速底盘粗对准，不发抓取 |
| 初始只见一两个颜色 | 允许慢速跟随获得视野；补充拟合时先全轴停车 |
| 扫描无物料 | 正vx100mm停1秒，再负vx200mm停1秒；按里程闭环，到末端一直等 |
| 扫描途中物料出现 | 取消剩余扫描，立即转初始找视野流程 |
| 三点近共线/轨迹不足 | 不输出假中心，不因找料时限收纳离站，保持可停止的等待 |
| 跨帧轨迹期间相机移动 | 清空样本，不将不同视角点混拟合 |
| 底盘粗对准 | 使用当前有效圆心；中心失效即停；最终误差容差可较宽 |
| 转盘定位完成 | 不再用底盘跟随物料，不再拟合已抓走后残余物料 |
| 当前颜色缺失，其他颜色可见 | 全轴保持零速等待，不临时跟随其他颜色 |
| 物料偏左/偏上 | 分别给正旋转角速度/正伸缩RPM；两轴可同时控制 |
| 物料随相机保持像素稳定但机构仍明显运动 | 两轴输出不小，不触发抓取 |
| 连续4张新帧误差及两轴输出都小 | 第4张产生停止和抓取请求；不附加视觉停车复核 |
| 重复帧、任一条件不达标、目标丢失 | 不凑够4帧，不用强制零速伪造达标 |
| 目标短暂丢失后重现 | 立即停轴，一张有效新帧恢复，无旧三帧门槛 |
| 目标长期丢失 | 实际回工作位一次，之后一直等待，不重复回位、不挪底盘 |
| 固定动作执行及结束 | 不跟随动作中图像；完成后只接受新姿态帧，无旧JOG续跑 |
| 正式每件完成 | 抓取程序完成且已回工作位才推进，严格顺序，不假称抓实验证 |
| 网页每件完成 | 全零1秒替代抓取，再实际回工作位；物料仍在画面可继续测试 |
| 三件结束 | 先收纳并确认完成，再返P0；返程完成才交回调度 |
| 缺目标长时间等待 | 不触发业务总超时；健康监控、状态推送和人工停止仍有效 |
| 取消、失联、故障 | 底盘与机构均停；不自动返程、不重发未知抓取、不自动续跑 |
| 公共模块回归 | 粗加工、暂存的定时升降、固定动作及网页规则不受改变 |

实施交付应另更新本计划的完成状态、对应配置和使用说明，并写明软件场景、静态真实模型及实车验证各自的范围；不能把旧版底盘跟随的测试成绩用于替代本版机构视觉闭环验收。

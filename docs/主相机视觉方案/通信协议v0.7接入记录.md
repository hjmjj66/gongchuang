# 通信协议 v0.7 接入记录

依据：[通信协议（最新）](../../通信协议（最新）.md)，版本v0.7，2026-11-15。

## 字段与控制适配

- `0x82 STATUS` 保持24字节：offset 8/12按小端int32解析 `fb_pulses/ud_pulses`，offset 21解析 `pos_flags`；yaw仍为offset 16的float。
- `/C/status` 使用int32脉冲和uint8位置标志。只改接口源文件并通过colcon重新生成，不保留容易误用的毫米别名。
- 前后位置有效位bit0决定能否构建机构位置样本；bit1为上下有效，bit2为已标定。粗加工前后位置闭环不依赖UD有效或bit2，不新增HOME前置。
- 粗加工放置前保存实际脉冲读数，取回直接以目标与当前的脉冲差驱动PID；机构初值预定位与保存同样使用脉冲。位置无效时不能记录、保存或按位置返回，网页分别显示各轴无效状态。
- 原料/暂存的图像误差PID仍按像素输入，JOG仍输出rad/s和RPM。底盘里程、连续yaw、速度和收纳后camera_car_offset的毫米含义不变。
- 机构yaw按新协议为单圈绝对角。用户确认机构不会转一圈，保留有限行程内的直接角差，不引入多圈展开或最短路径策略。
- v0.6固定动作不强制先HOME，ACK result=5表示位置反馈无效。原实现已无强制HOME前置，动作号与受理/完成交接保持现有行为。

## 参数与已有点位

用户确认伸出时前后脉冲增大；无需增加丝杆导程或长度标定，同一脉冲口径记录和返回即可。`length_tolerance_mm` 改为 `length_tolerance_pulses`，`length_pid`、`length_kp` 输入为脉冲误差、输出仍为RPM。保留现有数值作为新的脉冲域调试初值和现有速度限幅，未声称与旧毫米参数有换算关系；实际增益和容差可按响应调整。

`gantry_presets.positions` 使用 `{fb_pulses: 有符号整数, yaw_rad: rad}`，校验int32范围。旧毫米点位不可直接改名使用；仓库粗加工/暂存的四组初值目前均为null，没有已保存点位需要转换，未设初值时继续原有视觉流程。

## 构建与验证

已从源头构建agv_interfaces、agv_planning、agv_cboard、agv_mission、agv_perception。重启现有桥接、视觉节点和8086进程并刷新网页后使用新接口。旧固件与新固件STATUS长度相同，协议不提供版本协商，应使用v0.7配套固件。

验证覆盖协议官方示例及CRC、int32正负边界和偏移、位置位判定、粗加工记录/返回、初值保存/预定位、原料与暂存回归、网页脉冲显示。ROS/HTTP/伪串口集成测试仅使用软件对端，不连接真实车辆、串口或相机；软件通过不替代实车PID响应和取放验收。

验证结果：五个相关包构建成功；通信核心46项、视觉与控制119项、网页工具核心40项通过，前端交互测试通过。ROS/伪串口桥接6项、正式粗加工5项、HTTP/ROS机构初值保存与预定位1项全部通过。后者覆盖四组点位保存、正式配置同步、粗加工与暂存两次访问的预定位；粗加工集成包括仅bit0有效的两批完整流程，以及bit0无效时不记录、不放置并停止。需要真实BPU/硬件的测试未启用。

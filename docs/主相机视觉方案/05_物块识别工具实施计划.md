## 1. 本轮明确的方案

工具有两层选择，分别写入 YAML，不混用编号含义：

| 参数 | 值 | 含义 |
|---|---|---|
| `material_backend` | 1 | 传统 HSV 六色分割，输出轮廓质心 |
| `material_backend` | 2 | YOLO 模型识别，继续读取 `material_model` |
| `material_model` | 1 | 顶面模型：可靠霍夫圆心优先，否则取原检测框中心 |
| `material_model` | 2 | 整体模型：直接取原检测框中心，不再找圆 |

用户本轮已确认：保留 HSV，两参数独立选择；增加与圆环工具相似的网页预览，同时保留图片调试与核心 Python 调用接口。

此前仍然有效的确认：六色编号为红1、黄2、蓝3、绿4、黑5、浅蓝6；物块近似圆台形柱体，顶面平滑无孔；HSV 使用 `zuixin.py` 初始阈值，后续由另外的工具标定；跨颜色掩膜高度重叠时标记歧义，不猜颜色；输出当前帧全部候选，由区域程序选择目标。

本轮默认 `material_backend=2`、`material_model=1`。配置在启动时读取，修改后重启；不做网页热切模型，不逐帧切换路径，不自动同时运行两个模型。

顶面框中心是本方案允许的定位估计，不再一律拒绝。整体框中心同样是可输出的定位参考，但不是顶面圆心。所有输出保留实际路径与中心来源，区域程序据此使用对应准心。

参数说明：

- `top.refine_circle=false` 是顶面路径的对比开关，不改变 `material_model=1` 的含义；`top.allow_bbox_fallback` 仅在开启圆检测且失败时生效。
- 整体路径永远取原框中心，不读取顶面找圆开关；不因其半径配置有问题阻止整体路径启动。
- 初版使用公共模型置信度/NMS 门槛，两个模型分别做验证；不是把示例中的高置信度当成精度保证。
- 保持与现有圆环工具的候选阈值约定一致：保留 `confidence > confidence_threshold`，恰好等于门槛也排除。官方运行时可能保留等值项，物料适配后再做此一次最终过滤；文档和测试按该规则写清。
- `max_contour_area_ratio=0.0` 表示关闭最大面积限制，`save_every_n_frames=0` 表示不抽样写相机图片。
- HSV 数组每 6 个数为 `H下,S下,V下,H上,S上,V上`，同色多区间先 OR。使用扁平数组适配 ROS2 参数类型。
- H 为 OpenCV 常规 8 位转换的 0～179，S/V 为 0～255；原代码 H 上限 180 改为 179，不改变该转换的实际匹配像素。黑色等其他数值保持来源，不擅自扩大范围。
- 最小面积 100 沿用低分辨率旧程序起点，在 720p 不代表已合适；霍夫比例、重叠门槛及有效期也需要实拍调试。
- 相机稳定路径来自历史 C100 检查值；网络 640×640 输入由运行时处理，相机仍采集原始 1280×720，不将模型输入尺寸当成输出坐标空间。

### 4.2 校验和加载范围

`parse_material_config(parameters)` 统一供网页和 ROS 使用，配置错误说明字段和原因：

1. 严格检查两个选择参数为整数 1/2，目标颜色 0～6；布尔值不能冒充编号。
2. 仅校验启用后端所需内容。HSV 不要求模型/推理运行时存在；整体路径不要求顶面模型、几何参数有效；顶面路径不要求整体模型存在。
3. 几何调试不要求 BPU 模型存在，只校验手动框、颜色和几何参数。
4. ROS 中 `search_roi`、`manual_roi` 和空 HSV 范围显式声明整数数组类型，不让 `[]` 推断成错误类型。
5. 模型路径、类别和运行时在打开相机前核对；仅加载选中的一个模型一次。不在每帧访问模型文件，不静默下载权重。
6. 按需检查核大小正奇数、合法半径比例、有限数值、面积/频率/时间和置信度/NMS 范围。
7. 当前 HSV 六色范围均提供初值。用户后续清空某色范围时，该色标为未配置，不能伪装成正常漏检；全色模式报告缺失颜色，并说明无法完整检查其颜色冲突。
8. 所有模式启动时打印选择结果、实际模型路径和标签映射。模型切换需要重启，不在网页中自行改写 YAML。

## 5. 核心接口与坐标

### 5.1 调用方式

拟提供 `MaterialDetector`，不依赖 ROS、相机或 HTTP：

```python
config = parse_material_config(parameters)
model = load_material_model(config) if config.material_backend == 2 else None
detector = MaterialDetector(config, model=model)

result = detector.detect(frame_bgr, frame_seq=12, stamp=read_time_s,
                         target_color_id=None, search_roi=None)

# 已后处理的框输入，用于组合逻辑验证或上层共享模型结果。
result = detector.detect_boxes(frame_bgr, detections, frame_seq=12,
                               stamp=read_time_s, target_color_id=None)

# 显式手动顶面框，结果 identity_source=manual。
result = detector.detect_roi(frame_bgr, bbox_xyxy, manual_color_id=3,
                             frame_seq=12, stamp=read_time_s)
```

`frame_bgr` 是非空 `uint8 H×W×3` 原图，不带预览标注。图像、外部框和配置仅在各自入口校验，内部使用已规范类型；不反复做相同防御检查。

`detect` 使用初始化配置选择路径；`detect_boxes` 仅适用于 YOLO 后端，框已经是传入图像的原图坐标，不暗中裁剪或重做模型 NMS。手动入口显式走顶面几何，颜色由调用方提供，不说成模型识别结果。

模型适配对象提供 `infer(image_bgr)`，返回 `MaterialModelDetection(color_id, raw_label, confidence, bbox_xyxy)`。错误编号、非有限置信度、非正尺寸框等在适配边界拒绝；业务内部不再猜类型。

### 5.2 坐标还原的责任

- 像素原点为主相机原图左上，u 向右、v 向下；框为浮点 `[x1,y1,x2,y2]`，裁剪时右/下边界为排他边界。
- `search_roi=None` 是整图，非空为原图整数 `[x1,y1,x2,y2]`，必须位于图内且尺寸为正。
- 正式入口先取得工作 ROI，模型对工作 ROI 做 letterbox；适配层撤销网络缩放/补边，组合层只加工作 ROI 偏移。
- 顶面几何在原工作图的局部 ROI 内进行；局部圆心加顶面 ROI 偏移，再加工作 ROI 偏移，保留浮点精度。
- `detect_boxes`、`detect_roi` 直接使用所传整图坐标，不能又叠加调试节点的工作 ROI。
- 框中心必须由原检测框算出，不使用扩边 ROI 中心或裁剪后框中心；特别是触边裁剪不能悄悄改变定位点。
- 绘图在图像副本上进行，网页缩小预览时结果坐标仍为原图像素；不上报米制位置或机械臂坐标。

### 5.3 目标与实例

返回当前帧全部合格候选，允许同色多物块，不沿用圆环“每类只取最高分一个”。没有目标时返回空列表，不补六个虚拟物块，也不继承上一帧坐标。

`target_color_id=None` 返回所有颜色，1～6 只返回指定色。HSV 的跨颜色冲突检查先于过滤；YOLO 直接按模型分类过滤，不能要求 HSV 二次通过才接受模型。

候选列表按颜色编号和框左上坐标确定顺序，仅用于稳定展示，不作为跨帧跟踪身份。选择抓哪个、抓取顺序、原料转盘是否停稳都由区域程序负责。

## 6. 顶面模型路径的具体实现

### 6.1 检测框处理

1. 使用六类顶面模型，取得原工作图坐标的框、分数和标签。
2. 最终过滤置信度不严格大于门槛的项，保留全部合法实例。
3. 保存 `bbox_center_px=((x1+x2)/2,(y1+y2)/2)`。
4. 原框触及工作 ROI/原图边界时标记 `TRUNCATED`，保留框和估计中心供调试，但最终 `valid=false`；不把被裁断的顶面框当完整顶面定位。
5. 若 `top.refine_circle=false`，完整框直接返回中心，状态 `BBOX_ONLY`、来源 `bbox`、`geometry_reason=DISABLED`。
6. 否则以原框宽高的比例扩边，向外取整并限制在工作图内。仅扩边被裁剪不说明原物块已截断。
7. ROI 太小/完全出界时记录原因，按允许兜底与否处理，不用扩大更多背景来凑圆。

### 6.2 局部霍夫圆

拟新增 `TopCircleLocator.detect(roi_bgr, local_box)`：

1. 原始 ROI 转灰度、高斯模糊；默认不做 HSV、暗色反阈值或地面环孔提取。
2. 使用标准 `cv2.HOUGH_GRADIENT`，半径范围由未扩边原顶面框短边 `s` 乘配置比例得出。
3. 以原框中心为参考，限制圆心偏移；排除圆周明显被处理 ROI 截断的候选。
4. 用模糊灰度的 Canny 边缘检查圆周支持，均匀采样 72 个角度，允许配置的径向误差。越界角度算缺失支持，不从分母中删掉。
5. `param1` 为霍夫内部 Canny 高阈值，本地支持图使用该值及其一半作为高/低阈值；`param2` 是累加器门槛，不称为圆心概率。
6. 圆心和半径都非常接近的重复候选先去重。物块无孔，不增加同心环数量加分，不融合顶面和底部多半径中心。
7. 通过尺寸、偏移、支持门槛的候选按 `E=distance_to_box_center/s + abs(2*r/s-1) + (1-edge_support)` 排序，E 小者优先。
8. 两个不同候选的 E 差小于等于 `ambiguity_margin` 时返回 `AMBIGUOUS_CIRCLES`，不取霍夫输出的第一个或最大的圆。
9. 返回局部圆心、真实估计半径、支持比例、候选及拒绝原因，再由组合层还原坐标。

找圆成功也不必然比框中心准。此筛选用于排除明显错误候选，仍须在真实图片中看圆是否落在顶面；遇到显著椭圆形投影，先按找圆失败处理，不本轮另加椭圆算法。

首版只在物块局部 ROI 找圆，保留阶段耗时，不做全图霍夫。圆环工具曾出现大量候选导致阻塞，本工具不照搬其密集同心圆参数；若实际顶面 ROI 同样过慢，先依据耗时修订半径/候选搜索范围，再讨论候选图缩小或分阶段流水线，不能先延长有效期掩盖问题。

### 6.3 圆心与框中心的最终选择

| 条件 | 最终中心 | 状态与来源 |
|---|---|---|
| 原框完整、可靠圆成功 | 原图霍夫圆心 | `OK`，`circle` |
| 原框完整、找圆失败且允许兜底 | 原检测框中心 | `BBOX_ONLY`，`bbox`，保留失败原因 |
| 原框完整、主动关闭找圆 | 原检测框中心 | `BBOX_ONLY`，`bbox`，原因 `DISABLED` |
| 找圆失败且关闭兜底 | 无最终中心 | `GEOMETRY_FAILED`，`valid=false` |
| 原框截断/超出工作图 | 不提供有效最终中心 | `TRUNCATED` / `BOX_OUTSIDE_IMAGE` |

`bbox_center_px` 与 `circle_center_px` 分开保存。找圆失败时 `circle_center_px=null`，即使框中心可用也不伪装几何成功。不能沿用旧帧圆心或为顶面模型自动调用整体模型补救。

## 7. 整体模型路径的具体实现

1. 只加载整体六类模型，取得完整物块框与颜色。
2. 采用与顶面相同的框、分数和边界入口规则，保留同色多个候选。
3. 对完整框直接计算原框中心，输出 `center_source=bbox`、`status=BBOX_ONLY`、`valid=true`。
4. `circle_center_px=null`、`radius_px=null`，`geometry_reason=NOT_APPLICABLE`；不是“找圆失败”，而是本路径没有找圆。
5. 不调用顶面几何，不做框内 HSV 质心，不加固定的“向上/向下若干像素”修正。
6. 原框截断或无当前图像时不给有效中心，不因框中心容易算就跳过状态规则。

整体框中心与顶面中心在当前样本中相差约 21～38 px，方向随位置改变。该数字来自同一图片的标注框对比，不是模型误差、毫米误差或抓取失败证据。整体路径需要独立的实车对准准心，但准心和运动参数属于以后区域程序，本工具不加入抓放补偿矩阵。

## 8. HSV 路径保留的完整行为

1. 只转换工作 ROI 一次 `BGR→HSV`。
2. 按六色多区间 `inRange`，同色用 OR 合并；不因为红色有两段就重复出两个物块。
3. 仅对二值掩膜做配置的开/闭运算；默认 0 次，不直接腐蚀 HSV 三通道图。
4. 外轮廓使用 `RETR_EXTERNAL`、`CHAIN_APPROX_SIMPLE`，按面积过滤，使用图像矩计算浮点质心；零面积候选丢弃，不用框中心补成质心。
5. 保留全部合格轮廓、框和面积；触及工作 ROI 边界时标记截断。
6. 对不同颜色且框相交的候选，比较轮廓内部实际颜色掩膜前景；重叠比例为共同前景数除以两个前景数较小者。
7. 重叠比例达到 `hsv.color_overlap_threshold` 时双方都标记 `COLOR_AMBIGUOUS`、`valid=false`，保留冲突编号及比例；不按颜色列表、面积或编号选赢家。
8. 最后才过滤指定颜色，避免只检测蓝色绕过蓝/浅蓝重叠。
9. 返回 `center_source=contour_centroid`，不把轮廓质心称作真实顶面圆心，半径为空。

HSV 可以在没有模型、没有 BPU 运行时的机器上处理图片；YOLO 路径不加载 HSV 模块中的标定数据作为额外分类门槛。阈值重叠检查不能发现全部错色，仍需要后续标定。

## 9. 模型运行时接入

拟用 `load_material_model(config)` 返回 `X5MaterialModel`：

- 读取选中 `top` 或 `whole` 的 `model_path`、`classes_path`，校验标签文件的六个实际标签与对应 `class_labels` 顺序一致，不从模型文件名猜标签文件位置。
- 显式传入本地模型路径，不走官方 CLI 默认权重下载流程。
- 初始化 `YoloDetect(YoloDetectConfig(model_path=..., platform=resolve_platform('x5'), classes_num=6, resize_type=1, score_thres=..., nms_thres=...))`。
- 模型加载一次，`infer` 只调用 `predict`，把数组转换为规范检测框和普通数值。
- 由官方运行时完成 BGR→letterbox→NV12→BPU→DFL→一次类内 NMS→网络变换逆映射；物料工具不再进行第二次 NMS，也不重复缩放已还原的框。
- 项目环境可能已经载入圆环部署目录中同名 `samples` / `utils` 模块。实际适配时核对已导入运行库来源和版本；同进程未来整合使用同一份经过确认的运行库，不通过反复改 `sys.path` 假装热换运行时。
- 缺模型报 `MODEL_NOT_CONFIGURED` / `MODEL_LOAD_FAILED`，运行时缺失或协议不匹配报 `MODEL_LOAD_FAILED` 并保留原始原因，执行推理失败报 `MODEL_INFERENCE_FAILED`。
- 任何失败都不自动切换 HSV、另一模型或测试框；没有 X5 依赖时仍可验证纯算法图片入口。

不修改 `/root/material_deploy_v1` 内的编译产物、官方运行库、测试标注或既有结果图。新的测试结果写 `/tmp/material_debug...` 或用户配置的输出目录，不覆盖原部署证据。

## 10. 输出结构和有效性

### 10.1 帧结果 `MaterialFrameResult`

包含 `frame_seq`、`stamp`、`image_size`、`backend`（hsv/yolo/manual）、`model_kind`（upper_top/whole/null）、`search_roi_xyxy`、`processing_ms`、`stages_ms`、`status`、`observations` 和本地 `debug`。

- `stages_ms` 区分 `yolo`、`geometry`、`hsv` 等实际执行阶段，不虚构未执行阶段的耗时。
- 时间由采集方传入；相机时间是软件读帧完成时间，不是曝光时间或推理完成时间。
- `to_dict()` 只返回合法 JSON 类型，不包含图像数组、NaN 或无穷值。
- 帧级 `OK` 表示候选都可用（可能包含框中心）；`PARTIAL` 表示有效与无效候选并存；`NO_VALID_DETECTION` 表示有候选但均无效；`NO_DETECTION` 表示没有候选。
- 帧级状态不表示六色全部出现、不表示已对准或夹取成功。

### 10.2 候选结果 `MaterialObservation`

| 字段 | 约定 |
|---|---|
| `color_id`、`color_name` | 比赛编号与规范颜色名 |
| `raw_label`、`identity_source` | 真实模型标签和 `yolo/hsv/manual`，手动框不冒充自动识别 |
| `valid`、`status` | 当前观测是否可用于后续对准及具体状态 |
| `bbox_xyxy`、`bbox_center_px` | 原框及其浮点中心；只作调试的无效项仍可保留 |
| `circle_center_px`、`radius_px` | 仅真实霍夫定位成功时存在 |
| `center_px`、`center_source` | 最终采用的原图中心，来源 `circle/bbox/contour_centroid`；无效时中心为空 |
| `yolo_confidence` | 模型分数，HSV/手动为空，不能解释为定位精度 |
| `roi_xyxy` | 实际顶面处理区域，不用它计算兜底中心 |
| `geometry_reason`、`circle_support` | 无圆、弱边缘、歧义、主动关闭、不适用等原因及边缘支持 |
| `contour_area_px2` | HSV 轮廓面积，其他路径为空 |
| `conflicting_colors`、`color_overlap_ratio` | HSV 冲突证据 |

统一规定 `valid=false` 时 `center_px=null`、`center_source=null`，避免区域程序误用；诊断位置保留在 `bbox_center_px`、`circle_center_px` 或本地调试轮廓数据中。允许框中心的情况下 `valid=true` 不等于“几何精定位成功”，需要看来源。

`BBOX_ONLY` 是可接受的估计状态，不显示成错误告警；`COLOR_AMBIGUOUS`、`TRUNCATED` 等则明确无效。不增加语义重复的多层有效性布尔值。

## 11. ROS 图片与相机调试入口

`material_debug_node` 只包装同一核心，不另写一套检测算法。

- `debug_mode=detect`：按 YAML 两参数选择正式路径；`input_image` 非空读取一次静态图，不打开相机。
- `debug_mode=geometry_only`：只接受静态图、手动顶面 ROI 和颜色编号，输出 `identity_source=manual`；仍按配置验证霍夫/框中心兜底行为。
- 图片默认不开桌面窗口；`show_preview=true` 时需要桌面环境，按 q/Esc 退出。
- `output_dir` 非空时静态图保存 `result.json`、标注图；HSV 另存六色掩膜，顶面几何另存局部灰度、边缘及候选图。
- 相机输入复用 `CameraStream`，只处理新帧号，不维护积压队列；没有新帧不重复检测。
- 检测前和检测后均按单调接收时间检查 `max_frame_age_s`，超时结果不能作为新有效观测。状态分别为 `NO_FRAME`、`STALE_FRAME`、`STALE_RESULT`。
- ROS 相机首次等不到图像时按启动等待超时退出；正常结束释放相机和文件。
- 相机输出可追加 `results.jsonl`，仅按 `save_every_n_frames` 抽样保存图片，默认关闭写图。
- 不新增业务消息、颜色话题或抓取服务；正式区域程序直接导入核心。

## 12. 网页调试的详细安排

### 12.1 启动和配置

沿用圆环工具 `start.sh + Python 标准库 HTTP + 原生 JS/CSS` 的流程，建议默认端口 8085，与圆环 8084 区分。网页与 ROS 共用同一份 `material.yaml` 和配置转换函数，不依赖 ROS 环境、不要求先 colcon 构建。

`start.sh` 设置项目源码 PYTHONPATH、限制 BLAS 线程后启动服务；入口可接受 `--config`、`--image`、`--device`、`--port`、`--preview-width`。算法和模型只读 YAML，不另加一套 1/2 模式的命令行含义。

网页显示当前后端、模型路径及模型类别，页面只读观察，不写参数、不发底盘或机械臂命令。切换两条路径修改 YAML 并重启，后端改变后清空旧结果。

### 12.2 图像、候选和性能

- 显示六色编号、标签、置信度、状态和所有实例。卡片数量按候选动态生成，不能复制圆环固定三个工位卡片。
- 框中心 B 用青色、霍夫圆心 C 用洋红色，最终中心 F 用不同形状强调；重合时使用空心圈/十字区分，不只靠颜色。
- 卡片分别列 B/C/F 的原图像素坐标、中心来源、B 到 C 距离、几何原因；整体路径 C 显示“不适用”，顶面找圆失败显示“未取得”。
- HSV 显示轮廓质心与冲突状态，模型置信度栏为空；不伪造模型分数。
- 分别统计实际采集 FPS、实际完成识别 FPS、浏览器实际展示 FPS；初始不足样本为 0，静态图为“—”。
- 显示原图尺寸、帧号、结果年龄、模型与几何分段耗时；不把 `1000/耗时` 当成流水线 FPS。
- `/api/frame` 一次返回同一帧的图像与结果，静态图仅检测一次；网页缩放不修改结果坐标。
- 相机断流、结果过期、推理异常时清除当前有效中心；可展示仍新鲜的无标注原图。浏览器连接异常也清空坐标，不继续显示最后一次有效值。

### 12.3 处理结构和性能范围

首版采用一个模型实例和一个串行检测任务，采集线程持续更新最新帧，HTTP 请求不触发模型推理；预览编码/HTTP 读取与检测分开，最多保留最新待显示结果，慢浏览器不阻塞算法。

网页与 ROS 核心算法相同，但服务调度和显示可能不同，性能分别记录。已有圆环使用跨进程几何与共享内存是其实际性能优化结果；物料先跑局部霍夫和整体无几何路径，未经测速不照搬整套多进程实现，不承诺相同 FPS。

如实测表明顶面霍夫限制频率，先检查局部尺寸和候选数量，并对比 `top.refine_circle=false`；再决定是否需要已有流水线方式。不能以放宽结果有效期换取看似正常的显示。

## 13. 实施顺序与每步完成条件

### 第一步：配置、结果和纯框路径

完成配置解析、两层选择、六色映射、结果结构、`detect_boxes`、整体框中心、顶面关闭细化时的框中心及边界规则。

完成条件：规范测试框可验证 1/2 路径；整体不调用几何；同色多个框全保留；原框中心不受扩边影响；缺模型不阻止 HSV/手动入口。

### 第二步：真实两模型接入

沿用部署运行时实现适配，每次仅加载所选模型；先处理原始 `check.jpg` 与 `check_black_blues.jpg`，分别记录模型标签、框、置信度和时延。

完成条件：两个模型都在 X5 上有实际推理结果，六色映射准确、letterbox 坐标还原正确，不把已有标注框/可视化图当成新推理输出。

### 第三步：顶面霍夫与兜底

完成局部灰度、霍夫、可靠性检查、重复候选去重、歧义拒绝、圆心坐标还原及框中心兜底；输出 B/C/F 三者供直接对比。

完成条件：真实/合成顶面可找到合理圆；底边和错半径不轻易获选；找圆失败仍按配置输出原框中心，圆心字段保持为空；关闭兜底时正确返回无效。

### 第四步：保留的 HSV 链路

完成六色掩膜、质心、多实例、截断和颜色歧义。测试初值的真实重叠，且指定色查询不能绕过冲突。

完成条件：没有 BPU 也可跑 HSV 图片；六色编号正确；歧义候选无有效最终中心；全色结果不被“只取最大色块”截断。

### 第五步：图片、ROS 和网页调试

增加共享绘图、ROS 节点、YAML、launch、网页启动与 API，先静态图后相机。页面与 ROS 都调用相同核心，不复制检测算法。

完成条件：三条实际路径均可显示；同色多候选卡片完整；B/C/F 来源清楚；图像和结果同帧；无新鲜结果时清空中心；停止后资源释放。

### 第六步：软件回归与实拍记录

运行算法、服务与前端检查及现有圆环回归；在板端分别记录顶面细化、顶面仅框、整体仅框及 HSV 的效果和时延。

完成条件：有明确的软件通过记录和真实样本结果；说明哪些颜色、区域和姿态尚未验证。不把模型/软件链路通过写成夹取或码垛已经成功。

| 边界与坐标 | 原图、工作 ROI、顶面 ROI 偏移正确；边界截断不输出有效中心；不重复撤销 letterbox |
| HSV | 红色两段 OR、六色可控样本、实际蓝/浅蓝冲突、相邻物块不因框相交误判、噪点和退化轮廓 |
| 结果 | 空帧不继承坐标；无效最终中心为空；框中心兜底标估计；可 JSON 序列化；原图不被修改 |
| 手动调试 | 手动身份不冒充 YOLO；图片不打开相机；缺失图像明确失败 |
| 网页/API | 图像与结果同帧；多实例动态卡片；C 不适用/失败有区别；断流、过期、断网清中心；静态图不统计实时 FPS |
| 调度 | 一帧最多检测一次；请求不重复推理；慢显示不要求算法积压帧；退出释放本次相机/线程/文件 |
| X5 真实模型 | 顶面和整体都跑原始图片，覆盖六色；保存数值结果，不从 JPEG 上读字做数值回归 |
| 既有回归 | 原扫码、圆环核心及网页既有测试通过，不改变其类别与模型配置 |

现有 `results/*.jpg` 只用于人工对照，不提供精确数值基线。首次真实板端推理需记录 JSON；标注用于人工中心和检测框覆盖比较，不要求模型框与人工框逐像素相同，也不编造未测的 mAP。

# 粗加工区放料、取回与离站精校准实现规格

日期：2026-10-20。状态：待实现规格。本文按本次会话最新决定整理，可供其他会话直接据此编码；遇到旧总体规划分组、旧接口或本目录较早措辞冲突时，以本文和公共约定的最新补充为准。

## 1. 固定需求与实现边界

- 一个 `work_vision_node` 独占主相机，内部有原料、粗加工、暂存三个可独立调用的任务模块。本文件对应 `coarse_task`，不另开相机。
- 固定 USB 主相机近似垂直俯视，全部检测使用 1280×720。默认采用原图像素坐标，原点左上，u向右、v向下。
- 粗加工工位在中心观察姿态下从左到右编号1、2、3；本版不用OCR识别数字。
- 空工位用灰度霍夫圆定位；取回用指定颜色HSV掩膜轮廓质心；HSV具体阈值由外部YAML提供，不实现阈值标定工具。
- 视觉速度全部控制底盘，通过既有 `/C/controll` 发布 `ControlCommand`，不是机械臂速度。
- 每批先三个全部放完，再按本批颜色顺序三个全部取回入仓。
- 放或取对准后，底盘先停车，再向 `/C/arm_command` 发送一次1或0。0包含抓取、入仓和仓盘转位；1包含出仓、放置和仓盘转位。
- 板间通信当前不实现，动作完成反馈接口预留；不能用固定延时或“已发布命令”代替真实完成。
- 每项作业后先返回中心观察位附近，再获取下一目标。完成全部取回后，离站前必须用三个空圆环执行最终位置与朝向视觉精校准。
- 单目标调试可返回 `aligned`；完整区域只有六项动作完成、最后精校准成功并停车后才返回 `completed`。

公共基础见[公共视觉与伺服约定](00_公共视觉与伺服约定.md)，源码对照见[开源算法索引](README.md)。本文为待实现规格，不修改业务代码或扫码程序。

## 2. 任务输入、扫码数组与统一上下文

调度订阅 `/qr/result`，校验并保存一次本轮任务快照。区域执行中使用快照，不依赖每一步重新读到二维码。相同二维码重复发布不清空索引；新一轮显式重置。

输入语义：`run_id`、`task_id`、`batch`、三个颜色 `colors[3]`、三个位置 `positions[3]`。颜色编号红1、黄2、蓝3、绿4、黑5、浅蓝6。颜色与位置按同一个物料索引对应，索引从0开始，工位编号从1开始。

例：`156+123+516+231`：

| 批次 | colors | positions | 放置对应关系 | 取回顺序 |
|---|---|---|---|---|
| 1 | [1,5,6] | [1,2,3] | 红→1、黑→2、浅蓝→3 | 红、黑、浅蓝 |
| 2 | [5,1,6] | [2,3,1] | 黑→2、红→3、浅蓝→1 | 黑、红、浅蓝 |

检查数组长度、颜色编号、位置编号；本标准三工位流程要求三个颜色不同且位置为1、2、3的排列。校验失败报告原因，不擅自替换、补齐或重复位置执行。

上下文至少保存：

| 数据 | 用途 |
|---|---|
| 当前批次、phase、item_index、step_id | 区分六个动作及恢复位置 |
| `placement[color] -> position_id` | 已确认的本批放置对应关系 |
| 每步状态 `pending/running/completed/failed/unknown` | 动作结果不明时不重复执行 |
| station_id与观测关联 | 移动、出画后仍按明确条件维护身份 |
| 当前动作是否已发送、待等反馈 | 防止每帧重发0/1 |
| 中心观察位记录与局部移动状态 | 返回观察范围，而不是复用旧像素 |
| `reference_restored` | 最终精校准完成前始终为false |

## 3. 采放后自动转仓：动作契约

### 3.1 允许的设计

将车载仓盘转位封装进下位机每次采放程序，粗加工视觉端只发送0或1。公共指令另有2用于暂存第二批码垛，本区不发送2；其内部转仓同样由C板处理。转盘是车载物料仓，不是原料区比赛转盘。

- 0：在当前已对准目标处抓取 → 放入当前对接仓位 → 机构抬升避让 → 仓盘转到下一仓位 → 检查就位 → 返回本次完成。
- 1：从当前对接仓位取料 → 放到已对准目标 → 机构抬升避让 → 仓盘转到下一仓位 → 检查就位 → 返回本次完成。

转位发生在本物料采/放已完成、机构离开干涉范围后，不能收到0/1便立即先转仓。第三次也转位，目的是完整一圈后回到本组开始的对接仓位。

### 3.2 顺序能成立的前提

用户已确认三仓、同方向每次120°，每组第三次也转，且明确要求全部由C板自行实现。上位机不发送转仓指令、不配置转仓角度或方向、不维护转仓控制状态机，也不根据0/1次数虚拟计算实际仓位。下表只解释为什么顺序可行，不是上位机实现任务。

假设对接顺序S0→S1→S2→S0：

| 操作组 | 开始 | 依次操作仓位 | 三次完成后 |
|---|---|---|---|
| 原料采三件 | S0且仓空 | S0入第1件，S1入第2件，S2入第3件 | 对接S0，仓满 |
| 粗加工放三件 | S0且顺序已知 | S0出第1件，S1出第2件，S2出第3件 | 对接S0，仓空 |
| 粗加工取回三件 | S0且仓空 | S0入第1件，S1入第2件，S2入第3件 | 对接S0，仓满 |
| 暂存放三件 | S0且顺序已知 | S0出第1件，S1出第2件，S2出第3件 | 对接S0，仓空 |

因此每组严格完成三次、保持同一轮转顺序，就能按本批颜色顺序出入仓，无需每次额外指定仓位。工位位置顺序可以任意排列，不影响仓位的物料索引顺序。

C板负责上电仓盘参考、仓位次序和转位就位等内部处理。上位机只按本批颜色顺序发0/1并等待对应完整动作结果；C板异常或动作结果未知时，停止推进当前物料，不猜仓位补发命令。

### 3.3 失败与反馈

动作完成的含义是“采放完成、机构已避让、仓盘已转位并就位”。若抓取失败、出仓失败或转位失败，报告对应结果，不反馈成功。动作做到一半后结果未知，标记unknown并等待同步，禁止自动重发0/1导致重复抓放或多转一格。

接口预留阶段不实现机构控制；未来下位机/通信实现满足完整动作结果语义即可。上位机只在成功反馈后更新本物料进度；通信节点只转发采放请求，不额外触发转仓。转位状态是否单独反馈由电控决定，上位机不要求独立的转位完成接口。

## 4. 中心观察位与局部返回接口

### 4.1 先明确观察位

到达工位并完成作业朝向后，在机构固定观察姿态下看到三个空工位，建立1、2、3身份。记录中心观察位局部位置。首次进站可复用第9节三圆校准，完成后再记录观察位；该步骤由 `align_reference_on_entry` 控制。

保存 `visit_id/local_frame_id/reference_pose`、同一张有效新帧中的 `reference_station_uv[1..3]`、图像坐标配置及当时观察姿态。位置参考只在本次进站内使用，第二批入站重新建立；颜色/工位计划按批次保存，不延用上一批的图像坐标。

每次单工位精对准可能让其他工位出画。动作完成后，通过局部位置反馈返回观察位附近，目的是重新覆盖三个工位位置，不是要求被物料遮住的三个空环始终可见。

### 4.2 当前代码缺少的依赖

当前 `OdometryFeedback` 提供固定会话系 x/y、连续yaw、实际车体系速度和有效性；区域仍需实现局部参考捕获与返回逻辑，不能把新增反馈等同于已实现二维返回。

预留同一运动执行层中的 `capture_local_reference` 与 `return_to_local_reference` 能力。使用 `/C/odometry` 中一致会话的 x/y/yaw、时间戳和有效性，并绑定 `odom_session_id`；原累计反馈字段已移除。具体区域返回服务仍待实现。

返回执行期间，视觉任务不并行发底盘速度。返回执行器归零并报告到位后，视觉重新接手。不得固定时间反向运动、积分已下发速度或直接复用旧圆心像素来假定返回成功。

没有返回接口时，允许独立单目标检测、对准和一次指令输出调试；完整批次应明确报告 `LOCAL_RETURN_UNAVAILABLE`，不能模拟真实返回后继续比赛。

局部返回、最终校准profile、完整动作反馈、车道内允许纠偏范围等依赖在批次开始即检查。通过未来通信同步并确认 `work_area=coarse` 后才允许发0/1，避免0仍执行原料高处取料程序。区域同步契约见公共约定第7.3节。

## 5. 霍夫圆、编号与遮挡

### 5.1 检测流程

1280×720新帧 → 作业ROI → 灰度 → 高斯模糊 → 标准 `HOUGH_GRADIENT` → 半径与范围过滤 → 近圆心候选归并 → 工位结构验证 → 编号关联。

同心圆归并使用距离门限，不比较浮点圆心完全相等。不要求每个工位的全部评分环都被检测到。圆心组内使用中位数或受边缘支持约束的代表点；不同工位不得因链式近邻被合成一组。

首次三个空工位按u排序赋1、2、3。检查中心间距、近似共线、尺度与ROI；有多于三个候选时选择唯一满足工位布局的组合，否则报告歧义，不任取前三个。

圆候选保留浮点坐标和有符号误差，不能照搬 `uint16` 圆心相减导致负误差溢出。对候选圆周做边缘支持复核：在允许半径带附近按角度采样，记录受支持角段比例与分布；只有少量单侧弧、ROI边界截断或仅数字笔画支持的候选不能作为高质量中心。相关支持门限留YAML，先用实拍图确定，不默认必须检测全部评分环。

可借鉴江苏“粗定位再精定位”的流程，但统一保持720p与同一中心定义：首次在作业ROI获取候选，锁定后只在带足够圆周边距的局部ROI检测，最后停车复核可扩大ROI重新验证。局部ROI内坐标仍还原到原图；丢目标先归零，再回作业ROI重获，不能继续用预测点运动。缩小ROI是运算优化，不切换分辨率或偷偷换准心。

### 5.2 作业中的目标身份

移动到选定工位时持续关联本工位，其他工位可以出画；目标自身丢失或关联不明确时归零。不能将当前可见的剩余圆重新编号。

回到观察位后，已占用工位可能只见物料。结合已确认占用记录、物料颜色、仍可见空环及局部返回姿态建立完整布局关联。物料提供语义证据，不将其顶面圆心直接当作地面圆环中心。若仅剩一个空环且缺乏可靠位置信息，不能只凭它是“唯一圆”就确认身份。

放置目标必须使用当前可见的指定空圆环中心。首版不在环完全被遮住时根据预测坐标继续发速度。

### 5.3 返回观察位后怎样确认编号

首版采用“局部返回到位＋参考图像位置门限”的明确基线。只有当前局部坐标系、观察姿态与参考相同，返回位置/yaw偏差在已验证范围内，才可使用入站保存的工位像素作身份门限。`reference_match_radius_px` 需覆盖该返回误差及检测抖动，同时小于相邻工位参考间距的一半；无法同时满足时，说明当前返回精度不足，不能扩大门限直到身份混淆。

把当前新检测的空环与原工位作一对一匹配，要求位于对应门限内且无歧义；不以剩余候选数量重排。已占用位置可用预期颜色作语义复核，允许物料高度产生偏移，但不拿顶面坐标更新地面参考。旧工位像素只负责身份检查，伺服使用匹配后的当前实测圆心。

局部返回成功但像素门限仍冲突，报告 `STATION_ID_AMBIGUOUS`，重新恢复参考或请求上层恢复；不自动无限放宽门限。移动到单个工位期间使用当前目标的中心/尺寸连续性关联；自身丢失时停车，不在画面边缘突然接管另一个圆。需要跨越大偏移重获身份时，先返回观察范围。

## 6. 放料步骤：重复三次

每个物料执行：

1. 根据item_index取得本物料颜色、目标位置；C板负责对应物料按既定仓序出仓。
2. 在观察范围确认指定工位身份，选择当前有效空环中心。
3. 用 `coarse_ring` profile将圆心对准放料准心；只控制vx、vy，omega请求0并用新鲜yaw监视朝向漂移，超限则停车，见公共约定第5节。
4. 误差满足要求后归零，进行新帧复核；随后停止视觉速度输出。
5. 发布一次 `UInt8(data=1)` 到 `/C/arm_command`，锁定该次请求。
6. 等待相应放料与转仓完成反馈。等待中不再对准、不重发命令。
7. 确认成功后提交该物料放置记录，进入局部返回。
8. 返回观察位附近、停车，获取新画面，再开始下一项。

第三次也执行转仓和返回。三次均成功后才从PLACE切到PICK，取回item_index重新从0开始。

## 7. 取回步骤：重复三次

取回按colors顺序，不按左到右或positions排序：

1. 取得当前颜色与已确认放置位置，确认三个放置动作均已完成。
2. 当前作业ROI做该颜色HSV分割 → 小核开闭运算 → 合格物料轮廓 → 图像矩质心。
3. 排除车上/夹爪同色区域，并用当前工位关联约束，不能仅选全图最大色块。
4. 用 `coarse_material` profile将质心对准取回准心，误差满足后归零、复核。
5. 发布一次0，等待抓取、入仓、转位全部完成。
6. 确认成功后提交取回状态；返回观察位附近，再处理下一颜色。

不使用放料时的历史像素直接取回；当前底盘位置变了，必须重新检测。取回对象是静止物料，不需原料区的转盘停稳窗口，但仍需有效新帧和停车复核。

质心先作为默认方法。以后若启用顶面圆，必须另设profile和准心并验证，不在同一任务每帧静默切换中心定义。HSV阈值只从公共六色YAML读取。

## 8. 状态机、接口与停止策略

### 8.1 完整区域状态机

```text
IDLE → VALIDATE_BATCH_AND_DEPENDENCIES → WAIT_ROUTE_RELEASE → SYNC_COARSE_CONTEXT
→ ACQUIRE_OBSERVATION_VIEW → [ENTRY_REFERENCE_ALIGN] → CAPTURE_LOCAL_REFERENCE
→ PLACE_FIND → PLACE_ALIGN → ZERO_VERIFY → SEND_PLACE_ONCE
→ WAIT_ACTION_DONE → COMMIT_PLACE → RETURN_OBSERVATION
→（三次全部完成）PICK_FIND → PICK_ALIGN → ZERO_VERIFY → SEND_PICK_ONCE
→ WAIT_ACTION_DONE → COMMIT_PICK → RETURN_OBSERVATION
→（三次全部完成）FINAL_FIND_THREE_RINGS → FINAL_REFERENCE_ALIGN
→ FINAL_ZERO_VERIFY → REFERENCE_RESTORED → COMPLETED
```

每次RETURN后先停车并等待有效新图像。最后一次PICK返回后，直接进入最终三圆校准，不再触发新的采放。

每次发送前还须满足公共ready时效、区域同步、机构就绪和工作范围条件。发现放置颜色或占用与预期冲突时报告异常，不推着已落地物料“视觉纠偏”；规则不允许用推动补救摆放。

### 8.2 保留单项与整批两种入口

- 单项对准：`/vision/coarse/align`，传入 `coarse_place` 或 `coarse_pick`、颜色/位置/profile。纯align只返回aligned，不自动发机构指令，方便只读与伺服调试。
- 整批任务：拟定 `/vision/coarse/run_batch`，接收本批数组，按本文六步与回中流程调用内部对准并发送采放请求。
- 单步采放调试：另设 `/vision/coarse/execute_item`，显式开启 `enable_motion=true` 和 `execute_action=true` 后才允许“对准+一次0/1+等待结果”；纯align不接受机构执行请求。调试模式不得自动模拟完成推进真机批次。

以上接口名称为待实现约定。任务结果、反馈和取消应保持可响应，不用阻塞循环等待通信。

### 8.3 采放接口预留

| 话题 | 约定 |
|---|---|
| `/C/controll` | 既有 `ControlCommand`，vx向前m/s，vy向左m/s，omega逆时针°/s |
| `/C/arm_command` | 拟新增 `std_msgs/msg/UInt8`，0采并入仓后转仓，1出仓放置后转仓；RELIABLE、VOLATILE，禁止历史重放 |
| `/C/arm_status` | 预留完整采放执行反馈，区分运行/完成/失败/未知并能对应当前动作；C板成功前已自行完成转仓，不要求独立转仓反馈；类型待板间通信实现 |

仅裸0/1不具备请求身份，不能承诺可重传且恰好执行一次。正常流程每次只允许一个未完成请求；未来通信层若重传，须有命令身份及去重。连续相同的0或1仍是不同请求，不能只在数值变化时执行。

### 8.4 异常与取消

检测丢失、图像过期、候选身份歧义、无效参数时归零，保留当前步骤；不自动跳物料，不以超时默认成功。恢复后使用新帧重新关联。

寻找、对准、局部返回和最终校准各设超时/无进展条件，超时停止并报告对应原因，不永久占用控制。机构动作超时只说明结果未知，不能清除待完成状态、重发命令或立即放行底盘。等待依赖反馈的状态也须可取消，不能阻塞ROS执行器。

取消对准时归零并释放输出；采放已经发出时取消不能宣称物理动作已停止。须报告动作仍在执行或结果未知，等待未来下位机停止/完成契约，不直接接下一路线。

## 9. 最后离站精校准：三个圆心平均点 + 拟合直线

### 9.1 启动条件与目的

三物料均已取回、入仓并转仓完成，机构退出观察遮挡，底盘已返回观察范围。重新检测三个不同工位的空圆环，不能用同一工位的三个同心环，也不能把物料顶面补成缺失地面圆心。

本步骤采用用户确定的方法，同时控制vx、vy、omega，使三圆心平均点接近指定像素、工位拟合直线接近水平。只有满足最终条件才允许离开粗加工区。

它是固定相机、固定工位平面附近的相对视觉位姿恢复，不自动产出精确地图米制位置。参考图像必须在约定离站位置与朝向采集，不能将任意“看起来水平”的姿态当作地图基准。

### 9.2 特征计算

对有效的三个工位中心p1、p2、p3（浮点像素）计算：

```text
c = (p1 + p2 + p3) / 3 = [uc, vc]
q_i = p_i - c
S = (1/3) × Σ(q_i × q_i^T)
d = S最大特征值对应的单位特征向量
令d_u为正，theta = atan2(d_v, d_u)
```

实际实现可用上述PCA/TLS拟合或等价的 `cv2.fitLine`；方向是无向直线，角度按模180°处理。将角误差归一到[-90°,90°)，不能在方向向量反号时突然出现180°误差。

每帧检查三个工位唯一、圆心间距合理、拟合残差小、跨度足够且 `abs(wrap_line(theta_ref-theta))` 小于 `max_abs_line_error_deg`。该范围检查围绕标定参考角，而不是永远围绕0°。跨度太小或布局异常拒绝控制，不用高噪声角度转车。直线残差可由点到拟合线的最大垂距计算。

无向直线无法区分相差180°的车辆姿态。进入本步骤前仍须用路线朝向及新鲜yaw保证处于约定作业朝向的小偏差范围，不能从任意朝向仅凭“线水平”判定回正。

### 9.3 控制量

```text
e_u = u_ref - uc
e_v = v_ref - vc
e_theta = wrap_line(theta_ref - theta)
[vx, vy]^T = B_reference × [e_u, e_v]^T
omega_deg_s = k_theta × e_theta_deg
```

`theta_ref_deg`默认0°，对应图像水平；若实际安装使正确离站姿态下线条不是严格水平，标定后改为实际参考角，不强迫车辆斜着停来补偿相机安装角。

B_reference为2×2矩阵，包含轴交换、符号和增益，单位(m/s)/pixel；k_theta包含角速度方向符号，单位(°/s)/°。用低速微动验证闭环负反馈；不能因为图像坐标v向下就猜角速度符号。

三路速度在同一条ControlCommand里发布，并分别限幅；所有误差来自同一张有效新图像。旋转也会改变平均点位置，闭环每帧重新计算三个误差，不能先计算一次平移量再盲转。

首版在小偏差观察范围采用上述同时P控制。若实测耦合造成不收敛，再标定三特征对三速度的局部3×3雅可比或采用分阶段纠偏；不在未测量时宣称任意姿态下都能解耦。目标点与直线姿态不能约束相机高度等额外自由度，固定安装与工位平面是必要前提。

### 9.4 最终完成判据

同一有效新帧必须同时满足：

- 三个真实工位中心均可用，身份和几何检查通过。
- `sqrt(e_u² + e_v²) < center_tolerance_px`。
- `abs(e_theta_deg) < angle_tolerance_deg`。

连续满足 `settle_frames` 张不同采集帧后，三路速度全部归零，进入 `FINAL_ZERO_VERIFY`。等待停车稳定后重新获取新帧，仍同时合格才提交 `reference_restored=true`。若误差超出，回到精校准；目标丢失或过期时全部归零并清连续计数。

返回COMPLETED前还应确认局部返回执行器已释放控制、完整动作结束且机构允许行驶、当前视觉速度已停止。最后校准过程中不得再发0/1。

### 9.5 与路线执行的交接

将“已回到约定离站参考、当前作业朝向、任务身份”交给调度，并保持连续yaw测量更新。若校准产生转向，路线执行必须使用实际反馈yaw，不继续使用校准前的假设朝向；不能擅自重置IMU或通信里程坐标会话。

最终视觉校准不能替代最初的局部返回接口：三个圆不在画面时，平均点和拟合角都无法计算。先返回观察范围，三圆可见后再精校准。

## 12. 实现顺序与验收要求

建议按以下顺序实现，前一步可独立演示后再连接下一步：

1. 720p图像、空环候选、同心归并，显示全部候选和1/2/3身份。
2. 单环放料对准、指定色物料取回对准；只识别模式不发速度或机构命令。
3. 对准后一次0/1与WAIT_ACTION状态；没有反馈不得推进。
4. 接入局部返回能力，验证偏移后返回观察范围，不依赖完整空圆图案。
5. 六步批次状态机、一次动作请求与已完成物料状态保存。
6. 三环平均点与拟合角特征、三速度控制、停车后复核及离站结果。

应覆盖以下有意义的场景：

- 两批不同颜色/位置排列，严格按colors索引出入仓。
- 放一个后部分圆环不可见、只剩一个空环、物料顶面伪圆，身份不误重编。
- 返回观察位仍有入站误差时，用新图重关联，不直接使用旧圆心。
- 命令重复回调不重复发采放；迟到/重复完成不重复提交物料进度。
- 粗加工任务只输出0/1，不额外发转仓命令；暂存码垛另用2。转位结果包含在C板完整动作结果中，失败和未知不盲目重发。
- 最终三个空环全部可见：平均点偏移、线条倾斜、两者同时存在都能按正确符号减小误差。
- 三个同心环不能伪装成三个工位，拟合线方向反号不产生180°误差。
- 中心合格但角度不合格、角度合格但中心不合格，都不能离站。
- 图像冻结、丢一个工位或几何异常时三速度归零，参考恢复状态不置真。
- 最后一次动作完成但校准未完成时，不推进下一路线。
- 180°相反朝向虽然也可能形成水平线，必须被yaw/入站朝向检查拒绝。
- 返回误差导致参考门限重叠或两个身份均可解释同一空环时停止，不无限扩大匹配范围。
- 同为0，只有C板确认coarse上下文后才允许地面取回；原料上下文或迟到确认不得放行。

# 三个区域方案自查与开源复核记录

日期：2026-10-20。检查对象为01原料、02粗加工、03暂存，以及会影响其实现的公共约定、索引、简明流程。结论依据文档、当前ROS2接口、三套开源Python源码及今年两份规则PDF；未运行旧硬件程序，未验证实车性能。本轮仅修订Markdown。

## 1. 结论与使用边界

保留一个主相机节点内三个可独立调用的区域模块，统一720p，物料HSV、地面环霍夫圆、底盘限幅P伺服的架构。可以分步编码识别、单项对准和任务状态机；完整自动批次依赖局部二维返回、板间通信及明确关联的动作反馈，不能把这些预留接口视为已经存在。

动作统一0采并入仓、1出仓平放、2出仓码垛；三种动作的内部转仓均交给C板。用户在本次自查中确认：板间通信同步当前区域，C板按raw/coarse区分0的取料高度，不新增动作值。

## 2. 找到的问题及本轮处理

| 问题 | 影响 | 已修订方案 |
|---|---|---|
| 原料与地面取回均发0，却未明确高度上下文 | C板可能调用错误高度 | 用户确认区域同步；动作前等待本次区域确认，重连/重启后重同步 |
| 公共文档写调度逐目标调用，区域文档又写整批内部发动作 | 可能重复执行或索引各自推进 | 整批由区域执行器顺序执行，调度发起并幂等保存步骤；纯align不发机构命令 |
| 原料未明确每件取后如何重新覆盖转盘 | 下一颜色出画，失去获取条件 | 每件后局部返回本次观察位并清空稳定窗口；第三件后恢复离站参考 |
| “保留编号”缺少可编码的匹配规则 | 返回有偏差时仍可能认错唯一剩余空环 | 同次参考姿态＋局部返回误差限制＋不重叠像素门限＋一对一匹配；旧像素仅作身份依据 |
| 暂存第二次进站缺少重新初始化规则 | 可能将第一批旧像素当当前位置 | 本次观察位重新获取三个同高底层目标，核对颜色排列，再保存本次参考；逐项时可部分可见 |
| omega=0被描述成保持朝向 | 平移中yaw漂移破坏准心几何关系 | 明确不主动旋转并非闭环锁头；新鲜yaw监视，超限停车；最终三环校准单独接管旋转 |
| 公共完成流程没有统一停车后新帧复核，默认仅1帧 | 抖动或惯性可提前触发动作 | 建议至少3张连续新帧并满足时长；停车后重测；原料再做静止窗口 |
| 原料ready没有有效期，视觉无法预测转盘还停多久 | 延迟抓取时物料可能已运动 | ready含身份、帧号和时间；发0前复核，超时撤销；实测整段抓取延迟与停留窗口 |
| 最新帧缓存被当作充分新鲜度保证 | 驱动积压或阻塞时仍可能控制旧画面 | 时间来源与端到端延迟核查，独立速度看门狗，不用图像哈希代替采集帧号 |
| 部分模板缺局部返回字段、物料高度尺度、合并规则 | 跨会话实现可能错误继承或把null当0 | 补齐模板，明确递归合并、列表替换、仅校验启用profile及依赖 |
| 任意底盘纠偏缺工作范围约束 | 视觉对准可能要求驶出灰色车道 | 预检安全可达范围和局部允许位移，越界报告WORKSPACE_LIMIT |
| 三环拟合直线无向，且允许角度范围围绕0而非参考角 | 相反朝向/安装偏角被错误处理 | yaw保留朝向分支，角误差按参考角与模180°计算 |
| 部分状态可无限等待，缺完整任务预检 | 执行半批后发现缺返回能力或一直卡住 | 初始检查完整依赖，各状态有超时原因；动作超时为未知，不能放行或盲目重发 |

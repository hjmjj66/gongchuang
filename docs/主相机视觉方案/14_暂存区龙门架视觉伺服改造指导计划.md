# 暂存区龙门架视觉伺服改造指导计划

> 2026-11-17：已适配[上位机通信协议v2.0（正文v0.8）](../../上位机通信协议v2.0.md)。粗加工放置与暂存第一层统一使用cmd=6，暂存第二层仍为cmd=7；cmd=8已删除。下文旧动作号仅为历史记录，当前实现以[适配记录](../../docs/主相机视觉方案/通信协议v2.0接入记录.md)为准。

> 2026-11-15 协议v0.7适配：当前代码已改用有符号 `fb_pulses/ud_pulses` 和 `pos_flags`；下文毫米位置、连续机构角等描述保留为历史设计，以[协议v0.7接入记录](通信协议v0.7接入记录.md)为准。位置返回直接用脉冲误差，无需毫米换算。

日期：2026-11-15；本版已纳入相机/车体偏移补偿与高位直接放置。状态：需求已确认；正式流程及8086网页已按本版改造，软件验证见[实施记录](16_暂存区龙门架实施记录.md)。电控动作表及实车标定仍待现场验证。

本文替代[旧暂存指导方案](09_暂存区任务流程与实施指导.md)中底盘逐件对准、两次返回P0、一次下降、独立码垛准心和目标缺失业务超时等约定。旧软件验证仅证明旧版行为，不作为新版机构闭环验收结果。流程以本次用户确认与[更新版通信协议v0.5](<../../上位机通信协议(更新版)>)为依据。

## 1. 已确认范围

正式阶段8 `STORAGE_PLACE`与阶段14 `STORAGE_STACK`，以及8086网页暂存第一次/第二次选项同步改造。原料区和粗加工区各自的业务流程不在本次变更范围；公共模块修改须回归这两个区域。

- 相机固定在夹爪正上方，近似垂直俯视，随整个伸缩导轨旋转、随末端伸缩。机构旋转带动整个导轨绕固定支点转动。
- “r、t对准”采用图像误差速度PID：横向误差控制旋转角速度，纵向误差控制伸缩RPM；不反解绝对长度与角度。
- 第一次：高位工作位 → 底盘水平纠偏，最多3秒 → 底盘对准环2 → 底盘锁定 → 高位按序用机构对准圆环，高位对准后直接放料 → 三件后收纳 → 沿车体正vx补偿相机/车体偏移并确认停车。
- 第二次：到站后底盘全程零速；不做水平纠偏，也不做环2或中间物料的底盘平移校准。进入工作位 → 机构扫描确认第一层三色 → 回统一工作位 → 按第二批颜色顺序高位对准当前同色物料，每件在高位直接码垛 → 三件后直接收纳。
- 两次逐件动作后均回统一高位工作位置，不回本件对准结束时的r、t。工作高度、标定点和机构PID先共用一套；不是各区域共用同一份可变参数。
- 两次均不取回物料、不返回入站位置或旧P0、不做末次水平纠偏。机构收纳完成、首次偏移补偿及停车完成、控制释放后才交回比赛状态机；阶段14之后由原有路线去启停区。
- 连续4张不同新帧同时满足中心误差及两轴输出足够小，才允许停轴并直接交接固定放置动作。不增加旧版的停车后视觉新帧复核。
- 健康图像中目标缺失时原地等待重新出现，不因等待时间长报错离站。首次找环1/环3可分别向左/右小幅旋转探索；已在跟踪的目标丢失则立即停轴等待，不自动回工作位。

## 2. 顺序与第一层布局

沿用任务码及第一层确认映射，不改颜色定义：红1、黄2、蓝3、绿4、黑5、浅蓝6。

例 `156+123+516+231`：

| 内容 | 含义 |
|---|---|
| 第一批颜色156、位置123 | 颜色1/5/6依次放到环1/2/3 |
| 第一层确认映射 | `{1:1, 5:2, 6:3}` |
| 第二批颜色516 | 按颜色5→1→6码垛，对应位置2→1→3 |
| 第四组231 | 第二批粗加工位置，不直接作为暂存码垛顺序 |

第一层布局用于选择扫描/寻找方向及填写步骤元数据。第二次不重新做圆环检测或视觉布局一致性检查，精对准始终使用当前新图像中的同色物料中心。已完成颜色不再选为后续目标，不做上下同色实例拆分或堆叠效果复核。

## 3. 第一次：底盘一次校准、机构逐件平放

```text
受理任务，底盘停车
→ WORK工作位(cmd3)，等待完成
→ 用圆环中心拟合直线，底盘角速度纠偏，最多3秒
→ 机构保持工作位，用底盘平移将环2中心对准共用标定点
→ 确认底盘停止，锁定底盘
→ 按第一批位置数组选择目标环
→ 高位伸缩/旋转视觉对准，连续4张新帧合格
→ 停止伸缩/旋转并完成协议交接
→ PLACE_TEMP_1(cmd6)，等待完整放料及自动回高位工作位
→ 下一件从高位重新寻找、对准、直接放料
→ 第三件完成后INIT收纳(cmd2)，等待完成
→ 沿车体正vx按里程闭环移动camera_car_offset，确认停车
→ 释放控制，提交三项PLACE和第一层记录，交回比赛状态机
```

水平纠偏使用同一新帧中全部有效圆环中心拟合；两个有效中心也可参与。目标斜率0，不追踪绝对yaw。3秒包含等图、目标不足、纠偏及停车确认，不因重找而重计时；到时输出零角速度并继续环2校准。真实相机、通信或下位机故障不当作正常纠偏超时吞掉。

环2校准保持机构固定工作位；底盘视觉映射沿用 `vx=-PID(e_u)`、`vy=+PID(e_v)`，底盘角速度0。使用独立的底盘低速PID及到位/低速确认参数，不把机构RPM参数用于底盘。环2不可见时停车等待，不以其他环替代环2；本版不增加底盘扫描路线。

环2校准完成后，逐件放置及收纳期间底盘vx、vy、wz全零；首次收纳完成后才执行离站偏移补偿。校准后的里程位置可以展示为诊断数据，但不是需要返回的目标。即使输入顺序首先是环2，也要走正式机构对准与4帧门槛，不能凭此前底盘校准直接放料。

两次均取消上位机定时下降，直接从高位工作点衔接cmd6/7；固定放置程序自身的层高运动由下位机负责。每次程序完成回统一WORK姿态，下一件重新用新图像对准。相机对准环2时车体中心偏向环3；首次三件完成并收纳后，按用户指定的车体正vx方向补偿79.45mm。距离唯一配置为mission.yaml的camera_car_offset（mm，0禁用），粗加工两批共用该几何参数。起点取收纳完成后的新鲜里程，按当时车体前向轴投影计距；vy/wz为0，到位后零速并等新鲜低速反馈，才允许推进下一阶段。不是按世界坐标x移动，也不从环2校准前的坐标算距离。

## 4. 第二次：底盘不动、机构扫描与同色码垛

```text
受理任务，底盘停车且本批保持全零
→ WORK工作位(cmd3)，等待完成
→ 识别第一层三种颜色；视野不全则仅用机构旋转补齐
→ 三色全部确认，实际回统一工作位(cmd3)，等待完成
→ 按第二批颜色顺序寻找当前同色物料
→ 高位伸缩/旋转视觉对准，连续4张新帧合格
→ 停轴并完成交接
→ PLACE_TEMP_2(cmd7)，等待完整码垛及自动回高位工作位
→ 下一件重复高位对准、直接码垛
→ 第三件完成后INIT收纳(cmd2)，等待完成
→ 释放控制，提交三项STACK，交回比赛状态机
```

### 4.1 三色扫描

沿用每色连续有效新帧确认，默认3帧，可配置；这与逐件动作的固定4帧门槛不同。允许不同颜色跨画面累计，三色未齐不得开始第一件。

扫描启用物料工具全颜色输出，只确认本批第一层布局中的三种颜色。根据已知布局选择尚未确认的颜色，用机构低速旋转探索；不再输出底盘平移。探索使用可配置的小角速度与短时段，避免没有视觉反馈时无限转动；一次探索未找到则全零等待，不增加自动反向循环或回位恢复。

累计的是“颜色已被确认”，不是将不同相机位姿下的像素中心拼成地图。扫描后发一次工作位动作，再用该动作完成后的新图像寻找第一件；扫描的历史像素不能用于实际驾驶。扫描完成的已见颜色集合可以保留作状态展示，动作切换须清空伺服计数与旧观测。

### 4.2 逐色码垛

当前目标颜色按第一层映射得到位置号，仅作寻找方向和记录。从统一工作位出发，位置1在左、位置3在右，可分别小幅左/右转寻找；位置2缺失则停轴等待。机构已转动后，不直接将“目标编号比当前可见编号大”当作任意姿态下的图像方向。

目标一旦可见，就使用其当前有效中心做视觉PID。跟踪中目标丢失立即停止两轴、清空4帧计数并原地等待；一张新的有效图像重新出现即可恢复控制，不自动回工作位、不挪底盘、不重扫三色。

第二次直接从高位工作点交接cmd7，不发送额外下降，也不做离站偏移补偿。首版共用工作高度、准心及PID；第一层顶面与圆环平面不同，共用是用户确认的实施起点，不代表现场精度已验证。

## 5. 图像误差、输出与触发条件

使用工具提供的最终有效中心，不在任务层重算圆心或判色。原图左上为原点，右/下为正，空准心配置表示实际图像中心。

```text
e_u = u - u_ref
e_v = v - v_ref
旋转 yaw_wz = -PID_yaw(e_u)    # rad/s，目标偏左→逆时针正
伸缩 fb_rpm = -PID_fb(e_v)     # RPM，目标偏上→伸出正
机构视觉伺服期间 ud_rpm = 0
底盘 vx = vy = wz = 0
```

两轴允许同时运动。共用准心既用于首次底盘环2校准，也用于机构对准圆环和物料。使用通过标定点的竖直线作横向误差零线，不使用画面底边中点连线斜率估计真实机构极角。

每张新帧用正常PID并限幅后计算输出，再判断：中心欧氏像素误差在容差内、旋转输出绝对值不超过小输出阈值、伸缩输出绝对值不超过小输出阈值。连续4张均满足才达标；不能先把输出强制置零再判断合格。重复帧不能增加计数，缺目标或任一条件不满足清计数，PID切换及缺失后按既有控制约定复位。

第4帧达标后停止连续机构流，由桥接确认零JOG及新鲜空闲反馈后直接交接固定放置动作；这属于协议交接，不是额外视觉复核。固定动作执行期间不使用其图像控制机构；完成后只接受新姿态采集的新帧。

`fb_mm`、机构`yaw_rad`可用于调试展示；暂存不靠它们做绝对r、t位置返回，也无需保存三个物料对应的机构位置。不能将底盘yaw与机构yaw混用。

## 6. 更新版协议与动作边界

以仓库根目录[上位机通信协议(更新版)](<../../上位机通信协议(更新版)>) v0.5为动作号来源：

| 用途 | 帧/动作 | 约定 |
|---|---|---|
| 工作位、扫描后回位、网页逐件恢复 | `0x02 cmd=3 WORK` | 两次共用统一高位工作姿态 |
| 第一层放置 | `0x02 cmd=6 PLACE_TEMP_1` | 从托盘取出、第一层放置、回工作位 |
| 第二层码垛 | `0x02 cmd=7 PLACE_TEMP_2` | 从托盘取出、第二层叠放、回工作位 |
| 最终收纳 | `0x02 cmd=2 INIT` | 收拢位，完成后才放行路线 |
| 停止/中止 | `0x02 cmd=0` | 沿用桥接停止语义 |
| 连续伸缩/旋转 | `0x03 ARM_JOG`，50Hz | yaw_wz为rad/s、fb_rpm为RPM、ud_rpm为0 |

cmd8是粗加工放置，不得用于暂存；cmd6不再表示暂存码垛工作位，cmd5不再表示收纳。旧storage.yaml、网页暂存参数中的动作占位必须在实施时迁移，不能沿用旧数字。

最新约定取消上位机预下降，cmd6/7从高位工作点开始完整交换程序；层高差由cmd6/7区分，协议不传新增高度字段。现场需核对动作表能从高位直接起步并在结束后回统一WORK。

用户已确认点动后可直接执行固定动作、无需额外HOME。更新版协议仍含旧基准未验证提示，实施时应补充该会话确认条件；不改字段含义、不自动插入HOME。ACK仅表示受理，动作完成须匹配本次请求并观察当前动作忙→闲；拒绝或结果未知不自动重发。

## 7. 公共接口复用与当前差距

本次检查时，原料新版已具备`ArmServoCommand`、`/C/arm_servo`、共享`ArmServoPublisher`及桥接连续流/固定动作交接，见[原料实施记录](13_原料区龙门架实施记录.md)。暂存已复用`StorageTask(CoarseTask)`及网页包装；两次在高位工作，首次复用收纳后的底盘偏移移动。

优先复用现有：

- `task.velocity`表示底盘输出，`task.arm_velocity=(yaw_wz,fb_rpm)`与`servo_enabled`表示连续机构输出，`arm_request`表示固定动作。
- 同一桥接、串口、机构流有效期和许可绑定；停止旧流→零JOG→新鲜idle→固定动作，不在动作结束后复播旧速度。
- 唯一`coarse_node`、公共运行/停止/复位、`/vision/storage/run_batch`及跨区域互斥。
- 正式底盘速度仍由`/vision/storage/control`经mission仲裁到`/C/controll`；不得另开串口或绕过调度器。第二次仍维持有效零速反馈及控制许可。
- 一个共享相机/模型线程；机构视觉JOG阶段持续识别，固定动作期间只暂停用于控制的观测，不新增独立相机进程。

宿主的机构发布、停止和交接路径已接入storage。不能只改纯控制类而漏掉真实输出、固定动作前的旧流关闭、取消和退出清理。正式配置及网页配置均在外部入口统一校验一次。

## 8. 调度结果与离站条件

首批提交三项`PLACE`及完整颜色—位置记录；第二批提交三项`STACK`。真实动作完成只表示电控程序完成，`visually_verified=false`，不伪称视觉验证堆叠成功。

新版不执行二维返回；宿主与mission采用以下契约：

- 新版暂存不执行位置恢复，`reference_restored=false`，`final_alignment_outcome=NOT_RUN`；不得为兼容旧检查把未发生的返回报告为成功。
- mission对暂存8/14按对应三项完成记录、首批布局记录、`all_items_completed`、`motion_released`、`arm_idle`和`travel_ready`验收，不再要求旧二维返回字段；其他区域按各自现行契约处理。
- `travel_ready`只在最终cmd2确认完成、首次偏移补偿并停车完成、机构空闲、底盘零速且连续机构控制已释放后成立，不能在第三件放置完成时提前报告。
- 沿用现有结果表达；RunWorkBatch.camera_car_offset携带毫米距离，mission仅向粗加工两批及首次暂存下发非零值。无需新增返回目标或结果状态。
- 第一次最终停在环2校准位置沿车体正vx补偿后的区域位置，第二次停在本次到站位置；核对下一路线从实际离站姿态启动，不偷偷插入回P0补偿。

## 9. 等待、故障与停止

| 场景 | 行为 |
|---|---|
| 首次水平纠偏达到3秒 | 角速度归零，记录超时跳过，继续环2校准 |
| 健康新图像中环2不可见 | 底盘与机构停，等待环2 |
| 从工作位初次找环1/3或对应颜色 | 低速短时左/右探索；未找到停轴等待 |
| 三色未齐 | 继续规定的机构扫描/等待，不提前放第一件 |
| 已跟踪目标丢失 | 立即停轴、清计数，原地等待；不自动回工作位 |
| 等待很久但反馈、图像健康 | 保持任务、健康监控、可取消能力，无找料业务总超时 |
| 相机断流/过期、通信或控制许可异常、机构故障 | 停止底盘与机构并报告故障，不当作普通缺目标等待 |
| 固定动作拒绝、超时或结果未知 | 停止报错，不重发放置、不跳件 |
| 人工停止、取消、页面失联、进程退出 | 复用零输出及ABORT清理，不自动收纳、返程或续跑 |

取消旧暂存`target_missing_timeout`、`visual_step_timeout`对健康图像中缺目标的失败退出；仍保留图像有效期、相机断流、反馈及许可有效期、离站移动和固定动作的故障时限。所有等待用非阻塞状态机，网页心跳与比赛取消仍须及时响应。

## 10. 8086网页与参数迁移

网页保持已有三区域切换入口，本次只更新暂存两次选项。首次输入圆环顺序如213；第二次输入颜色顺序如516与按环1/2/3填写的第一层布局如156，均沿用现有入口校验。第一层物料由人工提前按输入摆好。

| 步骤 | 正式比赛 | 暂存网页 |

| 入站工作位、扫描后回工作位 | 实际cmd3 | 同样实际执行 |
| 首次底盘水平/环2校准 | 实际执行 | 同样实际执行 |
| r、t扫描、寻找和视觉对准 | 实际JOG | 同样实际执行 |
| 高位对准后 | 直接交接cmd6/7，无预下降 | 直接进入1秒等待，无预下降 |
| 本件放置/码垛 | cmd6/7完整动作 | 不发cmd6/7，全轴零速等待至少1秒 |
| 本件恢复高位工作位 | cmd6/7内部自动完成 | 等待1秒后实际发cmd3并等完成，第三件也恢复 |
| 三件后收纳 | 实际cmd2 | 同样实际执行 |
| 首次收纳后离站补偿 | 正vx移动camera_car_offset并停车 | 读取同一mission.yaml，同样实际执行；第二次不移动 |
| 回P0、末次纠偏 | 均不执行 | 均不执行，也不自动进入下一路线 |

页面明确显示会真实驱动底盘及龙门架，移除暂存旧版“相机人工固定、全程无机构动作”的提示。模拟完成记录与真实机械放置分开表述；一件1秒完成只计数一次，工作位恢复成功后才允许下一件，收纳前必须完成第三件恢复。

展示：次数/顺序/布局、当前高位/固定动作/离站补偿状态、底盘是否锁定、环2校准状态、入站纠偏结果、扫描已见颜色、目标中心/来源、帧序号及年龄、像素误差、旋转rad/s与伸缩RPM、4帧计数、等待原因、动作号、模拟完成数和收纳状态。坐标仅作当前位置诊断，不再展示暂存P0返回进度或P1/P2/P3底盘取回位置。

参数采用现有YAML与网页编辑保存，当前分组如下：

| 分组 | 内容 |
|---|---|
| `arm` | work=3、place=6、stack=7、stow=2；无下降速度或时长参数 |
| `vision` | 共用准心、模型配置、图像有效期与相机断流时限 |
| `angle_alignment` | 首次专用，最多3秒、斜率PID及容差 |
| `base_servo` | 首次环2校准PID、底盘限速、像素容差与停车确认 |
| `gantry_servo` | 两次共用旋转/伸缩PID、rad/s和RPM限幅、中心容差、两轴小输出阈值，固定4帧 |
| `ring_search` | 小幅旋转速度与短时段、每色连续确认帧数，首次找环与第二次找色共用方向约定 |
| `exit_motion` | 首次收纳后移动限速、比例增益、容差及时限；距离只读mission.yaml的camera_car_offset |
| `execution` | 50Hz、反馈/许可有效期、协议交接及固定动作故障时限 |

删除或迁移旧`xy_return`、两套平移`place_servo/stack_servo`及旧下降时机字段，不保留名不副实的m/s参数承载机构RPM。两次暂存先共用一套配置；网页保存只影响storage区域，停止后保存、下次开始生效，原料和粗加工参数不受影响。正式未标定项仍显式未就绪；网页用可编辑低速初值，不能拿底盘m/s数值直接充当机构RPM，也不把调试初值当作实车标定。

## 11. 实施顺序与验收

1. 按本版重构暂存纯控制核心，区分底盘、机构连续速度、固定动作及离站移动；先实现首次校准及两种逐件流程，再实现三色扫描与原地等待。
2. 接入已有连续机构通道和固定动作交接，保证每件从高位直接放置；固定动作后清旧帧，新任务清扫描、PID及完成记录。
3. 迁移正式storage.yaml动作号与共用参数，接入宿主storage输出/停止；同步修正mission离站验收，不伪造reference_restored。
4. 更新网页暂存包装、界面提示、独立参数与状态展示，实际工作位/恢复/收纳及首次偏移补偿，仅放置替换为1秒等待。
5. 使用真实核心、ROS节点、HTTP和软件伪串口验收，再回归原料、粗加工和共享桥接。改源接口时重新生成构建，不手改生成文件。
6. 软件通过后现场低速标定方向、共用准心、工作位覆盖范围、camera_car_offset、离站方向/距离及cmd6/7高位衔接，逐件再整批验证。

| 验收场景 | 必须结果 |
|---|---|
| 首次正常/入站角度超时 | 最多3秒；先水平纠偏，再高位底盘环2校准，放置期间锁定底盘 |
| 首次输入213 | 环2校准不计放料；仍按环2→1→3逐件高位机构对准、直接cmd6 |
| 首次每件完成 | 自动回统一高位；下一件重新对准，无上位机升降JOG |
| 首次完整结束 | 三项PLACE，cmd2收纳后正vx补偿并确认停车；无取回、回P0或末次纠偏 |
| 第二次开始 | 无底盘角速度、平移校准或搜索；整批底盘全零 |
| 第二次部分视野 | 机构补齐三色，未齐前无第一件；齐后实际cmd3回位再开始 |
| 第二次示例布局156、顺序516 | 当前物料中心按颜色5→1→6伺服，记录位置2→1→3；每件高位直接cmd7，无偏移补偿 |
| 两次准心及PID | 使用同一份暂存配置，未暗中复制成两套独立参数 |
| 4帧门槛 | 正常限幅输出足够小；重复帧、缺失、任一条件失败不凑数；不附加视觉复核 |
| 缺目标/跟踪中丢失 | 搜索动作受短时段约束；丢失立即零速，原地持续等待，一张新帧重现可恢复 |
| 图像过期或许可丢失 | 停止报错，不能以“持续等待”忽略故障 |
| JOG→固定动作 | 实际停轴和新鲜idle交接，无升降JOG或旧连续流复播 |
| 网页两次完整流程 | 实际工作位/扫描/高位对准、每件全零至少1秒、实际恢复、最终实际收纳；无cmd6/7 |
| 网页模拟第三件 | 工作位恢复完成再收纳，不跳过恢复，不自动开往下一阶段 |
| 取消、关闭页面、退出 | 底盘和机构停止、ABORT按既有契约执行，无自动恢复 |
| 调度完成 | 三步及首批映射正确、机构已收纳、首次补偿并停车、控制释放；reference_restored=false仍按新版暂存规则放行 |
| 共用宿主回归 | 原料4/10、粗加工6/12及暂存8/14互斥，停止和旧请求隔离保持 |

验收记录应区分纯软件闭环、真实模型照片推理与实车机械操作；本计划不把任何既有旧测试成绩写作新版完成证明。

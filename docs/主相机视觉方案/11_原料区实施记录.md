## 1. 已实现行为

- 到站后获取本批新的二维里程参考，再发送工作位动作；第二批独立记录参考。
- 严格按任务顺序抓取。必抓颜色不可见时，按剩余顺序选可见临时目标并持续跟随；必抓颜色出现即切换，不等待三帧。
- 当前目标丢失即零速，短暂等待原目标连续三张新帧后恢复；等待结束重新选择。临时目标丢失期间，必抓颜色出现仍立即切换。切换和恢复不延长当前件总时限。
- 只累计不同的新图像；必抓颜色连续四帧同时满足像素误差容差和实际底盘低速条件，第四帧立即零速并提交一次抓取。请求、ACK 等待和动作执行期间保持底盘零速。
- 同一个抓取程序执行三次。每次以对应动作完成反馈推进，程序负责抓取、入仓、托盘转 120°及恢复工作姿态。
- 三件完成后保持工作姿态返回本批参考，再收纳；收纳完成后交回比赛调度。原料区不下降、不纠偏角度，全程 `wz=0`。
- 异常、取消、目标超时或动作拒绝均停止并报告结果；不跳过物料、不自动重发抓取、不自动续跑。

停稳判据使用 `/C/odometry` 的实际平移速度，不以图像静止或 PID 输出较小替代。该判据及四帧计数按已确认需求实施；转盘停止窗口和夹爪接触延迟仍需现场验证。赛题 PDF 第 4 页规定运动时每圈 6～10 秒、方向随机，具体停止次数和时间现场确定，软件未假设固定转盘周期。

## 2. 接入位置

| 文件或接口 | 职责 |
|---|---|
| `agv_perception/raw_control.py` | 原料纯控制核心、目标选择、丢失恢复、四帧抓取、二维返回 |
| `agv_perception/work_control.py` | 与其他区域共用 PID、观测、位姿及二维返回速度转换 |
| `agv_perception/coarse_node.py` | 公共宿主提供 `/vision/raw/run_batch`，操作 `RAW_PICK`，与粗加工、暂存互斥 |
| `agv_perception/coarse_vision.py` | 共用采集/推理线程；原料请求全部颜色，直接使用工具有效中心；机构动作期间暂停控制识别，恢复后只接收新姿态图像 |
| `agv_mission/mission_node.py` | 阶段 4、10 接受 `/vision/raw/control`，仍由 mission 仲裁最终底盘速度 |
| [raw.yaml](../../ros2_ws/src/agv_perception/config/raw.yaml) | 原料标定、时限、准心和动作配置 |

保留 `coarse_node`、`coarse.launch.py` 作为现有公共启动入口，不另起原料相机或串口持有者。运行查询、停止和复位共用 `/vision`；串口及机构 ACK/执行超时复用既有 C 板桥接。

## 3. 配置状态

现场待标定值保留 `null`，未补齐时拒绝原料运动任务。需要填写丢失等待、每件总时限、像素容差、速度上限、两轴 PID、实际速度低速阈值和二维返程参数。准心为空时使用原图中心，亦可填写 `[u,v]`。

原图左上原点、向右/下为正，控制采用 `vx=-PID(u-u_ref)`、`vy=+PID(v-v_ref)`；实车需核对符号和相机安装方向。

动作号暂用工作位 **8**、抓取 **9**、收纳 **5**，避开粗加工 2～4、暂存码垛 6～7 的占位。这些不是已确认的电控动作表，必须核对后修改。抓取程序完成须已包含入仓、转位和恢复观察姿态；只收到 ACK 不算抓取完成。

## 5. 现场完成条件

1. 按真实动作表核对工作位、抓取和收纳号，确认抓取完成反馈包含托盘转位及恢复观察姿态。
2. 标定工作姿态下准心、伺服方向、限速、PID、像素容差及真实速度阈值。
3. 验证丢失停车/恢复、临时跟随和即时切换，测量四帧触发至夹爪接触的延迟，核对现场转盘停留窗口。
4. 验证工作姿态带料二维返回、收纳后离站及两批独立参考，完成实际三件顺序抓取与异常停车验收。

## 6. 网页底盘调试补充

按用户补充确认，原料已接入现有端口8086网页，与粗加工、暂存选项切换。输入三个不同颜色编号，开始后记录新P0，复用正式临时跟随、即时切换、三帧恢复及四帧对准/实际低速判据。仅将抓取替换为零速等待1秒，三件后回P0结束；已完成颜色仍在画面时直接忽略。工作姿态由人工固定，不发送任何机械臂命令。原料调试参数保存在工具自己的 `debug.yaml`，不改正式配置。

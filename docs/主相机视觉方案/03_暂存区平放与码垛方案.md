# 暂存区首批平放与第二批同色码垛方案

日期：2026-10-20。对应逻辑模块 `storage_task`，s=8 为第一批平放，s=14 为第二批码垛。

状态：待实现规格，按用户已认可的0采、1平放、2码垛方案整理；未代表实车验证。仓盘转动全部由C板执行，上位机不增加转仓话题、角度参数或实际仓位状态机。离站基线依赖局部位置返回能力，尚待运动层实现。粗加工离站前三个空环的校准已单独确定，不能照搬到放满物料的暂存区。

简版：主相机统一 1280×720，工位暂按左到右 1、2、3；第一次寻找任务指定圆环，对准后停车发一次 `1` 平放；第二次寻找第一层同颜色物料，对准后停车发一次 `2` 码垛。两种模式都等待完整动作完成再开始下一个颜色，各自准心留在 YAML 标定。详细方法保留如下，可先阅读[简明执行流程](简明执行流程.md)。

公共算法、坐标、接口与速度约定见 [00_公共视觉与伺服约定.md](00_公共视觉与伺服约定.md)，三套开源对照见 [README.md](README.md)。

## 1. 为什么两种放置共用一个区域模块

平放和码垛共享暂存工位、第一批颜色与位置关系、后续作业状态，但视觉目标和对准参数不同：

| 模式 | 本次对准什么 | 对准配置 |
|---|---|---|
| `storage_place` | 第一批应放的编号圆环中心 | `storage_ground_ring` |
| `storage_stack` | 第一层同颜色物料的目标中心，精度需要时使用顶面圆心 | `storage_stack_material` 或独立顶面圆 profile |

共用模块不代表共用准心、半径范围和速度增益。第一层颜色到位置的映射由统一任务上下文保存；暂存模块读取当前快照并返回结果，真实动作结果确认后由调度提交进度。

## 2. 任务码与同色码垛关系

命题第 8 页、评分规则第 3 页要求：第二批按任务码顺序放到第一层同颜色物料上，且第一批放置正确、码垛稳定。

任务码 `156+123+516+231`：

| 项目 | 内容 |
|---|---|
| 第一批暂存顺序 | 红 → 黑 → 浅蓝 |
| 第一批位置映射 | 红→1，黑→2，浅蓝→3 |
| 第二批码垛顺序 | 黑 → 红 → 浅蓝 |
| 第二批应寻找的底层位置 | 2 → 1 → 3 |
| 第四组 `231` | 第二批粗加工位置，不用于生成暂存码垛位置 |

任务码只给出计划。第一批对准了 1 号圆环，不等于红料已经正确放置；`aligned`、机构放置完成、视觉可见性复核应分别记录。系统记录的确认也不冒充裁判最终评分。

## 3. 第一批环节：编号圆环平放

### 去年方法

三套都具备圆环检测，但身份大多依赖红绿蓝：西安理工检测三个圆并排序；江苏用霍夫圆加圆周边颜色统计，分粗、精定位；第三套用霍夫圆、颜色筛选和机械臂视觉伺服，在 `subTaskNum==3_1` 依次放置。

它们提供了圆心检测与对准思路，不能直接提供今年编号位置选择。原代码细节及局限见 README；本环节复用 [粗加工圆环算法](02_粗加工区放料与取回方案.md)，使用独立暂存配置。

### 推荐流程

```text
读取本物料颜色和第二组对应位置
→ 获取暂存区工位身份 → 检测指定位置圆环
→ 同心归并与身份复核 → 平放准心伺服 → 归零 → aligned
```

首次完整观察三个工位并核对编号映射，随后放第一个、第二个后允许维护部分可见工位身份。不能要求整个放置过程中始终存在三个完整空环，也不能把剩余空环重新编号。

编号匹配具体复用粗加工第5.3节：保存本次观察位和三个地面环参考位置，动作后先局部返回，再在已验证的小误差范围用互不重叠的门限关联当前空环。所用的是本次新实测圆心；物料顶面只提供占用/颜色证据。不能只写“记住编号”而在车辆任意移动后直接按旧像素控制。

暂存区与粗加工区即使使用同一种霍夫方法，也分别配置作业 ROI、图像顺序映射、半径和理想圆心位置。工位镜像、相机朝向或停车姿态可能不同。

未来动作接入后，每个物料为：圆环对准 → 停止视觉控制 → 发一次1 → 等完整动作完成 → 保存第一层记录 → 用局部返回接口回到观察位附近 → 重新观察下一目标。C板在放置程序中自行处理出仓及后续转仓，上位机不单独控制。可在机构退开后用 HSV 检查该位置附近是否存在预期颜色，作为失败发现与可见性证据；仅“看见同色”不足以证明放置达到某个评分环数。

## 4. 第二批环节一：选择底层同色目标

### 三套开源怎么做

| 来源 | 码垛定位方法 | 可借鉴与不能直接沿用之处 |
|---|---|---|
| 西安理工 [unit 4 附近](/root/去年开源/Logistics_Vehicle_F407_V2/2025智能物流搬运_视觉_XAUT_20250815/TransportCAR_OSS_1.0.py:416) | 分别用 HSV 找蓝绿红三个物料、卡尔曼平滑，输出中间位置及两侧 y 差 | 借鉴圆环被遮挡后利用底层物料；当前应找任务所需颜色，不要求三个底层始终同时可见 |
| 江苏 [run_maduoyuanxin2](/root/去年开源/gcs-gold-medal/cv2_python/zongchengxu20250724chusai.py:1376) | 标准霍夫圆，半径范围相对地面环更小；圆周边判色、多次位置确认；另有中央小 ROI 版本 | 借鉴顶面圆心、颜色、局部范围三重约束；源码串口调用不等于所有精定位函数已启用 |
| 第三套 [subTaskNum 3_2](/root/去年开源/2025GongChuang_AGV/程序/上位机/国赛初赛/task.py:838) | 仍选择圆检测模式和目标颜色，机械臂在物料上方伺服，多次误差合格后停止跟踪，以码垛高度放置；另有不精定位分支 | 借鉴对准与动作分离及不同高度；不复制机械臂姿态、固定高度和色环选择规则 |

### 本项目推荐

读取当前第二批颜色 → 从已确认第一层映射得到预期位置 → 暂存 ROI 中分割当前颜色 → 排除车上、夹爪及持料区域 → 按工位身份和几何完整性选底层候选 → 输出中心。

同色和位置要共同约束。若同色物料出现在明显错误的位置，不应忽略冲突直接码垛；先返回身份/进度冲突供调度恢复。允许第一层正常放置误差，不能用过窄的固定像素 ROI 将真实底层物料排除。

逐个伺服期间不要求始终看到三色；但第二次进站需要重建当前视野与第一层记录的对应关系。首版在中心观察姿态同时获取三个第一层物料，分别有唯一颜色、几何完整性和区域证据，沿工位排列方向排序，与第一批已确认颜色到编号映射核对。三种颜色物料的形状与高度相同，在经验证的观察范围内用排序核对身份，不把其中心当成地面环中心。

核对通过后记录本次 `visit_id`、局部参考姿态及底层物料的观察位置；逐目标时只需当前颜色可见。第一批保存的历史像素不能跨进站复用。若初始三色被车载物料遮挡、排列冲突或视野不足，先在允许范围恢复观察姿态；仍无法建立身份就报告 `STORAGE_LAYOUT_UNCONFIRMED`，不自行用孤立色块猜工位。以后若有经标定的外部位姿到工位投影，可另增部分可见初始化，本版不假设已具备。

## 5. 第二批环节二：底层中心怎么求

### 方案 A：HSV 质心

对底层物料的完整颜色轮廓求图像矩中心。实现简单，适合今天先跑通识别与伺服；可与最小外接矩形中心进行离线对照，记录差异。

局限：圆台侧面、轮廓缺口、邻近同色物料和遮挡会让“颜色区域中心”偏离顶面支承区域。必须用实际图像确认偏差是否可接受，不因为图像近似俯视就假定完全重合。

### 方案 B：HSV 候选 + 局部霍夫顶面圆

颜色先确定底层候选，再在候选附近的灰度图检测顶面圆。检查半径符合该观察高度、圆心落在物料候选内部、边缘支持来自顶面而非底部或邻近物体，并满足连续性。

这结合了西安理工/第三套的 HSV 定位与江苏的物料圆检测。与“全图找圆后任取一个”相比，任务身份和搜索范围更明确。

**推荐分两步使用：今日以 A 建立可调试基线；实际码垛精度验证优先评估 B。** 若 B 更适合最终机构，则配置为独立 `storage_stack_top_circle` profile，单独验证后使用。B 失败时不静默切回 A 并仍返回同等精度的成功结果。

### 方案 C：模型候选/分割/关键点

以后模型给当前颜色物料框，用于粗定位；顶面分割或中心关键点可以直接表达需要的支承参考。通用物料框中心不必然对应顶面中心。模型仍须区分底层与持料，不能仅看类别分数。

今日不用模型、不以模型训练为前置条件。算法后端可替换，目标身份与高度 profile 保持一致。

## 6. 第二批环节三：高度、遮挡与对准顺序

### 高度使用独立配置

地面圆环与底层物料顶面高度不同，工作平面的像素比例及相机到夹爪的投影关系可能变化。近似垂直俯视会减小部分偏移，但不足以保证所有高度都可用同一准心和增益。

因此分别配置 `storage_ground_ring` 与 `storage_stack_material/top_circle` 的目标像素、速度矩阵、误差阈值和圆半径。机械码垛下降高度由机构执行层确定，视觉中心不提供高度测量。按最新讨论，动作指令区分为1平放、2码垛，C板直接按指令选择对应程序，无需额外平放/码垛模式同步话题。两种程序均包含完整出仓、放置、机构退让及内部转仓。

### 下降与接触检测：建议及能力边界

首版建议C板分别标定平放和码垛高度：先到目标上方，再减速下降至对应放置高度，松爪、抬升避让并完成内部转仓后反馈完成。具体机构高度、速度及转仓控制不由上位机实现。

用户提出的“慢慢下降，碰到东西就停”只有在机构能可靠感知接触时才可实现，不能仅凭降低速度获得接触信息。可以评估末端接触/力传感器；电机电流或扭矩反馈也可作为候选，但须验证能区分正常负载、摩擦、卡滞与真正的物料承托。普通开环步进或仅有位置命令的舵机不能默认具备该能力。当前尚未确认硬件，接触自适应不是本版前置条件，也不声称已实现。

若以后接入接触辅助，应由C板在预计接触高度附近低速下降，检测到稳定且合理的承托后停止下降并释放物料；需限制下降行程、受力及超时，未检测到承托或过早接触均返回异常，不能无限向下压或把任意碰撞算作成功。接触辅助仍保留指令2，且只补偿小幅高度偏差，不能替代视觉的平面对准；偏到边缘的接触不能证明码垛成功。

### 防止追踪夹爪持有的同色物料

码垛时，车上当前物料与地面目标颜色相同。只选最大同色轮廓或最大模型分数，可能跟踪到持料。

推荐在持料不遮挡目标的观察姿态下完成对准：利用排除区域、预期工位身份和顶面尺度选择底层目标；无法可靠分离底层与持料时报告遮挡并停车。ROI 需要与机构姿态匹配，不能承诺一个固定排除框适用于所有姿态。

如果机构必须在对准后移动到放置姿态，应验证该动作不破坏已建立的底盘到目标关系，并留出放置精度；需要最终复核时只能在目标可见、身份明确的条件下做。无法看清的下降过程不继续用猜测点控制底盘。

### 对准与动作分离

```text
CHECK_FIRST_LAYER_RECORD → FIND_BOTTOM_MATERIAL → ALIGN_STACK_TARGET
→ ZERO_AND_CONFIRM → ALIGNED → SEND_STACK_ONCE(data=2)
→ WAIT_ACTION_RESULT → COMMIT_STACK → RETURN_OBSERVATION
```

进入动作阶段后停止本次视觉输出。夹爪下降或上层物料遮住下层时，不因丢失而重新寻找并移动；只有动作结束并开始下一次独立任务，才清除旧关联、重新选目标。

平放与码垛均按公共流程执行多帧到位、归零停稳和新帧复核，动作发送前检查ready未过期。第二层完成的位置立即进入排除集合，不能用其上层顶面更新其他第一层目标的高度/尺度参考。

完成第一个码垛后，该位置已是两层；第二个任务只寻找下一种颜色的第一层目标。已完成位置作为排除语义，不要求所有可见物料高度一致。

## 7. 第一层与第二层任务记录

推荐由比赛上下文保存：

| 记录 | 含义 |
|---|---|
| `planned_color_to_position` | 任务码生成的第一层计划映射 |
| `first_layer[color].position_id` | 对应工位身份 |
| `first_layer[color].placement_status` | 未开始、执行中、动作已确认、失败、未知 |
| `first_layer[color].visual_check` | 未检查、可见且一致、冲突、遮挡等辅助证据 |
| `second_layer[color].stack_status` | 第二层动作进度，不由单次对准直接置成功 |

记录中心或框时带上图像时间与坐标空间，仅供后续关联、调试。车辆去原料区和粗加工区再返回后，必须重新检测底层目标；旧暂存图像像素不代表当前位置。

第一层记录缺失、结果未知、颜色位置冲突时，当前码垛任务明确报告原因，由调度保留阶段并恢复，不能自行换一个同色候选继续。

动作后的视觉检查仅提供可见性、颜色和明显异常证据。底层物料偏移或倾倒时不能通过夹爪/车身推动扶正；对准成功、C板程序结束和最终实际码垛稳定分别记录，均不冒充裁判评分。

## 8. 完整区域任务及离站边界

首批：按顺序完成三个圆环对准与真实放置 → 保存第一层状态 → 恢复离站参考 → 第二批取料路线。

第二批：按第三组颜色顺序，逐个选择第一层同色目标 → 对准与真实码垛 → 恢复离站参考 → 返回启停区路线。

平放/码垛后圆环可能不可见，不能沿用粗加工“物料取空后看三圆回中”的前提。底层物料的三中心组可以研究为视觉参考，但存在第一层放置偏差与第二层高度变化，必须按各自状态验证；也可后续使用里程计恢复入站参考。今天不写成已确定可用的回中算法。

当前建议采用与粗加工相同的局部位置返回接口恢复入站观察/离站参考，再按实际精度验收；这是暂存区的建议基线，不额外要求看到三个空环。仅有累计路程标量不足以实现二维返回，接口缺失时报告 `LOCAL_RETURN_UNAVAILABLE`，不假装回中成功。若以后要求视觉精修，需使用适合当前物料高度的参考或始终可见的固定特征，另行确定，不能混用地面环与顶面点。

独立调试只返回 `aligned`；完整阶段还需要三项物理动作确认及 `reference_restored`。暂不实现回中不意味着可以直接宣称整场暂存阶段完成。

```yaml
    min_edge_support_ratio: null
    min_supported_angle_sectors: null
```

两个圆检测 profile 需分别填写完整的公共霍夫参数；示例没有默认继承地面圆环半径给物料顶面。顶面 profile 是待评估备选，不代表首版默认双算法自动切换。

## 10. 调试与验收场景

1. 首批指定三个不同位置，对准目标按编号选择，成功后不自动登记真实放料。
2. 一、两个圆环被物料遮住后，下一空位身份仍可确认；不可确认时停车。
3. 使用示例任务码，第二批黑、红、浅蓝依次找 2、1、3 位，与第四组粗加工位置区分。
4. 画面中同时有底层和夹爪持有的同色物料时，底层被正确选中；分离失败返回遮挡/歧义。
5. 分别比较质心与顶面圆心，对支承面中心的偏差有实拍证据；不同方法不混用同一个未经验证的准心。
6. 完成一个码垛后开始下一个颜色，清理旧目标，不追踪已完成两层位置。
7. 相机丢帧、目标遮挡、取消均归零；动作阶段不重新发对准速度。
8. 动作接入后，平放/码垛成功以相应真实反馈及必要复核确认；回中条件满足后才离站。
9. 初始三件底层布局未确认时不发送2；逐件完成后，两层物料不能被当作下一件底层参考。
10. 1与2严格按operation发送，区域同步为storage；不因2不被支持而改发1。

## 11. 供后续编码的任务与状态接口建议

### 11.1 输入

平放整批任务：`run_id/task_id`、`operation=storage_place`、`colors[3]`为第一组、`positions[3]`为第二组。码垛整批任务：`operation=storage_stack`、`colors[3]`为第三组，并提供第一批已确认的颜色到位置映射及动作状态。

位置来自同一轮扫码任务与已提交记录；不在第二次进站重新用第四组构建暂存位置。码垛入口检查三个所需颜色都有已确认第一层记录。第一层计划与实际动作结果分开，未知状态不得默认完成。

纯视觉 `/vision/storage/align` 只返回对准，不接受机构执行请求。整批入口拟为 `/vision/storage/run_batch`，内部调用对准，再按operation发一次1（平放）或2（码垛）并等待结果。operation与指令必须固定匹配，不能沿用上一任务的动作值。另设 `/vision/storage/execute_item` 供显式单步动作调试，须同时 `enable_motion=true`、`execute_action=true`；只读观察和纯align均不发机构指令。消息/Action定义待编码时实现。

调度器只发起一次整批任务，不另发同一步1/2。整批启动前检查当前operation全部profile、第一层记录（码垛时）、动作反馈、区域同步及局部返回等依赖；通过未来通信确认 `work_area=storage` 再开始真实动作。通信层按区域及动作值转发，具体消息留给后续实现。

### 11.2 平放三次

```text
VALIDATE_FIRST_BATCH_AND_DEPENDENCIES → WAIT_ROUTE_RELEASE → SYNC_STORAGE_CONTEXT
→ ACQUIRE_EMPTY_STATION_LAYOUT
→ CAPTURE_LOCAL_REFERENCE
→ FIND_RING → ALIGN_GROUND_RING → ZERO_VERIFY
→ SEND_PLACE_ONCE(data=1) → WAIT_ACTION_RESULT → COMMIT_FIRST_LAYER
→ RETURN_OBSERVATION → 下一物料
→ 三个全部完成 → RETURN_DEPARTURE_REFERENCE → COMPLETED
```

平放前是否追加类似粗加工的空三环位置/角度精校准，可在固定姿态标定后配置；本次没有将其设为用户已确认的硬性要求。第一层全部放完后，不能再要求看到三个空圆环。

### 11.3 码垛三次

```text
VALIDATE_FIRST_LAYER_AND_DEPENDENCIES → WAIT_ROUTE_RELEASE → SYNC_STORAGE_CONTEXT
→ ACQUIRE_THREE_FIRST_LAYER_MATERIALS → VERIFY_COLOR_POSITION_LAYOUT
→ CAPTURE_LOCAL_REFERENCE
→ SELECT_SAME_COLOR_BOTTOM → ALIGN_STACK_TARGET → ZERO_VERIFY
→ SEND_STACK_ONCE(data=2) → WAIT_ACTION_RESULT → COMMIT_SECOND_LAYER
→ RETURN_OBSERVATION → 下一颜色
→ 三个全部完成 → RETURN_DEPARTURE_REFERENCE → COMPLETED
```

每次从当前新帧获取底层目标，不复用上一批或上一工位的像素坐标。放完后，当前颜色标为已码垛；下一目标不能被上层同色物料或车上持料替换。

### 11.4 动作、反馈和退出

两种模式共用 `/C/arm_command`（`std_msgs/msg/UInt8`）：平放发送1，码垛发送2，底盘速度使用 `/C/controll`。C板按值选择对应高度程序，处理完整出仓、放置、机构避让、转仓；上位机只等待 `/C/arm_status` 的本次完整动作结果。此反馈当前预留，没有接通就停在WAIT，不用定时器自动提交。

板间通信后续须保留并转发0/1/2，C板未支持2时不将其降级为1，也不判码垛已完成。高度及可选接触检测由电控实现；上位机不发逐步下降或仓盘转位命令。

取消前未发动作指令，可以归零结束；已发1或2后取消不等于下位机物理停止，必须保留动作未知/执行中状态，不直接交接路线。迟到或重复反馈不得重复完成同一物料。

对准丢失、过期、颜色歧义和机构未就绪时停车，不跳颜色，不默认超时成功。区域COMPLETED必须同时包含三次真实放置结果、离站参考恢复及速度归零，单次aligned不能替代。

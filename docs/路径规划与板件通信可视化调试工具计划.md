# 路径规划与板件通信可视化调试工具计划

编写日期：2026-10-25。状态：需求已确认，待实施；本次仅编写计划，不创建节点或修改运行代码。

## 1. 目标与已确认需求

在项目根目录新增 `tools/`，集中放置专用调试工具。本次规划其中的路径规划与 C 板通信可视化工具。

工具通过浏览器使用。一条命令启动网页服务、调试控制节点、现有路径规划节点与现有 C 板通信节点；用户在页面选择模式和参数，点击同一个“启动”按钮执行。两种模式都驱动真实小车，使用真实 C 板通信和真实里程反馈。

左侧完整展示根目录的 `屏幕截图 2026-10-15 220523.png`，保留地图、尺寸和位置编号；叠加起终点、规划路线、小车连续估算位置和朝向、已走轨迹。右侧提供模式、参数、启动／停止／复位按钮及运行状态。

初版范围：

- 自由行走：人工指定当前节点、当前朝向、终点，选择是否按终点工作方向对齐，调用现有规划器执行一次导航。
- 模拟比赛：人工选择起点和最终停车区，按现有比赛顺序真实行驶；扫码和区域工作均由停车等待 3 秒替代。
- 两种模式初版均使用全通地图，不识别障碍，不启动雷达、相机或机械臂任务。
- 模拟比赛预留封路数据入口，后续可在右侧选择道路；初版不实现道路选择界面与非空封路执行。
- 沿用启动时现有规划 YAML 中的速度、减速、容差及边长，不提供网页调速，也不另存一份运动参数默认值。
- 支持停止和复位；停止后重新摆车，从头开始，不支持暂停后续跑。

## 2. 地图、朝向与位置约定

方向全部以截图为准：上为 UP、右为 RIGHT、下为 DOWN、左为 LEFT。

```text
7 ── 4 ── 1
│    │    │
8 ── 5 ── 2
│    │    │
9 ── 6 ── 3
```

| 节点 | 用途 | 作业时固定车头朝向 |
| --- | --- | --- |
| 1 | 截图“启停区1” | 比赛出发朝 DOWN，最终停车无朝向要求 |
| 3 | 截图“启停区2” | 比赛出发朝 UP，最终停车无朝向要求 |
| 2 | 二维码区 | DOWN，左侧（+vy）面向地图右方的二维码板 |
| 4 | 原料区 | LEFT，右侧（-vy）面向地图上方的原料区 |
| 6 | 粗加工区 | RIGHT，右侧（-vy）面向地图下方的粗加工区 |
| 8 | 暂存区 | DOWN，右侧（-vy）面向地图左方的暂存区 |
| 5、7、9 | 通行节点 | 无作业朝向 |

工作朝向固定，不在网页上提供编辑。启动调试规划器时覆盖这四项工作朝向，保留正式配置文件的其他内容，不要求用户改动正式比赛配置。

截图中的启停区名称和现有配置 `left/right` 容易混淆，网页统一使用“启停区1（节点1）／启停区2（节点3）”。后端按节点编号转换。

用户手动将车放到所选节点，并按所选／约定方向摆放。软件初始化只建立地图位置与当前 yaw 的对应关系，不让车辆自动寻找起点，不要求 C 板 yaw 本身归零，也不复位板端原点。

## 3. 页面设计

### 3.1 左侧地图

- 原图等比例完整显示，覆盖层与原图使用同一坐标变换，窗口缩放后标记仍对应正确位置。
- 以截图各编号所在位置的道路中心作为九个节点锚点；单独保存图像像素锚点，避免强行用均匀网格覆盖截图。
- 用不同样式区分起点、终点、当前规划路线、已走轨迹和小车朝向。
- 连续移动图标依据真实反馈更新，不按预计耗时播放动画。
- 显示“里程估算位置”；反馈过期时冻结最后位置并显示失效状态。人工摆车、复位或中断后，不继续假设旧位置有效。

### 3.2 右侧设置与控制

| 项目 | 自由行走 | 模拟比赛 |
| --- | --- | --- |
| 模式选择 | 自由行走 | 模拟比赛 |
| 起点 | 节点1～9 | 启停区1／启停区2 |
| 当前朝向 | UP／RIGHT／DOWN／LEFT，配中文方向 | 根据起点固定显示，不可编辑 |
| 终点 | 节点1～9 | 独立选择启停区1／启停区2 |
| 终点工作对齐 | 可勾选，仅终点为2／4／6／8时可用 | 四个工作区始终按固定朝向对齐 |
| 地图 | 全通 | 全通，说明后续支持封路设置 |
| 操作 | 共用启动、停止、复位 | 共用启动、停止、复位 |

未勾选终点工作对齐时，自由行走保持本次出发的车头朝向，通过前进、后退和横移完成路径；沿途经过工作区不额外转向或等待。勾选后只在终点对齐。终点为非工作节点时清除并禁用该勾选。

运行、停止处理中和复位处理中锁定模式及运动参数，禁止连续点击重复启动。停止后要求人工恢复现场并复位。正常完成后允许设置下一次任务并再次启动，每次新运行都重新建立所选初始位姿及反馈基准。

### 3.3 右侧状态

显示：连接与就绪状态、当前模式、当前阶段、当前目标、当前节点或所在道路、连续估算位置与朝向、等待倒计时、本轮耗时、路线节点序列、执行结果、错误原因及最近事件日志。

通信项显示 C 板连接、PC 控制权、里程有效性、运动许可和故障原因；数值项显示累计路程、连续 yaw、当前下发速度及本次加载的速度配置。`motion_allowed` 表示通信桥允许运动，不作为物理停稳证明。

## 4. 两种执行流程

### 4.1 公共启动流程

1. 校验设置、规划器服务与进程身份、通信健康、PC 控制权、真实新鲜里程，以及本工具对最终速度话题的独占情况。
2. 为本轮生成新的运行身份，登记当前操作，持续输出零速；初始化规划器位置与 yaw 基准，等待复位后的新里程样本。
3. 发布与本轮身份一致的全通地图快照，查询确认规划器已接受该版本。
4. 确认规划器空闲、配置和反馈就绪后派发当前模式的第一条路线。

这些步骤由一次“启动”触发完成，不要求用户在终端手工发布地图或逐段调用服务。尚未连接 C 板时页面可以打开并显示等待原因，但不能启动运动。

### 4.2 自由行走

按用户设定的起点与朝向初始化，规划到所选终点；到达后按勾选决定是否执行终点工作对齐。对应任务完成、输出归零且规划器释放控制后结束，不增加 3 秒区域等待。

起终点相同时也允许执行：不对齐则作为零路程任务完成；要求对齐则只进行必要转向。不能由于空行动链而卡住或误报失败。

### 4.3 模拟比赛

不启动正式比赛的真实业务依赖；在调试节点中使用明确的串行阶段表组织以下流程，节点号与现有 `agv_mission/stages.py` 对照维护。

| 顺序 | 行驶目标 | 到达后的行为 |
| --- | --- | --- |
| 1 | 所选启停区 → 2 | 朝 RIGHT，等待3秒，代替扫码 |
| 2 | 2 → 4 | 朝 UP，等待3秒，代替第一批取料 |
| 3 | 4 → 6 | 朝 DOWN，等待3秒，代替第一批粗加工 |
| 4 | 6 → 8 | 朝 LEFT，等待3秒，代替第一批暂存平放 |
| 5 | 8 → 4 | 朝 UP，等待3秒，代替第二批取料 |
| 6 | 4 → 6 | 朝 DOWN，等待3秒，代替第二批粗加工 |
| 7 | 6 → 8 | 朝 LEFT，等待3秒，代替第二批暂存码垛 |
| 8 | 8 → 独立选择的最终启停区 | 不要求朝向，停车结束 |

总计 8 条导航、7 次等待，固定等待总时长 21 秒。每次区域到访只等一次3秒，不按三次抓取或六次抓放分别等待。

等待必须在对应导航与终点转向完成、规划器报告释放后开始，使用单调时钟计时，期间持续输出零速并检查通信健康。等待期间停止会取消倒计时，不能再派发下一阶段。用异步定时状态处理，不在 ROS 回调或网页请求中阻塞休眠。

此工具验证的是比赛路线和朝向，不生成虚假的二维码或抓放成功结果，也不把调试完成发布为正式比赛完成。

## 5. 现有实现核对与复用方式

已核对源码：`agv_planning` 实现规划、速度计算、动作合并、减速和里程闭环；`agv_cboard` 实现 USB CDC 通信、真实反馈及故障锁；正式 `agv_mission` 具有真实业务依赖，不能直接在缺少这些模块时运行完整流程。

采用“调试控制节点 + 原规划器 + 原通信桥”，调试节点承担本工具的阶段管理和速度转发，复用原规划器的路线算法与执行逻辑，不复制导航控制器，也不放宽正式比赛的真实来源检查。

```text
浏览器 ←HTTP／WebSocket→ 调试控制节点
                           │ 目标／停止／复位／运行查询
                           ↓
                       现有路径规划器 ← /C/odometry ← 现有C板通信桥 ← C板
                           │ 内部速度与执行状态
                           ↓
                       调试控制节点 → /C/controll → 现有C板通信桥 → C板
```

所有运动决策、超时和3秒计时在小车端运行。浏览器只提交意图并展示状态；网页刷新或网络时延不能改变运动控制频率。

### 5.1 规划器复位的必要扩展

现有 `ExecutorContract.reset` 仅接受 `home_node=1/3` 及对应 DOWN／UP 朝向；绑定非空 `run_id` 后，规划请求又要求 `start=0`。因此不能直接用现有复位契约满足自由行走的任意起点和朝向。

计划增加默认关闭的调试初始化选项，仅由工具启动的规划器开启：允许复位到节点1～9和四个合法方向。继续复用 `ResetExecutor`，保留新轮身份、比较并交换、幂等、空闲检查与复位后新里程要求。正式启动的默认规则仍只允许两个比赛启停区。

初始化成功后，两种模式统一使用 `start=0`、空 `current_heading` 发送导航，连续各段使用规划器维护的位置与反馈朝向。所有目标显式填写节点编号，不依赖 `goal=0` 的启停区语义。

### 5.2 接口隔离与速度出口

调试启动统一将规划相关服务、话题、地图和租约心跳映射到 `/tools/route_debug/...`。现有契约里的绝对服务名和 `/mission/heartbeat` 需要逐项显式 remap，不能只设置节点 namespace。

| 接口用途 | 既有接口 | 调试用途 |
| --- | --- | --- |
| 导航 | `/route/plan` | 映射到工具私有服务，提交目标、终点对齐和唯一任务ID |
| 路线、状态、速度 | `/route/path`、`/route/execution_status`、`/route/control` | 映射到工具内部话题 |
| 查询、停止、复位 | `/route/get_runtime`、`/route/stop`、`/route/reset_context` | 映射到工具内部服务 |
| 地图 | `/map/blocked_edges` | 映射到工具地图话题，发布本轮全通快照 |
| 租约 | `/mission/heartbeat` | 映射到工具心跳话题，携带本轮身份 |
| 最终底盘速度 | `/C/controll` | 调试控制节点作为本次调试的唯一发布者 |
| 真实反馈 | `/C/odometry`、`/C/status` | 原通信桥发布，工具和规划器按需订阅 |
| 通信故障解除 | `/C/reset_fault` | 满足恢复条件后由复位流程调用 |

统一入口不启动正式 mission，也不重复启动已有串口桥。启动前检查是否存在其他最终速度发布者、冲突服务或硬件桥；发现冲突时报告原因并拒绝接管，不停止用户已有进程。运行中发现竞争发布者，进入故障并请求停止。

调试节点仅转发匹配本轮、当前任务、执行器进程身份、来源及递增序号的新鲜速度，核对时间戳，拒绝过期、重复、乱序和旧任务反馈。不循环重发缓存非零速度；待命、等待、完成、停止与故障期间持续发布零速。

导航响应表示接受，不代表到达。派发前登记任务，处理终态先于响应的情况；以匹配的终态及后续运行查询确认完成和释放。响应丢失时查询当前身份的执行结果，不盲目重发运动请求。执行器进程重启或身份改变时结束本轮并要求复位。

## 6. 连续位置与轨迹显示

现有 `/C/odometry` 只有累计路程和连续 yaw，不能单独还原地图二维坐标；`CBoardStatus.fb_mm/ud_mm` 也不能未经协议确认就当作底盘 x/y。初版使用“当前路线运动段 + 实际累计路程增量 + 连续 yaw”估算地图位置。

为避免前端猜测运动段开始时间，规划器增加可选、默认关闭的调试进度输出，工具入口开启，建议10 Hz。该输出直接读取现有执行循环的运动段和基线，不影响50 Hz控制。按需在 `agv_interfaces` 增加进度消息，包含：

- 本轮、任务、执行器进程身份，采样时间及执行状态。
- 当前合并运动段序号、类型、起止节点、起始／目标朝向。
- 该段总量、实际进度、段起始累计路程与 yaw、当前反馈值和有效性。

进度发布与运动段切换在同一执行上下文取快照；每次开始、结束、转向和中止均更新状态。两个同向前进合并成2400 mm或两个转向合并成180°时，显示仍与真实执行段一致。

平移时按当前合并段累计距离，在对应路线边上分段插值；分段使用规划器实际加载的边长，再映射到截图像素锚点。转向时位置保持该节点，朝向按真实连续 yaw 差更新。前后左右平移均沿路线方向移动图标。

状态失效、累计距离回退或任务身份不匹配时停止更新并显示原因；中止后保留最后估算轨迹，但标记位置不再可用于自动续跑。估算位置只用于观察，不反向作为规划器定位输入，也不声称能识别横向偏离、打滑或提供绝对定位。

## 7. 状态、停止与复位

建议状态：待命、初始化中、导航中、工作等待中、停止中、已停止、复位中、已完成、故障。状态更新统一串行处理；HTTP命令、ROS回调及定时器通过队列交给控制状态机，避免网页线程直接操作执行上下文。

### 7.1 停止

页面按钮标为“停止”，含义是结束本轮，不提供继续。

1. 先关闭阶段推进和速度转发权限，立即输出零速，取消待执行阶段及等待计时。
2. 对当前导航发送匹配身份的停止请求，查询确认执行器已停止并释放。
3. 已确认软件停止后显示“已停止，重新摆车并复位”；若未能确认，显示停止未确认和具体故障，保持零速，禁止重新启动。

停止服务被接受及零速已发布均不等同于物理车辆已经停稳；页面据实显示软件与通信状态。

### 7.2 复位

用户先人工把车摆到页面指定的初始节点并调整车头；复位按钮旁固定说明这一要求，不另加每轮确认弹窗。

复位确认执行器空闲，清除本轮阶段、倒计时、路线和旧回调上下文，重新建立初始位姿及反馈基准、发布全通地图，最终返回可启动状态。复位不自动行驶、不恢复旧路线、不发送机构命令。

若存在 C 板通信故障锁：先完成停止与规划上下文复位，确认通信、PC控制权和反馈恢复且本工具持续发送零速，再调用 `/C/reset_fault`；解除后重新检查新鲜里程和地图，全部就绪才允许启动。若失败，保留故障原因，不反复自动清锁。

### 7.3 断线与异常

- 里程过期、无进展、规划失败、C板掉线、失去PC控制权、反馈中断、服务状态未知：停止推进，归零并请求停止，不自动重试或续跑。
- 浏览器控制连接采用单一控制会话和应用心跳；控制会话断开／超时则停止本轮。重连只获取状态，不自动恢复运动；其他页面可以只读查看。
- 后端退出时尽力发送零速并停止规划器；异常崩溃依赖规划器租约及现有通信指令超时停车，不将网页连接当作底盘唯一看门狗。
- 启动／停止／复位请求使用操作ID并在后端串行处理，浏览器重试不能产生重复运动。通信刷新与前端更新建议10 Hz，心跳超时值在实施配置中明确记录。

## 8. 配置与启动安排

工具启动参数包括 HTTP 监听地址／端口、规划 YAML 路径、C板 YAML 路径、可选串口覆盖。网页同源提供静态资源和状态连接，不要求浏览器配置ROS，也不依赖额外 rosbridge 服务。

启动时优先明确加载项目源码中的 `ros2_ws/src/agv_planning/config/planner.yaml`，允许指定其他文件；不要无提示地读取旧安装副本。只叠加工具必需的工作朝向、接口映射及调试选项。

本次核对到的运动配置如下，仅作编写时快照，不是工具硬编码值：

## 12. 验证与验收标准

| 场景 | 预期 |
| --- | --- |
| 启动工具 | 一条命令启动全部调试依赖，输出网页地址；未连接硬件时页面可用、运动不可启动 |
| 配置读取 | 采用用户最新YAML参数，界面和日志能核对实际速度及配置来源 |
| 自由行走 | 任意1～9起终点、四种初始朝向均能正确构造任务；只按选项在工作终点对齐 |
| 同点任务 | 无需转向时完成零路程任务；需要对齐时完成原地转向，不卡住 |
| 比赛组合 | 起点1／3、终点1／3四种组合，均按8条导航、7次等待结束，终点无方向约束 |
| 工作朝向 | 车头2下、4左、6右、8下；二维码区左侧作业，其余三区右侧作业；只在目标工作区转向，途中经过不进入工作阶段 |
| 等待起点 | 只能在导航及终点转向完成并确认释放后开始计时，不以服务接受作为到达 |
| 连续显示 | 前进、后退、横移、90°与180°转向、合并直线段显示正确；反馈过期时不继续动画 |
| 重复与竞态 | 重复启动、旧轮结果、旧进程反馈、终态先于服务响应不重复行驶或错误推进 |
| 停止 | 导航中和等待中均可停止，后续阶段不再派发；未复位前拒绝重开 |
| 复位再运行 | 重新摆车后可启动新轮，旧计时器、旧任务和旧地图不影响新轮 |
| 故障恢复 | 断链、控制权变化、里程异常时停车，不自动续跑；故障锁需按恢复流程解除 |
| 连接与进程退出 | 控制页面失联、后端退出、规划器重启均不维持旧运动；重连不恢复运行 |
| 输出独占 | 已有mission或其他控制发布者时拒绝开始，工具不关闭用户进程 |
| 业务边界 | 不访问相机／雷达，不下发机构命令，不伪造正式比赛成功 |

自动验证聚焦阶段顺序与等待时序、身份过滤、复位契约、停止竞态及里程显示转换；ROS联调使用独立domain和伪串口验证原桥接链路，不连接物理车辆。构建涉及的接口包与规划包，并检查正式启动默认仍保留原有复位限制。

实车验收另行在现场完成，核对方向、距离、转向、停稳和断线停车效果；软件或伪串口验证不作为实车精度与物理停车验收结果。

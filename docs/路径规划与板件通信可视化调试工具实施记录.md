# 路径规划与板件通信可视化调试工具实施记录

对应需求与范围见 [实施计划](路径规划与板件通信可视化调试工具计划.md)。当前已完成代码与软件联调，尚未开展真实小车验收。

## 已交付

- 根目录 `tools/` 及 `tools/route_debug/` 专用调试工具，一条命令启动网页、调试控制器、现有规划器与现有C板通信桥。
- 浏览器左侧完整原截图，叠加起终点、路线、连续估算位姿与轨迹；右侧两种模式、统一启动／停止／复位、阶段、倒计时、通信与运动配置显示。
- 自由行走支持1～9任意起终点、四种初始朝向、可选终点工作对齐，以及同点零路程／转向任务。
- 模拟比赛支持两个启停区独立选择起终点，执行 `起点→2→4→6→8→4→6→8→终点`，7次固定工作朝向对齐后各等待3秒。
- 使用真实里程与原通信协议；不启动扫码、雷达或抓放，不生成正式比赛成功结果。
- 停止后要求复位重来；处理控制页面失联、通信故障、反馈超时、执行器重启、重复操作与旧轮消息。
- 初版地图全通；封路快照生成位置及请求字段保留，非空封路值明确拒绝。

运动参数读取源码 `ros2_ws/src/agv_planning/config/planner.yaml` 或用户传入文件，不修改用户速度。工具固定覆盖四项作业朝向和调试接口。

## 实现相对计划的调整

网页实时连接使用 Python 标准库 HTTP + SSE 状态推送与应用心跳，替代原计划的轻量WebSocket服务库。浏览器控制请求仍使用HTTP，控制和计时在小车端处理；因此无需增加pip依赖或前端构建步骤。

规划器增加两项默认关闭的参数：`debug_allow_any_pose`、`debug_publish_progress`。前者允许工具初始化任意节点和朝向，后者输出10 Hz实际合并运动段快照；正式启动保留原启停区复位规则。新增消息 `RouteExecutionProgress` 仅用于显示。

# 公共视觉与伺服约定

日期：2026-10-20。本文是三个区域方案共享的设计约定；接口、配置及状态机均待实现。

最新执行规格：粗加工的批次状态机、采放后自动转仓和离站前三环三自由度校准，详见[02_粗加工区放料与取回方案.md](02_粗加工区放料与取回方案.md)。单点伺服不主动转向、用yaw监视偏差；最终三环校准显式控制旋转。

## 1. 职责与执行边界

一个 `work_vision_node` 独占固定主相机，内部承载 `raw_task`、`coarse_task`、`storage_task`。公共代码处理采集、物料检测、圆环检测、目标关联和伺服；三个任务保留不同的状态流程、配置和独立调用入口。

建议继续放在现有 `agv_perception` 包内组织，避免为了三个逻辑任务再建三套相机程序。模型以后只加载一份，首版无需模型或独立推理服务。

| 层次 | 负责什么 |
|---|---|
| 比赛调度 | 15 阶段、批次、任务码、当前子步骤、真实动作进度、第一层颜色位置映射 |
| 区域任务 | 检查任务参数、选择本区域目标、判稳、对准、返回该次结果 |
| 公共检测 | 从图像产生多个候选，携带位置、类别、几何和有效性 |
| 公共伺服 | 当前选定目标误差到连续底盘速度，归零与交接 |
| 未来机构执行 | 抓放、升降、入仓及真实动作结果；不能由视觉结果代替 |

比赛时调度器向对应区域的 `run_batch` 提交一次整批请求：原料三次采、粗加工三放三取、暂存三次平放或三次码垛。区域执行器内部调用公共对准，按顺序发送机构指令并等待结果，调度器不得同时再发送同一步采放命令。`align` 入口专供单目标纯视觉调试，不自动发送机构指令；显式单步动作调试只执行一件。

调度器保存本轮规范任务记录及第一层映射；区域执行器保存执行中状态，按 `run_id/task_id/step_id` 上报已确认步骤，调度幂等提交。不得让两者各维护一份可独立推进的物料索引。模块不自行推进全局 s，也不自行通知另一个区域开始工作。

## 2. 图像、坐标和目标观测

主相机统一使用 720p（1280×720），原料、粗加工、暂存全部保持这一分辨率。采集采用现有相机程序的思路：独立线程持续读帧，只保存最新图像。准心、ROI、半径与像素阈值全部按 1280×720 配置，不在任务中切换采集分辨率。下文对去年分辨率的说明仅描述旧源码。

每份观测至少带以下语义，不强制现在确定具体 ROS 消息类型：

| 字段 | 说明 |
|---|---|
| `frame_seq`、`stamp` | 对应实际新采集帧；重复读取同一帧不算新的稳定证据 |
| `valid`、`reason` | 无目标、颜色冲突、遮挡、关联歧义、图像过期等必须可区分 |
| `target_kind` | `material` / `ring_station` / `three_ring_feature`（最后三环校准） |
| `color_id`、`position_id` | 与本任务相关的颜色、工位；不适用时明确为空 |
| `u`、`v` | 当前目标中心，浮点像素 |
| `center_method` | `contour_centroid` / `min_area_rect` / `top_circle` / `hough_ring` 等 |
| `area`、`bbox`、`radius` | 按检测方式提供，用于筛选和调试 |
| `quality` | 规则打分或模型分数，注明来源；规则分数不是概率 |

图像坐标原点左上，u 向右、v 向下。裁剪 ROI 后的检测点加回 ROI 偏移；若对 ROI 缩放，先反缩放再加偏移。模型以后须撤销缩放和 letterbox 填边。所有最终误差计算必须使用与准心配置相同的坐标空间。

默认使用原始采集图像坐标。如以后启用畸变矫正，应统一切换检测、预览、ROI、准心与标定，不能将矫正图中的点与原图准心混用。

最新帧缓存不能消除相机驱动内部积压。实现时记录采集来源、帧序号和可获得的采集时间，测量端到端延迟；不能在处理旧帧时重新打上“现在”的时间冒充新帧。相同静态画面的像素值可以完全相同，不能仅按图像哈希判断是否采集了新帧。速度新鲜度由独立定时看门狗检查，采集或霍夫检测阻塞时也必须能够停止旧速度。

## 3. 物料检测算法

### 3.1 HSV + 轮廓：今日基线

```text
读取新帧 → 作业 ROI → 适度平滑 → BGR 转 HSV
→ 当前目标颜色的一个或多个阈值掩膜取并集
→ 二值掩膜开闭运算 → 外轮廓/连通区域
→ 面积、宽高、形状、边界完整性筛选 → 目标关联 → 中心点
```

一个颜色支持多个 HSV 区间。六色编号固定为红1、黄2、蓝3、绿4、黑5、浅蓝6；具体阈值由后续外部工具填写。本方案不讨论阈值生成与调整。

统一使用OpenCV常规8位 `COLOR_BGR2HSV`，H取0–179、S/V取0–255，不混用HSV_FULL或角度制阈值。矩计算必须检查 `M00>epsilon`，空轮廓、退化轮廓均返回无效。面积/尺寸门限按各作业高度的profile分别允许覆盖，不能用地面物料尺度统一过滤原料与码垛目标。不同色掩膜明显重叠、身份不能唯一确定时报告冲突；不在本次设计阈值标定工具。

首版在物料profile中明确填写 `min_area_px2/max_area_px2/min_circularity`，取值由各高度图像验证；公共material仅提供参数结构和形态学默认值，不替代各区域尺度标定。建议运行时保持已验证的曝光、白平衡等取像设置，避免自动变化导致HSV掩膜大幅波动；只记录和核查取像条件，本轮不实现相机调参或HSV工具。

先在二值掩膜上做形态学处理，避免直接腐蚀 HSV 各通道造成不易解释的颜色变化。使用小核去散点、补小洞；不照搬某颜色连续膨胀六次的设置，防止改变轮廓中心或连接相邻物体。

面积只是一项筛选依据。先按区域和任务身份排除夹爪、车上物料、场地背景，再比较候选；不能始终选全图最大的同色区域。候选歧义无法排除时返回 `AMBIGUOUS` 并停车。

### 3.2 中心点怎么选

| 方法 | 做法 | 适用与局限 |
|---|---|---|
| 轮廓质心 | `M10/M00, M01/M00` | 简单快速；完整、对称物料俯视时作为首版中心；侧面、阴影、缺口会偏移 |
| 最小外接矩形中心 | `minAreaRect(contour).center` | 西安理工路径，适合较完整轮廓；对伸出的小边缘、截断轮廓敏感 |
| 最小包围圆中心 | 对轮廓求包围圆 | 可作对照调试；离群轮廓点会影响，不保证是上表面中心 |
| 顶面圆心 | HSV 给候选 ROI，灰度图局部霍夫圆，颜色和尺度复核 | 圆台物料抓取、码垛精定位候选；必须确定检测到的是顶面边缘 |
| 椭圆拟合 | 对足够完整且同属顶面的轮廓拟合椭圆 | 倾斜明显时可选，暂不作为近似垂直俯视的首版默认 |

今日先用质心跑通闭环，同时保留 `center_method`。对同一任务不得每帧在不同中心定义之间随意切换。若要启用顶面圆心，应形成独立 profile 并验证；圆心失败时停车/重新获取，不静默改用另一种中心继续抓取。

### 3.3 “先找颜色”和“先找圆”的区别

- HSV 优先：先确定指定色的物料区域，再按需在局部找顶面圆。今日推荐，颜色与任务身份明确，计算范围小。
- 霍夫优先：像江苏程序，先找若干圆，再统计圆内颜色并按目标色筛选。物料顶部轮廓清晰时可用，但可能先找到车轮、圆环或夹爪圆形结构，且缺色时仍须拒绝。
- 几何复核不是多算法投票：一个错误的 HSV 目标可能也含圆形边缘，因此仍需作业 ROI、类别和位置约束。

### 3.4 深度学习后端：后续路径

模型输出物料候选 → 置信度/类别过滤及重叠候选处理 → 坐标还原 → 公共目标选择 → 公共伺服。模型使用自带后处理时不重复做一遍相同的 NMS。

可选三种输出：六颜色类别的检测框；统一物料类加 HSV 判色；实例分割或顶面中心关键点。普通检测框中心可用于粗定位，不能默认等于夹取中心或码垛支承面中心。若最终精度由顶面中心决定，可让模型给 ROI、几何法精定位，或训练中心关键点/顶面分割。

首版 `material_backend: hsv`；以后新增 `model`，保持候选与目标观测接口不变。模型不可用时明确报告，不擅自切换算法后仍沿用旧中心标定。模型训练、数据采集和部署不纳入今天范围。

## 4. 圆环检测与工位身份

### 4.1 推荐流程

```text
工位 ROI → 灰度 → 高斯平滑 → 霍夫圆候选
→ 半径、ROI、边缘支持检查 → 近圆心候选归并
→ 工位排列/间距检查 → 工位编号关联 → 选择 position_id
```

首版建议标准 `HOUGH_GRADIENT`，江苏代码有直接参考；`HOUGH_GRADIENT_ALT` 是西安理工和第三套工程的备选。两者的 `param2` 含义与取值范围不同，不能沿用同一配置数值。标准方法的 `param1` 对应内部边缘检测高阈值，`param2` 是圆心累加器阈值；ALT 的 `param2` 是接近 0—1 范围的圆形完善度门槛。参数需随实际图像验证。

不必为了“多边缘”默认堆叠 CLAHE、梯度和强二值化。先灰度模糊检测；必要时再比较增强分支，保留独立配置，避免细圆环被膨胀或二值化合并。

### 4.2 同心圆归并

一个编号位置含多条同心环，不能将它们当作多个放置工位。按圆心距离门限归并，门限应明显小于相邻工位间距；避免距离链条把不同工位串成一组。组内取中心中位数或受支持程度约束的代表圆心，同时保留半径列表用于调试。

霍夫算法的 `minDist` 可能已抑制一部分近圆心结果；归并仍处理残留重复，不要求每条同心环都被检测到，也不以检测环数等于六作为必要条件。

### 4.3 编号不能从颜色猜

今年圆环位置标 1、2、3。首版在固定作业朝向下，看到完整三个工位后，沿工位排列方向排序，再使用已核对的图像顺序到编号映射。该映射必须按实际安装和场地核对，不能默认图像左到右就是 1、2、3。

首次关联要求完整且无歧义的三个工位。之后目标部分被遮挡时，可按已知身份与当前可见结构重关联；不能把剩余两圆重新命名为 1、2。新帧匹配允许有限的整体图像位移，匹配存在歧义则停车重建。保存的像素坐标只作关联参考，不能当作底盘运动后的当前测量。

若现场无法固定编号与图像顺序，后续增加数字识别；不能在编号未确认时任选最近圆。基于已知间距推算被遮挡圆心只作为以后增强，首版不把推算结果当真实观测发速度。

## 5. 视觉伺服：今日采用限幅 P 控制

### 5.1 坐标映射

每种 operation 使用自己的准心 `u_ref,v_ref`。设当前测量为 `u,v`：

```text
e = [u_ref-u, v_ref-v]^T
[vx, vy]^T = B × e
omega = 0（单点伺服不主动请求旋转；不等于闭环锁定车头）
```

`B` 是包含轴交换、正负号和比例增益的 2×2 矩阵，单位 `(m/s)/pixel`。它不是直接拿相机内参计算的空间坐标变换。通过实际低速移动确认“哪个底盘方向使哪个像素误差减小”，再配置 B；禁止默认像素 x 就是底盘 x。若用观测运动模型 `p_dot=Jv`，比例反馈应满足 `B=λJ^-1` 的方向关系。

输出沿用自定义 `ControlCommand`：`vx_mps` 向前为正、`vy_mps` 向左为正、`omega_deg_s` 逆时针为正。矩阵乘积输出再做速度限幅。检测点单一且未给其他姿态约束时，不同时求解三个平面自由度；首版不凭单点误差控制偏航。

首版用新鲜yaw反馈监视作业朝向，偏离入站/局部返回确认的参考超过 `heading_guard.max_error_deg` 时，三路速度归零并返回 `HEADING_OUT_OF_RANGE`，先恢复作业朝向再重新获取目标。`omega=0`自身不能抵抗轮差或外力漂移。若C板已闭环锁定yaw，须明确其与速度指令的契约；不得另外启动一个并行ROS速度发布者“补角度”。最终三环校准显式接管omega时不能被固定yaw锁定抵消。

### 5.2 为什么先用 P，而不直接搬 PID

第三套源码先对误差距离用远近两组 PID，再沿误差方向分解速度，控制的是机械臂；其误差符号、速度单位和无显式 dt 的离散实现都与当前底盘不同。

今日先采用 P：误差大时受限幅，接近目标速度自然减小，参数少。若实测远近响应需要区分，可增加两段增益并防止边界反复切换；存在确定的稳态偏差或超调问题后，再决定积分或微分，并明确 dt、积分限幅和状态清零。

### 5.3 完成与退出

有效当前目标满足 `sqrt(ex²+ey²) < tolerance_px` 才有资格判为对准。自查后将首版建议改为至少3张连续新帧，并同时覆盖 `min_alignment_time_s`；单帧只适合观察调试，不作为完整动作的默认许可。实际帧数与时间按检测抖动和节拍验证，不沿用旧任务循环“执行二十次”等同于二十张新图。

完成顺序统一为：连续新帧满足误差条件 → 发零速度 → 等待 `zero_settle_time_s` 且确认停车 → 使用停车后的新帧重新检查身份与误差 → 停止本任务发布 → 返回 `aligned`。误差重新超限则恢复对准，丢失则清计数。原料还必须重新完成静止观察窗口；完整抓取许可见原料方案。

目标丢失、图像过期、身份切换、任务取消或异常时，立即归零、停止无依据的控制并重置相关计数。重新获取必须用新图像；滤波预测、缓存点和零坐标都不能替代有效观测。

首版不默认使用卡尔曼。需要平滑时，先比较原始中心和轻量低通/短窗口中位数的抖动与滞后；滤波器按目标身份分开，任务切换清零。若伺服选择了平滑中心，停车后到位复核与原料停稳仍检查原始有效测量，不能靠平滑掩盖运动。

完整任务在最终复核后立即进入发送步骤，复核结果携带目标身份、frame_seq和时间，只在 `max_ready_age_s` 内且控制权、机构状态未变化时有效；过期或有新帧反证就撤销并重新复核。原料不能把一次 `ready_to_grasp` 长期缓存后才抓取。动作发出后不因视觉遮挡而自行移动底盘。

像素阈值必须通过实际位置误差和机构重复精度验收，不直接等同于比赛环数。固定安装、相同取像设置、对应作业高度与机构观察姿态，是准心及B矩阵生效的前提。

## 6. 控制权与动作阶段

三个区域共用忙碌状态，只允许一个任务输出速度。路线执行结束并归零后，视觉任务才接手；视觉结束归零后，路线或机构才接手。非活动任务不持续发零速度干扰当前控制者。

未来抓放动作启动后，视觉进入 `WAIT_ACTION_RESULT`，停止输出本次对准速度。夹爪下降遮挡时不能自动重新对准。只有动作结果已确认且下一次任务明确开始，才重新获取目标。机构结果未知时保留当前子步骤，不无条件重试物理动作。车载仓盘转位拟封装在每次采/放后，动作完成必须包含机构避让和转仓就位；具体顺序契约及异常规则见粗加工规格第3节。

正常归零不能覆盖进程崩溃；未来通信接收方仍需速度新鲜度检查和断流停车。本文不新增通信节点或硬件协议。

一项已由本区域发出的机构动作尚未结束时，区域不得释放“允许底盘移动”的锁。第三件后的观察位与离站参考相同，可把该次返回结果用于离站判据，不再重复执行一次相同返回；粗加工仍需接着完成最后三空环精校准。

视觉纠偏仍须限制在允许的灰色车道及机构可达范围内。整批执行前校验当前区域的允许局部平移/偏航范围；将要越界、目标需越界才可达时停车报告 `WORKSPACE_LIMIT`，不能为了误差归零无限追踪。仅作业图像ROI不足以证明车身仍在车道内。局部位置反馈、区域边界和车身轮廓的实现由运动层接入，不在视觉中新增地图规划。

## 7. 任务接口建议

建议三个独立 Action 入口：`/vision/raw/align`、`/vision/coarse/align`、`/vision/storage/align`；名称是设计建议，当前仓库尚未实现。

- Goal：`operation`、`profile`、`batch`、`item_index`、`color_id`、`position_id`、`enable_motion`；关联当前比赛任务身份。
- Feedback：子状态、当前目标有效性与身份、像素位置与误差、判稳状态、原因。
- Result：`status`、`reason`、`aligned`；不返回未经确认的 `picked/placed/stacked`。

整批另设 `/vision/raw/run_batch`、`/vision/coarse/run_batch`、`/vision/storage/run_batch`；实现为可取消的长任务入口。整批Result含已确认步骤、失败/未知步骤及离站参考状态。只读观察、纯align、单步带动作、整批四种模式必须显式区分；单步带动作另设 `/vision/<area>/execute_item`，仅允许 `enable_motion=true` 且 `execute_action=true`，纯align拒绝执行机构请求，只读模式不发送机构指令。

只识别调试可持续显示中心、误差和预计速度，不发布控制；结果为 `observed`，不冒充运动对准成功。调试模式不要求接比赛调度，指定单一区域即可调用。

### 7.1 扫码结果转为本轮任务数组

任务数据统一从现有 `/qr/result`（`std_msgs/msg/String`）获取。调度器订阅、校验四组数据并保存本轮任务快照：第一批颜色数组、第一批位置数组、第二批颜色数组、第二批粗加工位置数组，以及由第一批生成的颜色到暂存位置映射。区域模块接收当前物料目标，不在每次抓取前重新等待二维码消息。

任务码严格为四组三位数字，颜色组均为六色中的三个不同编号且两批颜色集合一致，位置组均为1、2、3的排列。不满足时拒绝整轮任务，不从残缺文本补默认值；跨组校验由调度完成，区域入口仍检查当前快照身份和数组。

核对当前源码：未识别到二维码时不发布空字符串，离开扫码区也不会主动清空结果；但现有 `VOLATILE` QoS 不向晚加入的订阅者回放旧结果。拟将文字结果改为 `RELIABLE + TRANSIENT_LOCAL + KEEP_LAST(1)`，订阅端使用匹配的持久化 QoS，使发布节点仍存活时，新订阅者可以收到最近一次成功文本。发布节点重启后的磁盘持久化不在本次设计内。

本轮任务码一旦确认，由调度器保存，后续重复扫码不重置物料索引；新一轮初始化显式清理或更新任务快照，不把缓存的上一轮结果自动当作新任务。二维码中心 `/qr/center` 继续按实时有效观测处理，不能将旧中心持久化后用于控制。

### 7.2 对准后发送固定采放动作

新增拟定话题 `/C/arm_command`，`std_msgs/msg/UInt8`：`0` 表示完整采料并入仓，`1` 表示完整出仓并向地面圆环平放，`2` 表示完整出仓并向同色底层物料码垛。原料区用0，粗加工用1放、0取，暂存第一批用1、第二批用2。该话题是机构动作请求，与底盘速度 `/C/controll` 分开；以后由板间通信节点订阅并转发。

每个目标满足条件后先停车，仅发布一次采或放指令，然后进入等待动作结果。不能在每个对准帧反复发送 0/1/2；等待期间不切换物料、不继续对准运动。采放命令使用实时、非持久化策略，晚加入的通信节点不能重放历史采放命令。

通信端按新收到的一次请求处理，不能仅在数值变化时执行：连续三个物料可能依次发布三次 `0`，这是三次独立采料请求，连续三次2同样是三次码垛请求。后续如需重传，应补充命令身份与去重机制，不能直接重发裸 0/1/2 并假设不会重复执行。

为动作完成预留 `/C/arm_status` 反馈入口，具体消息与完成关联方式待板间通信约定。只有对应动作完成且结果明确，才提交本物料步骤并开始下一个；暂未接反馈时，调试可验证一次动作请求，但不能凭“消息已发出”自动执行下一物料。

预留反馈须能关联本轮/任务/步骤，区分执行中、成功、失败与未知。裸UInt8动作值本身没有身份，最终桥接协议需解决迟到反馈与重连后的关联问题；未完成这份契约前只做单次调试，不假定“最近收到done就是当前动作”。反馈还需注明验证能力：程序执行结束不等于传感器证实抓到物料。控制器结果与可获得的视觉复核分别记录，发现颜色/占用冲突就停止，不能把控制完成直接宣称为裁判意义上的物理成功。

用户已确认车载仓盘的三仓同向每次120°、第三次也转位的流程全部交给C板。最新指令方案增加2区分码垛；0/1/2均包含各自完整机构动作及后续内部转仓。上位机不增加转仓命令、角度配置、实际仓位计数器或转仓状态机。1与2由C板分别选择平放与码垛高度，不再依赖额外模式话题；实际高度由电控标定，接触检测仅为待评估的可选内部能力，未确认硬件前不作为前提。视觉端不把“夹爪闭合/张开”直接算成采放完成。用户要求完成反馈先预留，当前不实现板间通信；对准后可验证单次命令输出，但未接完成反馈时停在等待动作结果，不自动执行下一个物料。只读识别调试不发送机构指令。

### 7.3 同一0指令的取料高度上下文（用户已确认）

原料转盘高80–100mm，粗加工为地面工位，两处完整取料动作不能默认共用下降高度。用户选择保留0/1/2，由板间通信另行同步 `work_area=raw/coarse/storage`；0在raw使用转盘取料程序，在coarse使用地面取回程序。区域上下文是独立于动作值的必要信息，与已取消的“平放/码垛模式话题”不同，不重新扩展动作编号。

区域任务接手后，先请求通信层同步 `run_id/task_id/work_area` 并等待C板确认当前区域已就绪，再允许发动作。具体话题名/消息/线协议留给通信会话，但必须保证确认的是本次上下文；只发出区域消息或依赖不同话题的到达先后都不足以确认。区域未知、冲突、通信重连或C板重启后，先重新同步，禁止沿用旧区域高度。观察姿态、机构是否允许底盘移动和完整程序完成反馈也由这份动作契约明确。

完整整批在第一项物理动作前检查所需能力：动作反馈、区域同步、局部返回、离站参考和工作范围。缺少依赖时直接报告具体原因；单次消息输出调试可单独进行，但必须显式选择，不能执行半批后才发现无法回中。通信schema尚未实现属于明确预留，不允许编码者以延时或假反馈补齐。

## 9. 实车前先验证的可行性

1. 1280×720只是像素数，不代表物理视野：在固定安装和安全停车范围内，确认能完整看到宽约580mm工位的三个中心及所选圆的必要边缘，且手臂/仓盘在观察姿态不遮挡。转盘观察位同样需确认当前待取区域可见。达不到时先调整安装/停车几何，不由编码者默默取消三工位初始化或改分辨率。
2. 标定准心后检查目标移到准心所需的底盘位移是否仍在灰色车道内，以及完整采放程序的机构可达性。若为了对准必须驶出允许范围，当前“固定相机＋底盘伺服＋固定机构程序”组合需要调整，不能靠放宽图像误差解决。
3. 全场共6次原料采、12次粗加工采放、6次暂存放置，合计24次完整机构动作，另有24次逐项局部返回、区域路线、视觉对准和两次粗加工最终校准。180秒平均到每次机构动作连同所有其他开销仅7.5秒，须实测整场预算；不承诺增加返回后仍天然满足时间。首版保留清晰的逐项返回，实测后可评估在身份明确时直接转入下一个目标，作为单独验证的优化，不能初版偷偷省略。

## 10. 公共验收

- 每帧可观察原图、ROI、掩膜、全部候选、最终目标、中心方法、误差与任务状态。
- ROI 坐标还原后与原图重合；检测和准心使用相同分辨率及坐标空间。
- 低速分别沿底盘两轴运动，验证像素误差响应与控制方向。
- 完成、丢失、过期、取消时归零；无目标不误报零误差成功。
- 同一采集帧被多次读取时，不增加稳定或到位计数。
- 不同任务不能并发发速度；结束结果只对应当前任务身份。
- 本次文档阶段只检查方案一致性，不宣称上述实车验收已经通过。

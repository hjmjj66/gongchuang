# 屏幕四阶段通信测试

脚本：`/root/工创/test/screen/screen_interaction_test.py`。

只与现有屏幕收发数据，不修改屏幕代码，不控制底盘或机构，也不启动正式比赛。无需启动 ROS2，无需另外启动屏幕驱动。

## 启动

在 RDK X5 的交互式终端执行，保留屏幕 USB 连接和正常供电，并关闭其他占用屏幕串口的程序：

```bash
python3 /root/工创/test/screen/screen_interaction_test.py
```

默认使用此前实机确认的稳定设备路径，串口参数按现有协议使用 9600、8N1、无流控。本机已检查安装了 pyserial 3.5。

若需要显式指定当前串口：

```bash
python3 /root/工创/test/screen/screen_interaction_test.py --port /dev/ttyUSB0
```

默认稳定路径为：`/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0`。

从任何工作目录均可启动。程序会清空本次任务码并让现有屏幕切到路径选择页，不需要先在终端按回车。收到 `[阶段1]` 提示后再开始操作屏幕。

## 四阶段操作

1. 在屏幕选择不能走的路径并按 OK。例如选 1、5、12，终端打印 `人工禁行路径：1、5、12`，并显示对应的双向封锁边。路径 1 封锁 7↔4；不选则打印“无”。
2. 在屏幕分别选择 start/stop 并按 OK。终端立即打印选项和规划节点，例如 `start2 → 节点3；stop1 → 节点1`；约 2 秒后打印一次“比赛开始”。此处只是模拟提示。
3. 在终端输入 `452+321+254+312` 并按回车。屏幕显示两行 `452+321` 和 `254+312`；第二行开头不添加加号。输入必须为四组三位数字，以英文 `+` 连接，保留前导零。错误时可重新输入。
4. 观察任务码后，在终端依次输入成功抓取数、成功放置数，每项分别按回车。两项均有效后切到结果页，更新统计并保留任务码。次数允许 0，拒绝负数、小数和非数字。

例如最后依次输入：

```text
成功抓取数：3
成功放置数：2
```

第二项回车后，屏幕显示抓取数 3、放置数 2。

完成后输入 `r` 并回车，回到路径页重新开始；输入 `q` 并回车退出。任意阶段均可 `Ctrl+C` 退出，退出不清空屏幕显示。重测时请检查路径按钮是否保留上轮高亮，必要时手动取消。

## 日志与排查

- 每次运行将原始 RX/TX 十六进制、发送指令、合法消息和关键终端提示保存到 `/root/工创/test/screen/records/interaction_*.jsonl`，启动时打印完整文件名。日志时间为 UTC；操作时间不受影响。
- 若提示无法打开串口，先检查 USB、设备路径和串口占用。若终端提示权限不足，请检查运行用户的串口访问权限。
- 若路径页按 OK 没有输出，先停在此阶段，保存日志并核对现有屏幕的 ROUTE 回传；不要盲目更换波特率。协议规定为 9600，变更前需向电控核实。
- 如果先收到了 CFG 而没有本轮 ROUTE，程序不会打印“比赛开始”；可在终端输入 `r` 回车重新回到路径页。
- 发送日志只证明发送了指令，最终以实屏看到的数字、加号和统计为准。当前协议没有显示成功确认。

## 软件验证

使用两个伪终端分别充当屏幕串口、交互式终端，对真实测试脚本执行四轮流程，覆盖四种起终点组合、拆包/粘包、非法输入、重复启动消息、空禁行列表、前导零、0 次和重新开始。不会打开实物串口。

```bash
python3 -B -m unittest discover -s /root/工创/test/screen -p test_screen_interaction_pty.py -v
```

此软件验证不等于实屏验收，仍需按四阶段操作检查屏幕实际显示。
